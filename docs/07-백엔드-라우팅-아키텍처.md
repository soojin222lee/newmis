# 백엔드 서버 · LLM 연동 · URL 라우팅 (공통 아키텍처)
> 요구사항명세서 Agent 입력용. 본 문서는 `server.js`, `ai-proxy.js`, `public/js/app.js`(라우팅부), `package.json` 소스 코드에 근거한다(추측 없음).

## 1. 개요 (기술 스택·원칙)

- **런타임 / 실행**: 순수 Node.js. `package.json`의 스크립트는 `"start": "node server.js"` 단 하나이며, `dependencies` 항목이 없다(`package.json` 전체). 즉 **zero-dependency** — 외부 npm 패키지 없이 Node 내장 모듈만 사용한다.
- **사용 내장 모듈**: `http`, `https`, `fs`, `path`(`server.js` 1~4행), 그리고 텍스트-투-SQL 실행용 `node:sqlite`(`server.js` 373행 `require("node:sqlite")`).
- **포트**: `process.env.PORT || 57291` (`server.js` 8행).
- **설계 원칙**
  - 브라우저는 항상 이 Node 서버를 경유하므로 **OpenAI API 키가 클라이언트로 노출되지 않는다**(`server.js` 118, 549행 주석).
  - **키는 `process.env`에서만 읽는다** — 코드/깃에 저장하지 않는다(`server.js` 177, 180행; `ai-proxy.js` 8~9, 37~39행).
  - 키가 없으면 LLM을 호출하지 않고 **로컬 규칙 기반 폴백**으로 화면이 비지 않게 한다(모든 핸들러 공통 패턴).
  - 목업이므로 영속은 파일(`data.json`) 1개, 레포트 조회용 DB는 **인메모리 SQLite**를 매 기동 시딩한다.

## 2. 서버 구조 (정적 서빙·라우터·영속·보안)

- **HTTP 서버**: `http.createServer`로 단일 서버 구성(`server.js` 49행). 요청 URL을 `new URL(req.url, ...)`로 파싱해 `pathname`이 `/api/`로 시작하면 API, 아니면 정적 파일로 분기(52행).
- **정적 파일 서빙**(77~94행)
  - 루트 디렉터리는 `public/`(`PUBLIC_DIR`, 17행). `/`는 `/index.html`로 매핑(81행).
  - `decodeURIComponent` 실패 시 400(79~80행).
  - **디렉터리 이탈 방지**: `path.normalize`로 정규화한 뒤 `filePath`가 `PUBLIC_DIR` 자신이거나 `PUBLIC_DIR + path.sep`로 시작하지 않으면 **403 Forbidden**(83~87행).
  - 확장자 기반 MIME 매핑(`MIME` 테이블 10~15행: html/css/js/json), 미등록 확장자는 `text/plain`. 파일 없으면 404(90~94행).
- **API 라우팅**
  - `/api/*` 요청에 CORS 헤더(`Access-Control-Allow-Origin: *`, Methods GET/POST/PUT/OPTIONS)를 붙이고 `OPTIONS`는 204로 프리플라이트 응답(53~57행).
  - 바디를 스트림으로 수집 후 `req.on("end")`에서 JSON 파싱하여 `handleAPI(pathname, method, body, res)` 호출. 파싱 실패 시 400(69~73행).
  - `handleAPI`(97~153행)는 **if 체인 방식의 라우터**로 경로·메서드를 순차 매칭한다. `/api/ai/*`는 외부 모듈 `handleAiApi`에 위임하고 처리했으면(`true` 반환) 종료(139행). 어느 것도 매칭 안 되면 404(152행).
- **요청 바디 크기 상한**: `MAX_BODY = 1_000_000`(1MB, 18행). 누적 바디가 초과하면 즉시 **413 Payload too large** 후 `req.destroy()`(63~67행).
- **영속(persist)**: `DATA_FILE = data.json`(19행). `loadData()`가 기동 시 파일을 읽고(없으면 `getDefaultData()`의 리스크 시드), `saveData()`가 `JSON.stringify(…, null, 2)`로 전체 저장(21~30행). 현재 영속 대상은 `risks` 데이터뿐이며, 메모 저장 시 `saveData(appData)` 호출(115행).

핸들러 위임: `/api/ai/*`는 `ai-proxy.js`의 `handleAiApi`가, 나머지는 `server.js`가 처리한다.

|---|---|---|---|---|

| `/api/insight` | POST | 종합현황 AI Insight 3줄(인사이트 종합현황 탭) | `{project,status,metrics,cause,accounts[]}` | `{insight, source}` |

## 4. LLM 연동 (callLLM·프롬프트 패턴·폴백·키 보안)

- **호출 방식**: OpenAI **Chat Completions** (`https://api.openai.com/v1/chat/completions`, POST). `server.js`와 `ai-proxy.js`가 각각 동일한 `https.request` 방식의 `callLLM`을 별도로 갖는다(중복 구현, `ai-proxy.js` 128행 주석이 "server.js의 callLLM과 같은 https 방식"임을 명시).
- **`server.js` `callLLM(prompt, cb, system)`**(177~215행)
  - 모델: `process.env.OPENAI_MODEL || "gpt-4o-mini"`(181행).
  - 키: `process.env.OPENAI_API_KEY`를 읽고 `.trim()` — 붙여넣기 시 딸려오는 공백·개행 제거(개행이 헤더에 들어가면 요청 전체 실패, 179~180행).
  - 메시지: `system` 인자가 있으면 그것을, 없으면 기본 시스템 프롬프트("비개발자 PM이 이해하기 쉽게 간결한 한국어…마크다운·불릿 금지", 185행)를 사용 — **system override 지원**.
  - **온도**: `system ? 0.1 : 0.3` — 구조화(SQL/JSON) 작업은 낮게(188행). `max_tokens: 600`.
  - **타임아웃**: `req.setTimeout(20000, …)` 20초 후 `req.destroy(new Error("timeout"))`(213행).
  - 응답: `choices[0].message.content` 추출 후 `.trim()`, HTTP 400↑이면 에러 콜백(205~207행).
- **`ai-proxy.js` `callLLM(payload, cb)`**(129~178행)
  - 모델 동일(`OPENAI_MODEL || gpt-4o-mini`), **`max_tokens`는 `OPENAI_MAX_TOKENS || 450`**(132행), 온도 0.2, **`response_format: {type:"json_object"}`** 강제(134행). 타임아웃 20초(`TIMEOUT_MS`).
- **폴백 패턴(공통)**: `if (!process.env.OPENAI_API_KEY)`이면 LLM을 부르지 않고 로컬 함수 결과를 `source:"fallback"`으로 즉시 반환. 키가 있어도 `callLLM` 콜백이 `err || !text`면 동일 폴백(사유 `note` 포함). 로컬 함수 예: `localBudgetSummary`, `localReportSummary`, `localInsight`, `localProgressSummary`, `localChatAnswer`, `localAssist`, `localNavigate`(server.js), `LOCAL_EXPLAIN`/`localExplain`(ai-proxy.js).
- **프롬프트 빌더 패턴**: 각 기능마다 `buildXxxPrompt(data)`로 숫자를 억·% 단위 문장으로 조립하고, "마크다운·불릿 금지 / 받은 숫자만 근거 / 추측 금지" 지침을 공통으로 명시. JSON 응답 기능(`report-assist`, `navigate`, `ai/explain`)은 코드펜스·설명을 벗겨 파싱(`parseAssist` 465행, `extractSql` 411행 등).
- **키 보안(중요)**: 키는 오직 `process.env.OPENAI_API_KEY`. 코드·깃에 하드코딩 없음. `ai-proxy.js`는 편의상 Node 내장 `process.loadEnvFile('.env')`로 `.env`를 `process.env`에 실어주되(27~31행), 존재하지 않거나 구버전 Node면 조용히 건너뛰고, **쉘 환경변수가 파일보다 우선**하므로 팀원의 기존 실행 방식(`$env:OPENAI_API_KEY=…`)을 덮지 않는다. `package.json`의 `start` 스크립트는 공용이라 건드리지 않는다(주석 8~16행).
- **비용 안전장치(ai-proxy 전용)**: 응답 길이 상한(`OPENAI_MAX_TOKENS`), 동일 요청 메모리 캐시(`cache`, 최대 100건, 같은 알림 재클릭 시 1회만 과금), 분당 호출 상한(`RATE_PER_MIN = 20`, 초과 시 폴백 + note)(33~56, 211~222행).

## 5. SQLite (node:sqlite) 사용·보안

- **용도**: `/api/nl2sql` 맞춤 레포트 — LLM이 생성한 SQL을 **실제로 실행**해 mock 데이터를 조회(`server.js` 347~446행).
- **인메모리 DB 시딩**: `getReportDB()`가 최초 1회 `new DatabaseSync(":memory:")`(node:sqlite)를 만들어 `projects`(`PROJECT_COLS`/`PROJECT_ROWS`, 8건)와 `budget`(`BUDGET_COLS`/`BUDGET_ROWS`, 6건) 테이블을 `CREATE`+`INSERT`로 시딩하고 `_reportDB`에 캐시(370~384행). 두 테이블은 `projectNo`로 조인, 금액 단위는 원(KRW)(`reportSchemaText` 385~389행).
- **SQL 생성**: `buildNl2SqlPrompt`가 스키마·환산 규칙(1억=100000000 등)·예시를 담아 프롬프트 구성. `callLLM` 호출 시 system 프롬프트로 "Output ONLY one read-only SELECT"를 강제(442~445행). 응답에서 `extractSql`이 코드펜스·후행 세미콜론 제거.
- **SELECT 전용 보안 가드 `isSafeSelect`(417~424행)**
  - 빈 문자열 거부.
  - 세미콜론 포함 시 거부 → **다중문 차단**.
  - `^select`로 시작하지 않으면 거부 → **SELECT만 허용**.
  - `insert|update|delete|drop|alter|create|replace|attach|detach|pragma|vacuum|reindex|truncate` 키워드 포함 시 거부.
  - 가드를 통과해야만 `db.prepare(sql).all()` 실행. 실패 시 안전 메시지 반환(431~438행).
- **폴백**: 키 없거나 LLM 실패 시 고정 `FALLBACK` 쿼리(`SELECT … FROM projects LIMIT 20`)를 실행(440~443행). `node:sqlite` 로드 자체가 실패하면(`getReportDB` catch) `source:"error"`로 응답(428~429행).

## 6. 프론트 URL 라우팅 (해시·딥링크·동적 라우트·양방향 동기화)

소스: `public/js/app.js` 28~146행. **해시(`#/…`) = 라우트명(대체로 소스파일/화면명)** 규약(41행 주석).

- **화면 전환**: `setScreen(id)`가 `.screen` 중 해당 id만 `active`로 만들고 곧바로 `updateHashForScreen(id)`로 URL을 갱신(29~34행). `setNav(id)`는 좌측 메뉴 active 상태 갱신(35~39행). 둘은 독립.
- **화면 → 해시 매핑 `SCREEN_ROUTES`**(42~87행): 화면 id를 라우트 문자열로 매핑. 값이 **함수면 동적 계산**한다.
  - `s-budget`: 단일 화면(s-budget)에 3개 서브모드가 있어 `costMode`(`adjust`/`history`/그 외)로 라우트명을 결정. `adjust`는 선택 계정(`budgetSetupEditAccount`)의 슬러그(`BUDGET_AREA_SLUGS`)를 한 뎁스 더 붙여 `budget-adjust/<slug>`. 상세 화면이면 `?pj=<프로젝트키>` 파라미터 부착(49~62행).
  - `s-insights`: `insights/<탭>?pj=<프로젝트ID>` 형태로, 탭(`insTab`)과 프로젝트(`insRouteId()`)를 반영(64~68행).
- **해시 → 액션 매핑 `ROUTE_ACTIONS`**(88~110행): 라우트명 → 해당 `show*()` 렌더 함수. 예: `dashboard→showMain`, `custom-report→showCustomReport`, `ai-report→showAiReport` 등.
- **딥링크 파라미터 규약**: 프로젝트는 경로가 아니라 **쿼리 파라미터 `?pj=`**로 전달. `routeName()`은 `#/` 제거 후 `?` 앞부분만 취하고(119행), `routeQueryParam(k)`가 해시 내 쿼리스트링을 `URLSearchParams`로 파싱해 값 조회(121~126행). 예: `#/insights/progress?pj=xxx`.
- **동적 라우트 `DYNAMIC_ROUTES`**(127~131행): 정적 `ROUTE_ACTIONS`에 없을 때만 정규식으로 매칭. 현재 `^insights(?:\/([^/?]+))?$` 하나 — `insights[/<탭>]`를 `gotoInsights(pj, 탭)`으로 연결. `resolveAction(name)`이 정적 → 동적 순으로 해석(132~136행).
- **양방향 동기화 & `_suppressNextHash`**(111~146행): `setScreen`이 URL을 바꾸면 브라우저 `hashchange`가 발생해 다시 렌더가 도는 **무한 루프**가 생길 수 있다. 이를 막기 위해 `updateHashForScreen`이 해시를 세팅하기 직전 `_suppressNextHash = true`로 플래그를 세우고(117행), `hashchange` 리스너 `routeFromHash`는 플래그가 켜져 있으면 **소비(false로 리셋)만 하고 액션을 실행하지 않는다**(137~141행). 즉 프로그램적 해시 변경(화면→해시)은 재실행을 건너뛰고, 사용자의 직접 URL 변경(뒤로가기/딥링크)만 액션을 태운다.
- **초기 진입**: `routeInitial()`이 현재 해시로 액션을 해석해 실행하고, 없으면 `showMain()`(142~145행). `bootstrapApp()`에서 데이터 로드·각 화면 init 이후 마지막에 호출(741~750행), `DOMContentLoaded` 또는 즉시 실행(751~754행).

## 7. 프론트 자산/캐시버스팅·로드 순서 규약

소스: `public/index.html`.

- **캐시버스팅 `?v=`**: 모든 CSS/JS 링크에 `?v=<날짜-태그>` 쿼리를 붙여 브라우저 캐시를 무효화한다. 예: `app.js?v=20260826-budgetpj2`, `home.css?v=20260826-projclick`(10~17, 299~335행). 버전 태그는 `YYYYMMDD-<변경키워드>` 관례이며 파일마다 독립적으로 갱신된다.
- **로드 순서 규약**: `app.js`가 **가장 먼저** 로드되어 `SCREEN_ROUTES`/`ROUTE_ACTIONS`/`setScreen` 등 공통 라우팅 기반을 정의한다(299행). 이후 화면별 스크립트가 순차 로드되며, 서브 화면 라우트 액션을 **후속 파일이 `ROUTE_ACTIONS[...] = ...`로 등록**한다:
  - `budget-cost-status.js` → `ROUTE_ACTIONS['budget-status']`
  - `budget-cost-adjust.js` → `ROUTE_ACTIONS['budget-adjust']`
  - `budget-cost-history.js` → `ROUTE_ACTIONS['budget-history']`
  - `budget-area-routes.js` → `BUDGET_AREA_SLUGS` 정의 + `ROUTE_ACTIONS['budget-adjust/'+slug]` 등록

## 8. 팀 협업/브랜치·주의점

- **브랜치 전략**: 개인 작업은 `feature/*` 브랜치에서 진행하고 팀원 리뷰 후에만 `develop`으로 머지한다(현재 브랜치 `develop`, 최근 이력에 `feature/sj`, `feature/home-finance-cj` 머지 존재). 커밋 메시지는 `[화면] 변경요약 - 작성자` 형태의 짧은 한 줄 관례.
- **여러 번 override되는 함수 패턴(주의점)**
  - `callLLM`이 `server.js`와 `ai-proxy.js`에 **각각 중복 정의**되어 있다. 모델·타임아웃 등 공통 정책을 바꿀 때 **두 곳을 함께** 수정해야 한다(현재 max_tokens는 600/450, response_format 유무 등 차이 존재).
  - `ROUTE_ACTIONS`는 `app.js`에서 객체로 선언되지만, 서브 화면 라우트는 `budget-cost-*.js`·`budget-area-routes.js`가 **런타임에 키를 추가**한다. 라우트를 추적하려면 이 파일들을 함께 봐야 한다.
  - `SCREEN_ROUTES`의 일부 값은 전역 상태(`costMode`, `budgetScreenView`, `insTab`, `insRouteId()` 등)를 `typeof … !== 'undefined'`로 방어적으로 참조하는 **함수형 라우트**다 — 해당 전역이 다른 파일에서 정의/변경되므로 상태 결합에 주의.
  - 신규 화면 추가 시 (app.js 11~16행 가이드): index.html의 screen div, 좌측 메뉴 onclick, `show*` 함수, `SCREEN_ROUTES`/`ROUTE_ACTIONS`, 그리고 `screen-guide-chatbot.js`의 지식(screenGuideKnowledge)을 **함께** 추가해야 한다.
- **API 라우터 위임 순서 주의**: `handleAPI`에서 `handleAiApi`는 `nl2sql`/`report-assist`/`navigate`보다 **앞**(139행)에서 호출된다. `/api/ai/*` 신규 경로를 추가할 때 위임 반환값(`true/false`)에 따라 뒤 라우트가 건너뛰어질 수 있으므로 순서에 유의.
