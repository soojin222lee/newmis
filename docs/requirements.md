# NEW MIS 프로젝트 관리/실행예산 시스템 요건정의 초안

## 1. 문서 목적

본 문서는 NEW MIS 프로젝트 관리 및 실행예산 시스템 구축을 위한 현업 PO 관점의 요건 초안이다. 현재 목업으로 정의된 화면과 업무 흐름을 기준으로, BP 및 개발 수행사가 업무 범위, 주요 화면, 데이터 관리 기준, 외부 시스템 연계 범위를 이해할 수 있도록 정리한다.

본 문서는 상세 설계서가 아니며, 향후 분석/설계 단계에서 화면별 필드 정의, 권한, 인터페이스 항목, 검증 로직, 승인 정책을 상세화해야 한다.

## 2. 시스템 목적

NEW MIS는 프로젝트의 생성부터 실행예산 수립, 수행비용 관리, 구매/SCM/ERP 연계, 프로젝트 종료까지의 업무를 지원하는 프로젝트 관리 시스템이다.

주요 목적은 다음과 같다.

- 프로젝트 유형별 기본정보를 관리한다.
- 프로젝트 실행예산을 비용 영역별로 수립하고 버전 관리한다.
- 기준월 이전 ERP 실적과 기준월 이후 실행예산 계획을 결합해 수행비용을 산정한다.
- 인건비, 외주비, 재료비, 경비, A/S비를 세부 계정 기준으로 관리한다.
- 구매시스템, SCM, ERP와 연계되는 데이터를 현업이 확인하고 예산계획과 매핑할 수 있게 한다.
- PM, 팀장 등 사용자 역할에 따라 주요 화면과 업무 가이드를 다르게 제공한다.
- 사용자가 필요한 필드만 선택해 레포트를 조회/추출할 수 있게 한다.
- 화면별 업무 가이드 챗봇을 통해 사용자가 현재 화면 기준으로 업무/소스/로직을 질의할 수 있게 한다.

## 3. 주요 사용자 및 역할

### 3.1 PM

PM은 본인이 담당하는 프로젝트의 실행예산을 수립하고 관리한다.

주요 업무는 다음과 같다.

- 내 프로젝트 조회
- 실행예산 상세 수립
- 인건비/외주비/재료비/경비/A/S비 계획 등록 및 수정
- 실행예산 버전별 데이터 조회
- 작성중 예산 버전의 변경사항 확인 및 결재 요청
- 구매/SCM/ERP 연계 데이터 확인
- 프로젝트 종료 관련 정보 확인

### 3.2 팀장

팀장은 팀 내 프로젝트의 이상 징후와 주요 이슈를 확인한다.

주요 업무는 다음과 같다.

- 팀 내 프로젝트의 비용/일정/검수/승인 이슈 확인
- AI 기반 요약 또는 챗봇을 통한 리스크 확인
- PM의 결재 요청 또는 ERP 전송 관련 알림 확인

### 3.3 현업/관리자

프로젝트 기준정보, 시스템 공통정보, 레포트, 구매시스템 참고 화면 등을 관리하거나 조회한다.

## 4. 프로젝트 정보 관리 요건

프로젝트 정보는 프로젝트 유형별로 관리한다.

현재 정의된 하위 메뉴는 다음과 같다.

- 수주형 프로젝트
- W/G 프로젝트
- 사내 프로젝트
- 투자프로젝트
- 선투입 프로젝트

수주형 프로젝트 화면은 기본정보와 IF 변경이력을 관리한다. 단계별 기간 정보는 관리하지 않는다.

사내 프로젝트, 투자프로젝트, 선투입 프로젝트는 동일한 화면 구조를 사용하되, 화면명과 등록 대상 텍스트를 각 프로젝트 유형에 맞게 표시한다.

프로젝트 목록에서는 프로젝트번호와 프로젝트명을 표시하고, 프로젝트 선택 시 상세/등록/승인 상태를 확인할 수 있어야 한다.

## 5. 메인 화면 요건

메인 화면은 AI PMO 중심의 간결한 시작 화면으로 구성한다.

주요 구성은 다음과 같다.

- 메인 문구: `NEW MIS는.`
- 서브 문구: `사용은 가볍게, 데이터는 단단하게.`
- 보조 문구: `편리한 업무 환경과 신뢰할 수 있는 데이터의 연결.`
- 사용자 역할 전환 스위치: PM / 팀장
- 내 프로젝트 목록
- 일정 확인 버튼
- 구매시스템 참고 버튼
- 화면별 업무 가이드 챗봇 아이콘

PM 화면에서는 본인 프로젝트를 조회하고 프로젝트 선택 시 실행예산 상세 수립 화면으로 이동한다.

팀장 화면에서는 프로젝트 리스트를 직접 노출하기보다, AI 요약 중심으로 이슈와 해야 할 일을 보여준다.

## 6. 실행예산 공통 업무 규칙

실행예산은 다음 5개 비용 영역으로 관리한다.

- 인건비
- 외주비
- 재료비
- 경비
- A/S비

최종 수행비용은 위 5개 항목의 합계로 산정한다.

각 비용 영역은 계획금액과 실적금액을 함께 관리한다.

수행비용은 기준월(STAC)을 기준으로 산정한다.

- 기준월 이전: ERP 실적 반영
- 기준월 이후: 실행예산 계획 반영

프로젝트가 진행될수록 계획은 ERP 실적으로 대체된다.

실행예산 승인 시에는 Detail 데이터를 그대로 승인하지 않고, 비용 영역별 Detail을 다시 집계하여 Summary와 정합성을 확인해야 한다.

신규 실행예산 버전 생성 시 기존 실행예산 계획 데이터를 승계하고, 이미 발생한 ERP 실적을 함께 고려한다.

## 7. 실행예산 버전 관리 요건

실행예산은 버전 단위로 관리한다.

상단에는 여러 예산 버전이 탭 형태로 표시되어야 하며, 사용자는 버전을 클릭해 해당 시점의 실행예산 데이터를 조회할 수 있어야 한다.

작성중 예산 버전은 확정 전 다음 정보를 확인해야 한다.

- 현재 버전 Summary
- 이전 버전 대비 변경사항
- 계정별 증감 금액
- 변경 사유
- 결재 요청 가능 여부

예산 확정 후 ERP 전송이 가능해야 하며, ERP 전송 시 팀장에게 메일 알림이 발생하는 프로세스를 고려한다.

## 8. 계정별 실행예산 수립 요건

프로젝트 선택 후 바로 상세예산 수립 화면으로 이동한다. 기존 계정별 예산 이관 화면은 별도 진입 단계로 사용하지 않는다.

상단에는 프로젝트 총 실행비용과 5개 비용 영역이 한 줄로 표시된다.

- 프로젝트 총 실행비용
- 인건비
- 외주비
- 재료비
- 경비
- A/S비

각 계정 카드를 클릭하면 화면 아래에 해당 계정의 예산내역과 상세 등록/수정 영역이 펼쳐진다.

월별 예산내역 표는 전체 화면이 아니라 표 내부에서 좌우 스크롤이 발생해야 한다.

과거월은 실적 구간으로 표시하며, 금액은 링크 형태로 표시한다. 클릭 시 실적 상세 팝업을 보여준다.

미래월은 계획 구간으로 표시하며, 일부 비용은 계획 상세를 조회하거나 수정할 수 있어야 한다.

## 9. 인건비 요건

인건비는 다음 3개 상세 계정으로 관리한다.

- 실투입인건비
- 이관인건비
- OT비

### 9.1 실투입인건비

실투입인건비는 SCM에서 확정완료된 인력을 그대로 등록한다.

업무 흐름은 다음과 같다.

1. 사용자가 `신규인력투입` 버튼을 클릭한다.
2. `투입가능 인력 리스트` 팝업이 표시된다.
3. 팝업에는 이름, P레벨, 역할, 투입기간, 총MM이 표시된다.
4. 사용자가 인력을 선택하고 등록한다.
5. 선택된 인력은 인건비 계획에 반영된다.

사용자는 SCM에서 확정된 인력정보를 직접 수정하지 않는다.

### 9.2 이관인건비

이관인건비는 이관외주비와 동일한 방식으로 관리한다.

신규 등록은 Receiver Project만 가능하다.

Sender Project는 타 시스템에서 집행완료 후 조회 데이터로 표시되며, 수정할 수 없다.

관리 항목은 다음과 같다.

- Project Type
- 이관예정월
- 금액
- 이관 사유
- 상태

### 9.3 OT비

OT비는 월별 금액을 직접 입력한다.

경비 자원계획과 유사하게 계정별/월별 그리드에서 금액을 입력하고 저장한다.

저장된 OT비는 인건비 예산내역의 OT비 행에 반영된다.

## 10. 외주비 요건

외주비는 다음 6개 상세 계정으로 관리한다.

- 실투입대상 외주비
- 전문직수수료/제안/기타
- 외주출장비
- 공사MA
- 이관외주비
- 기타외주비

외주비 계획 리스트에는 순번이 표시되어야 한다.

### 10.1 실투입대상 외주비

실투입대상 외주비는 구매시스템에서 IF된 견적 데이터를 기반으로 계획을 등록한다.

견적 확정 여부를 먼저 선택한다.

- 견적 확정 Y: 구매시스템 견적 데이터를 불러와 외주계약 기본정보를 자동 세팅한다. 구매에서 수신한 데이터는 수정할 수 없다.
- 견적 확정 N: 사용자가 직접 입력한다.

월별 검수계획금액 확정 팝업에서 견적 기반 월별 금액을 확인하고 보정한다.

실투입 전표가 생성된 월은 수정할 수 없다. 실투입 생성여부는 전표번호 존재 여부로 판단한다.

검수상태는 완료/미완료로 표시한다.

### 10.2 전문직수수료/제안/기타

실투입대상 외주비와 유사한 등록 구조를 사용한다.

다만 전문직수수료는 실투입 생성 대상이 아니다.

견적 산출내역은 역할, 기술등급, 시작일, 종료일, Assign Type, 인원수, 총MM 기준으로 조회한다.

월별 검수계획금액 확정 팝업에서는 전체 금액을 기간 내 월별로 N등분하고, 사용자가 확정금액을 직접 보정할 수 있어야 한다.

### 10.3 외주출장비

외주출장비는 기등록 계획 리스트를 먼저 보여준다.

신규 등록 시 필요한 주요 필드는 다음과 같다.

- 계약번호 검색
- 출장내역
- 집행예정월
- 출장금액
- 항공료
- 숙박비
- 교통비
- 일비
- 기타비용
- 기타비용내역

출장 시작일/종료일, 비고/예산 설명 필드는 사용하지 않는다.

### 10.4 공사MA

공사MA는 구매시스템 견적/물품정보를 기반으로 계획을 수립한다.

물품정보에서 관리하는 주요 필드는 다음과 같다.

- 항번
- 비고
- 단위
- 수량
- 유지보수시작일
- 유지보수종료일
- 검수유형
- 공급단가
- 검수집행월
- 검수여부

검수집행월은 기본적으로 유지보수종료일의 YYYY-MM으로 세팅되며, 검수 이력이 없는 경우에만 수정 가능하다.

기등록 MA 리스트를 먼저 표시하고, 수정 버튼을 통해 상세를 수정한다.

### 10.5 이관외주비

이관외주비는 비용 이관 계획을 관리한다.

신규 등록은 Receiver Project만 가능하다.

Sender Project는 집행완료 후 리스트에서 조회만 가능하다.

관리 항목은 다음과 같다.

- Project Type
- 이관예정월
- 금액
- 이관 사유
- 상태

### 10.6 기타외주비

기타외주비는 집행월, 금액, 설명을 기준으로 단순 계획 등록한다.

향후 데이터가 축적되면 AI가 설명 텍스트를 기반으로 카테고리를 추천하는 방향을 고려한다.

## 11. 재료비 요건

재료비는 다음 3개 상세 계정으로 관리한다.

- 상품재료비
- 감가상각비
- 이관재료비

### 11.1 상품재료비

상품재료비는 구매시스템 견적 데이터를 기반으로 계획을 등록한다.

기등록 상품계획은 PO 기준 1줄로 표시한다.

해당 라인을 클릭하면 항번 기준의 상세 내역이 여러 줄로 표시된다.

신규 등록 시 견적선정유무를 선택한다.

- Y: 구매시스템 견적 데이터를 불러와 화면에 세팅한다.
- N: 사용자가 예산 시작일~종료일 사이에 견적금액을 할당하여 직접 입력한다.

견적 기반 등록 시 구매에서 수신된 기본정보는 수정하지 않고, 검수 계획만 등록/수정한다.

검수예정일이라는 표현은 사용하지 않고 `검수 계획 등록`으로 표시한다.

검수 계획은 수량 기준으로 검수 예정월을 입력하는 팝업을 통해 관리한다.

### 11.2 감가상각비

감가상각비는 기등록 계획 리스트를 먼저 표시한다.

신규 등록 시 감가상각 계정 4개 중 하나를 선택하고, 감가상각 개월수와 감가상각 시작일을 입력한다.

입력 후 월별 감가상각 금액이 자동 배분되어야 하며, 필요 시 팝업에서 월별 금액을 보정할 수 있어야 한다.

### 11.3 이관재료비

이관재료비는 이관외주비와 동일한 방식으로 관리한다.

신규 등록은 Receiver Project만 가능하며, Sender Project는 집행완료 후 조회 전용으로 표시한다.

## 12. 경비 요건

경비는 예산내역과 자원계획을 별도 화면으로 나누지 않고, 하나의 월별 자원계획 그리드에서 작성한다.

경비는 중계정 기준으로 통제/비통제를 구분한다.

중계정명 기준으로 경비 구분을 관리하고, 전체 계획은 소계정별 월별 금액으로 작성한다.

통제 계정의 경우 ERP에 해당 프로젝트의 매출귀속부서 기준 가용예산이 있어야 계획을 수립할 수 있다.

소계정별 계획 합계가 중계정 가용예산을 초과하면 저장할 수 없다.

화면에는 다음 안내 문구가 필요하다.

- 통제 중계정은 매출귀속부서 기준 ERP 가용예산을 초과할 수 없다.
- 계정별 예산 이관에서 경비 조정배분을 변경할 때도 동일한 한도를 체크한다.

## 13. A/S비 요건

A/S비는 A/S 프로젝트에 수립할 비용을 별도 계정으로 관리한다.

A/S비 내부에는 다음 항목을 직접 입력한다.

- A/S 인건비
- A/S 외주비
- A/S 재료비
- A/S 경비

각 항목은 사용자가 키인하는 방식으로 등록한다.

입력 후 A/S비 총액에 반영되어야 한다.

## 14. 구매시스템 참고 화면 요건

NEW MIS 안에서 실제 입력은 수행하지 않지만, 구매시스템 원본 화면을 참고할 수 있는 별도 HTML 화면을 제공한다.

메인 화면에는 `구매시스템 참고` 버튼을 제공한다.

버튼 클릭 시 참고 화면 목록이 표시되고, 사용자는 원하는 구매 화면을 별도 팝업으로 열 수 있다.

현재 정의된 참고 화면은 다음과 같다.

- 01 외주실투입구매요청
- 02 상품재료비 구매요청
- 03 공사MA 구매요청
- 04 외주출장비 요청상세
- 05 검수상세 > 검수계획

06~10번은 현재 표시하지 않는다.

구매 참고 화면에는 NEW MIS와 매핑해야 하는 필드를 빨간색 박스로 표시한다.

### 14.1 외주실투입구매요청

품목정보 하단의 투입원가 매핑은 사용하지 않는다.

프로젝트정보 하단에 `MIS원가맵핑` 영역을 추가하고, 실행예산 > 외주비 > 실투입 외주비 계획과 매핑한다.

투입원가 밑의 기존 돋보기는 X 표시하여 앞으로 사용하지 않음을 표시한다.

### 14.2 상품재료비 구매요청

프로젝트 정보 영역에서 실행예산 > 재료비 > 상품재료비 계획과 매핑한다.

팝업을 통해 금액, 시작일, 종료일 등을 확인한다.

### 14.3 공사MA 구매요청

유지보수 정보에 총금액 필드를 추가한다.

실행예산 > 외주비 > 공사MA 계획과 매핑한다.

### 14.4 외주출장비 요청상세

협력사가 제출한 출장비 내역을 조회한다.

사업팀에서 프로젝트 > 외주출장비 계획 중 몇 번 계획과 매핑할 수 있어야 한다.

### 14.5 검수상세 > 검수계획

기존 검수상세 화면에 `검수계획` 영역을 추가한다.

검수 계획은 월별로 표시하고, 현재 월에 해당하는 계획만 선택 가능해야 한다.

검수 요청 시 선택한 실투입 금액과 검수 계획 금액이 동일할 때만 요청 가능해야 한다.

## 15. 프로젝트 종료 요건

프로젝트 종료 메뉴를 제공한다.

프로젝트 종료 목록은 실행예산 프로젝트 리스트와 동일한 형태로 조회한다.

프로젝트 선택 시 종료 상세 화면을 표시한다.

종료 상세 화면에는 다음 정보가 필요하다.

- 구매 검수 완료 여부
- 산출물 등록 여부
- 빌링 여부
- 계획 종료일
- 프로젝트 종료일
- 종료 선언일
- 사후점검 결과보고 계획

## 16. 레포트 요건

레포트 메뉴를 제공한다.

사용자는 레포트 유형을 선택하고, 조회할 필드를 직접 선택할 수 있어야 한다.

프로젝트번호는 키값이므로 기본 선택되어야 하며, 해제할 수 없다.

필드 선택은 행 형태로 나열한다.

사용자가 필드를 선택한 순서가 조회 결과의 컬럼 순서가 되어야 한다.

기본값은 모든 필드 선택 상태이다.

조회 결과는 선택된 필드만 표시하며, 다운로드 시에도 동일한 컬럼 순서를 유지한다.

레포트 유형 중 `실행예산 현황`은 다음 성격의 데이터를 조회한다.

- 프로젝트 기본정보
- 예산 버전
- 프로젝트 유형
- 조직 정보
- 프로젝트 상태
- 승인 요청일/완료일
- 전버전 수행비용
- 현재 수행비용
- 비용 영역별 금액

## 17. 화면 업무 가이드 챗봇 요건

각 화면 오른쪽에 업무 가이드 챗봇 아이콘을 제공한다.

챗봇은 현재 사용자가 보고 있는 화면을 기준으로 답변해야 한다.

화면 식별은 URL만 의존하지 않고 다음 정보를 함께 사용한다.

- 현재 active screen id
- active nav id
- 화면 내부 상태값
- 프론트 파일명
- 화면 주석/업무 로직 메타데이터

챗봇은 다음 질문에 답할 수 있어야 한다.

- 이 화면은 어떤 업무를 처리하는 화면인가?
- 이 화면의 프론트 파일은 무엇인가?
- 관련 백엔드/API 후보는 무엇인가?
- 주요 업무 규칙은 무엇인가?
- 특정 버튼이나 필드가 어떤 프로세스와 연결되는가?

답변 품질을 위해 프론트 소스에는 AI GUIDE 주석과 주요 함수 주석을 보강한다.

## 18. 외부 시스템 연계 요건

### 18.1 SCM

SCM은 인건비 실투입 인력 확정 데이터를 제공한다.

NEW MIS는 SCM에서 확정완료된 인력만 조회하고 등록한다.

승인/확정 이후 상태 변경이 다시 NEW MIS에 반영되어야 한다.

### 18.2 구매시스템

구매시스템은 외주비, 재료비, 공사MA, 출장비, 검수 관련 원천 데이터를 제공한다.

NEW MIS는 구매시스템에서 수신한 견적/계약/PO/검수 데이터를 기반으로 예산 계획을 수립하거나 매핑한다.

구매시스템에서 수신한 확정 데이터는 원칙적으로 NEW MIS에서 수정하지 않는다.

### 18.3 ERP

ERP는 실적 원가와 가용예산 정보를 제공한다.

기준월 이전 수행비용은 ERP 실적을 기준으로 반영한다.

통제 경비는 ERP 가용예산을 초과할 수 없다.

실행예산 확정 후 ERP 전송 프로세스가 필요하다.

## 19. 권한 및 통제 요건

권한은 최소한 다음 기준으로 구분한다.

- PM
- 팀장
- 관리자
- 조회 전용 사용자

PM은 본인 담당 프로젝트를 수정할 수 있다.

팀장은 팀 내 프로젝트를 조회하고 승인/검토할 수 있다.

구매 또는 ERP에서 수신된 확정 데이터는 원칙적으로 수정 불가하다.

실적이 발생한 계획은 수정할 수 없다.

Sender Project로 수신된 이관 데이터는 조회만 가능하다.

Receiver Project 계획은 실적 발생 전까지 수정 가능하다.

## 20. 향후 상세화 필요사항

분석/설계 단계에서 다음 항목을 상세화해야 한다.

- 프로젝트 유형별 필수 입력 항목
- 화면별 필드 정의서
- 각 비용 영역별 저장 테이블 구조
- 예산 버전 생성/승계 기준
- 기준월(STAC) 산정 기준
- ERP 실적 반영 주기
- SCM 인력 데이터 인터페이스 항목
- 구매 견적/계약/PO/검수 데이터 인터페이스 항목
- 경비 통제 중계정 및 가용예산 검증 로직
- 결재선 및 승인 상태 정의
- ERP 전송 시점과 실패 재처리 방식
- 레포트 필드 사전
- 화면 업무 가이드 챗봇의 소스/주석 인덱싱 방식
