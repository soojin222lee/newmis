# AI 레포트 (LLM-to-SQL) & 맞춤 레포트
> 요구사항명세서 Agent 입력용.

## 1. 개요 (두 화면 구분)

본 문서는 SI 예산관리 목업 웹앱의 레포트 관련 두 화면을 다룬다. 두 화면 모두 `public/js/custom-report.js` 한 파일에 구현되어 있으나, 데이터 접근 방식과 목적이 명확히 구분된다.

| 구분 | AI 레포트 | 맞춤 레포트 |
|---|---|---|
| 목적 | 자연어 질문을 SQL로 변환해 실제 데이터를 조회 | 사용자가 필드를 직접 골라 표 형태로 조회·추출 |
| 데이터 접근 | 자연어 → LLM이 SELECT SQL 생성 → 실제 `node:sqlite` 인메모리 DB 실행 | 프론트엔드 mock 배열(`customReportRows` 등)을 클라이언트에서 필터링 |
| 핵심 함수 | `renderAiReport()`, `runNl2Sql()` | `renderCustomReport()`, `applyCustomReportSearch()` |
| AI 연동 | `/api/nl2sql` (LLM-to-SQL) | `/api/report-assist` (필드 설명·목적별 필드 추천 채팅) |
| URL | `#/ai-report` | `#/custom-report` |
| 보안 특성 | SELECT 전용 가드(`isSafeSelect`), SQL 노출 운영자 토글 | 조인 키(`projectNo`) 필수 고정 |

- **AI 레포트**: 한국어 질문을 입력하면 LLM이 SELECT 쿼리를 생성하고, 서버가 안전성(SELECT 전용)을 검증한 뒤 인메모리 SQLite에서 실제 실행하여 결과 테이블을 반환한다. 생성 SQL은 기본적으로 일반 사용자에게 숨기며 운영자 토글로만 확인한다. 조건 선택 칩(프로젝트 유형/매출귀속부문/상태)으로 WHERE 힌트를 질문에 자동 결합한다.
- **맞춤 레포트**: 레포트 유형(프로젝트 현황/실행예산 현황)을 고르고, 그룹화된 필드 목록에서 원하는 필드를 체크해 조회·엑셀 추출한다. 프로젝트번호(`projectNo`)는 조인 키로 항상 선택·고정된다. AI 도우미 채팅으로 필드 의미 설명과 목적별 필드 자동 추천·자동 선택을 받는다.

## 4. 비즈니스 로직 & 규칙 (SQL 생성·보안 가드·조건 결합·필드 추천)

### 4.1 SQL 생성·안전 실행 (AI 레포트)
- 자연어 질문은 프론트에서 조건 힌트(`crConditionText()`)를 붙여 `/api/nl2sql`로 전송된다 (`runNl2Sql`, `custom-report.js:220-236`).
- 서버는 `OPENAI_API_KEY` 존재 시 LLM 호출(`buildNl2SqlPrompt`), 없으면 폴백 SQL 사용 (`handleNl2Sql`, `server.js:440-445`).
- 생성/폴백 SQL은 실행 전 `isSafeSelect`로 검증 (`server.js:417-424`):
  - 빈 문자열 거부
  - 세미콜론(`;`) 포함 시 거부 → **다중문 차단**
  - `^select`로 시작하지 않으면 거부 → **SELECT 전용**
  - `insert|update|delete|drop|alter|create|replace|attach|detach|pragma|vacuum|reindex|truncate` 키워드 포함 시 거부
- 검증 실패 시 실행하지 않고 "안전하지 않은 쿼리라 실행하지 않았습니다(SELECT 전용)." 반환 (`server.js:431`).
- `extractSql`로 마크다운 코드펜스(```` ```sql ````) 제거 및 말미 세미콜론 정리 (`server.js:411-416`).

### 4.2 SQL 노출 운영자 토글
- `crShowSql` 상태(기본 `false`)로 SQL 블록 노출 여부 제어 (`custom-report.js:107`).
- 일반 사용자에게는 생성 SQL이 숨겨지며, `crToggleSql()`로만 표시된다. 결과 HTML에서 `crShowSql && r.sql`일 때만 SQL 블록을 렌더 (`custom-report.js:174-175`). 블록에는 "운영자 전용" 배지 표기.

### 4.3 조건 결합 (조건 선택 칩 → WHERE 힌트)
- 3개 facet: `projectType`(프로젝트 유형), `salesDivision`(매출귀속부문), `projectStatus`(프로젝트 상태) — `CR_COND_FACETS` (`custom-report.js:111-115`).
- 프로젝트 유형 후보값은 실제 유형 코드 예시 배열 `CR_PROJECT_TYPES`(제안-본제안, SI-컨설팅, SI-AD … 투자-개발, 원가-선투입 등 22종) 사용 (`custom-report.js:117-121`). 그 외 facet 후보값은 `customReportRows`에서 distinct 추출 (`crDistinct`, `custom-report.js:122-125`).
- 칩 토글 시 `crConditions[facet]` 배열에 값 추가/제거 (`crToggleCond`, `custom-report.js:128-133`).
- `crConditionText()`가 선택 조건을 자연어 WHERE 힌트로 변환해 질문 뒤에 결합 (`custom-report.js:135-142`). 힌트 문구는 "값을 쪼개지 말 것", "조건에 필요 없으면 budget 테이블과 조인하지 마" 등 LLM 유도 지시를 포함.
- 질문·조건 둘 다 없으면 실행 차단(토스트). 질문이 없고 조건만 있으면 기본 질문 "조건에 해당하는 프로젝트를 조회해줘" 사용 (`custom-report.js:224-226`).

### 4.4 필드 선택·추천 규칙 (맞춤 레포트)
- **키필드 고정**: `CUSTOM_REPORT_KEY_FIELD = 'projectNo'`는 조인 키로 항상 포함되며 체크 해제·비활성화 불가 (`normalizeCustomReportFields`, `toggleCustomReportField` 초기 return, `custom-report.js:295-299,329-337`).
- **선택 순서 = 컬럼 순서**: 체크 순서가 조회 결과·엑셀 컬럼 순서가 된다(필드 라벨 옆 순번 표시).
- **프리셋**: `all/pm/leader/close` 4종을 레포트 유형별로 각각 정의(`customReportPresets`, `customBudgetReportPresets`). `setCustomReportPreset`로 적용 시 토스트로 "AI가 목적에 맞는 필드를 추천했습니다" 표시 (`custom-report.js:339-344`).
- **그룹 토글**: 그룹 단위 전체 선택/해제(`toggleCustomReportGroup`), 단 키필드는 항상 유지 (`custom-report.js:346-352`).
- **조회**: `applyCustomReportSearch()`가 선택 필드를 확정(`customReportAppliedFields`). 선택 필드가 없으면 최소 `projectNo, projectName`로 폴백 (`custom-report.js:354-363`).
- **AI 챗 추천 자동선택**: `/api/report-assist`가 반환한 추천 필드 중 현재 유효 키만 필터링해 자동으로 선택 상태에 반영 (`sendReportChat`, `custom-report.js:277-283`).

## 6. 백엔드/API/LLM 연동 (nl2sql·report-assist 스키마·프롬프트·SQLite 시딩·폴백)

전부 `server.js`. 라우팅: `/api/nl2sql`(POST)→`handleNl2Sql`, `/api/report-assist`(POST)→`handleReportAssist` (`server.js:141-146`).

### 6.1 SQLite 인메모리 시딩
- `getReportDB()` — `node:sqlite`의 `DatabaseSync(":memory:")`를 최초 1회 생성·캐시(`_reportDB`) (`server.js:370-384`).
- `seed(name, cols, rows)` — `CREATE TABLE` 후 `prepare/INSERT`로 행 삽입, `undefined`는 `null`로 치환 (`server.js:375-379`).
- 두 테이블 시딩: `projects`(`PROJECT_COLS`/`PROJECT_ROWS`, 8행), `budget`(`BUDGET_COLS`/`BUDGET_ROWS`, 6행) (`server.js:349-368,380-381`).

### 6.2 `/api/nl2sql` (LLM → SQL → 실행)
- 요청: `{ question }`. 응답: `{ sql, columns, rows, source }` 또는 `{ sql, error, source }`.
- `source` 값: `ai`(LLM 생성) / `fallback`(API 키 미설정 또는 LLM 실패) / `error`(SQLite 불가).
- 프롬프트 `buildNl2SqlPrompt` (`server.js:390-410`): "SQLite 텍스트-투-SQL 변환기", SELECT 1개만·마크다운 금지·존재 컬럼만 사용, **금액 원 단위 환산**(1억=100000000 등), 특정 값/이름은 WHERE 등호 필터, 비용 계정은 budget 테이블 사용, few-shot 예시 2개, `reportSchemaText()` 스키마 포함.
- 시스템 프롬프트: "Output ONLY one read-only SELECT statement" (`server.js:445`).
- **폴백 SQL**: `SELECT projectNo, projectName, pmName, projectStatus, finalLaborCost FROM projects LIMIT 20` (`server.js:440`).
- 실행: `isSafeSelect` 통과 시 `db.prepare(sql).all()`, 컬럼은 첫 행 키에서 도출, 실행 예외는 "쿼리 실행 오류: …"로 반환 (`server.js:430-439`).

### 6.3 `/api/report-assist` (필드 설명·추천)
- 요청: `{ message, reportType, fields:[{key,label,group}] }`. 응답: `{ reply, fields, source }`.
- 프롬프트 `buildAssistPrompt` (`server.js:449-461`): 필드 목록(key : 이름 (그룹))과 현재 레포트 유형·사용자 메시지 제공, **순수 JSON 한 개**(`{"reply","fields"}`)로만 답하도록 강제. `reply`는 한국어 2~4문장 설명, `fields`는 목록의 key만 추천.
- `parseAssist` (`server.js:465-478`): 코드펜스 제거 → `{…}` 슬라이스 → `JSON.parse`, `fields`는 `validKeys` 교차 필터. 파싱 실패 시 특수문자 제거한 원문을 reply로 폴백.
- **폴백** `localAssist` (`server.js:462-464`): API 키 없거나 LLM 실패 시 "지금은 AI 설명을 사용할 수 없어요(API 키 미설정)… 'AI 추천' 프리셋 버튼으로 …", `fields: []`.

### 6.4 공통 폴백 원칙
- 두 API 모두 HTTP 200으로 응답하며, LLM 미가용/실패를 에러가 아니라 `source: "fallback"`로 표기해 목업이 항상 동작하도록 설계됨.

## 7. 데이터 모델 (필드 카탈로그·SQLite 스키마)

### 7.1 맞춤 레포트 필드 카탈로그 (프론트, `customReportFields`)
프로젝트 현황 유형. 그룹별:
- 프로젝트 기본정보: projectNo(키), projectName, orderCompany(발주처), contractCompany(계약처), projectType(프로젝트유형)
- 조직/PM: salesDivision(매출귀속부문), salesHead(매출귀속본부), salesDept(매출귀속부서), pmNo(PM사번), pmName(PM명)
- 기간/상태: startDate, endDate, projectStatus, erpEndDate(ERP종료일)
- 계약/검수: freeMaintenanceYn(무상하자보증여부), overseasPmYn(해외PM여부), relatedCompanyYn(관계사여부)
- 예산/실적: finalLaborCost(최종예산인건비), finalMaterialCost(최종예산재료비), finalAsCost(최종예산AS비)
- ERP/정산: finalApprovedAt(최종예산승인일자), budgetVersion(실행예산버전), erpSendStatus(ERP전송상태)

### 7.2 실행예산 현황 필드 카탈로그 (프론트, `customBudgetReportFields`)

- 버전/상태: budgetVersionNo(예산버전), projectStatus, approvalRequestedAt(예산승인 요청일), approvalCompletedAt(예산승인 완료일)
- 조직/PM: salesDivision, salesHead, pmName
- 전버전 금액: previousTotalCost, previousLaborCost, previousOtCost, previousOutsourceCost, previousMaterialCost, previousExpenseCost, previousPjtReserve, previousAsCost, previousWlbCost, previousInternalMm
- 현재 실행예산: executionCost(수행비용), laborCost, otCost(OT비), outsourceCost, materialCost, expenseCost, pjtReserve(PJT손실예비비), asCost, wlbCost, internalMm(내부MM)

> 주의: 프론트 mock(`customReportRows`/`customBudgetReportRows`)과 서버 SQLite 시딩 데이터(`PROJECT_ROWS`/`BUDGET_ROWS`)는 별개 정의이며 컬럼 구성이 다르다. AI 레포트는 서버 SQLite 스키마만, 맞춤 레포트는 프론트 mock만 사용한다.

### 7.3 SQLite 스키마 (`reportSchemaText`, `server.js:385-389`)
**projects** (프로젝트 현황): `projectNo, projectName, orderCompany, projectType, salesDivision, salesHead, salesDept, pmName, projectStatus, startDate, endDate, finalLaborCost, finalMaterialCost, finalAsCost, budgetVersion, erpSendStatus, relatedCompanyYn, overseasPmYn`

- 두 테이블은 `projectNo`로 조인. 모든 금액 컬럼 단위는 원(KRW).
- 프롬프트에 각 컬럼의 한국어 의미·예시값(예: projectStatus 예:수행/착수완료, erpSendStatus 예:전송완료/미전송/전송대기)이 함께 제공됨.

### 7.4 프리셋 정의
- 프로젝트 현황(`customReportPresets`): all / pm / leader / close (`custom-report.js:90-95`).
- 실행예산 현황(`customBudgetReportPresets`): all / pm / leader / close (`custom-report.js:97-102`).
- 모든 프리셋은 적용 시 `normalizeCustomReportFields`로 키필드 `projectNo`가 선두 보장됨.

## 8. 사용자 플로우 (자연어 질의 / 목적별 필드 추천)

### 8.1 AI 레포트 — 자연어 질의
1. 사용자가 (선택) 조건 칩으로 프로젝트 유형/부문/상태 필터를 고르고, 질문을 입력하거나 예시 칩 클릭.
2. `runNl2Sql()`이 질문 + `crConditionText()` 힌트를 결합해 `/api/nl2sql` POST.
3. 서버: API 키 있으면 LLM으로 SQL 생성(`ai`), 없으면 폴백 SQL(`fallback`).
4. `isSafeSelect`로 SELECT 전용 검증 → 인메모리 SQLite에서 실행.
5. 응답의 columns/rows로 결과 테이블 렌더, 건수 표시. 운영자 토글 ON이면 생성 SQL·소스 태그 함께 노출.
6. 실패/무결과/안전위반 시 각각 에러 메시지 표시.

### 8.2 맞춤 레포트 — 목적별 필드 추천
1. 사용자가 AI 도우미에 목적/질문 입력(예: "팀 귀속 프로젝트 원가 변동 비교분석 레포트 추천해줘") 또는 예시 칩 클릭.
2. `sendReportChat()`이 현재 필드 목록·레포트 유형·메시지를 `/api/report-assist` POST.
3. 서버가 JSON `{reply, fields}` 반환(폴백 시 안내문·빈 배열).
4. 프론트가 reply를 채팅에 표시하고, 추천 `fields` 중 유효 키만 자동 선택(키필드 선두 유지) → 필드 선택기·결과 테이블 즉시 갱신.
5. 사용자는 프리셋 버튼(PM용/팀장 보고용/종료·정산용)으로도 동일하게 필드 세트를 빠르게 적용 가능.
6. "조회" 시 선택 필드 순서대로 결과 테이블 구성, "엑셀 다운로드"는 목업(토스트 안내).
