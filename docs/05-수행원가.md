# 수행원가 (원가현황·원가조정·변경이력)
> 요구사항명세서 Agent 입력용. 비즈니스 로직·프론트/백엔드 로직·데이터·플로우를 코드 근거로 정리.

> ⚠️ 근거·override 규칙: 수행원가 화면(`s-budget`)의 렌더링 코어는 `budget-status.js` + `budget-status-2.js`~`-5.js` 5분할 파일에 있고, **동일 함수를 여러 번 재정의(override)** 한다(예: `renderBudgetPage`, `renderBudgetAccountEditor`, `saveBudgetTransfer`, `renderExpensePlanPanel`, `renderMaterialPlanPanel`, `renderBudgetSetupOverview`). 프로젝트 규칙("뒤에 정의된 코드가 앞을 override") + 로드 순서(`budget-status.js` → `-2`~`-5` → `budget-cost-*.js` → `budget-area-*.js`)에 따라 **가장 마지막에 정의/데코레이트된 버전이 실제 동작**한다. 본 문서는 최종 유효 버전 기준이며, 계정별 상세(인건비·외주비·재료비·경비·A/S)는 `budget-area-*.js`(데코레이터 체인)가 최종 소유자다.

## 1. 개요
- **목적**: SI 프로젝트의 실행예산(수행원가)을 프로젝트 단위로 조회·수립·조정하고 변경 이력을 관리하는 화면. AI GUIDE 주석(`budget-status.js:10~17`)에 따르면 이 앱에서 가장 핵심적인 업무 도메인.
- **비용 계정 5종**(`CATS`, `budget-status.js:742`): `['인건비','외주비','재료비','경비','A/S Cost']`. 화면에서 A/S Cost 라벨은 "A/S비"로 치환 표시(`budget-area-as.js:217`).
- **핵심 컨셉**(`budget-status.js:13`): 기준월(STAC/당월) **이전은 ERP 실적(actual)**, **이후는 실행예산 계획(plan)** 을 반영해 수행비용을 계산한다. 계획월에는 확정분(`q`, 투입확정/quasi)이 별도로 잡힌다.
- **한 화면(`s-budget`) = 3개 하위 메뉴**: 진입 모드 `costMode`(`budget-status-5.js:69`, 기본 `'history'`)가 `'status'`(원가현황)·`'adjust'`(원가조정)·`'history'`(변경 이력)를 구분한다. 세 메뉴는 렌더러(`budget-status*.js`)를 공유하고, 진입점/라우트만 `budget-cost-status.js`·`budget-cost-adjust.js`·`budget-cost-history.js`가 나눠 소유한다.
- **사용자**: PM(기안자, 목업 상 `이봄`) · 팀장(결재자, `김도윤 팀장`). 프로젝트별 PM은 `EXEC_BUDGET_PROJECTS`의 `pm` 필드(`getBudgetProjectPm`, `budget-status.js:1314`).

## 2. 진입 경로 & URL (딥링크·계정별 세분화)

| 하위 메뉴 | costMode | 진입 함수(목록) | 프로젝트 진입 함수 | 라우트 | 소유 파일 |

### 2.2 딥링크(`?pj=`) — 양방향 URL 갱신
- **URL → 화면**: 라우트 등록부(`budget-cost-*.js:13~18`)가 `routeQueryParam('pj')`(`app.js:121`)로 프로젝트 키를 읽어, 있으면 `costMode` 세팅 후 `openBudgetProjectScreen(pj)`로 그 프로젝트 상세 바로 진입, 없으면 목록.
- **화면 → URL**: `SCREEN_ROUTES['s-budget']`(`app.js:49~62`)가 현재 상태로 해시를 역산한다:
  - `costMode==='adjust'` → `budget-adjust`, 계정 선택 시 슬러그 한 뎁스 추가(`BUDGET_AREA_SLUGS[budgetSetupEditAccount]`) → `budget-adjust/<slug>`
  - `costMode==='history'` → `budget-history`, 그 외 → `budget-status`
  - 상세 뷰(`budgetScreenView==='detail'`)면 끝에 `?pj=<currentBudgetProj>` 부착.
- `updateHashForScreen('s-budget')`(`app.js:112`)가 위 결과로 `location.hash`를 갱신(`_suppressNextHash`로 재진입 방지).

### 2.3 원가조정 계정별 딥링크 (`#/budget-adjust/<slug>?pj=`)
- 계정↔슬러그 매핑(`budget-area-routes.js:13~14`): `BUDGET_AREA_SLUGS = { 인건비:labor, 외주비:outsource, 재료비:material, 경비:expense, 'A/S Cost':as }`, 역매핑 `BUDGET_AREA_BY_SLUG`.
- 라우트 등록(`budget-area-routes.js:37~44`): 5개 슬러그마다 `ROUTE_ACTIONS['budget-adjust/'+slug]` 등록 → `openCostArea(계정, pj)`.
- `openCostArea(account, projectKey)`(`budget-area-routes.js:30~34`): `costMode='adjust'` → `openBudgetProjectScreen(pj||'budgetMock')`(원가조정 edit 단계 진입) → `openBudgetAccountEditor(account)`(계정 선택 + 해시 반영).

- AI 채팅 네비게이터 진입: `app.js:1251~1253`에서 `budget-status/adjust/history` 해시 세팅.

## 4. 비즈니스 로직 & 규칙 (계정 구조·계획/실적·한도 검증·예산 이관)

### 4.1 수행비용 집계 계산 (`budget-status.js:797~805`)
- `catVal(mo, cat)`: `type==='actual'`이면 `{a, q}`, `'plan'`이면 `{q, p}` 반환.
- `calcActual`=실적 `a` 합, `calcQuasi`=투입확정 `q` 합, `calcPlanTotal`=계획월 `p` 합, `calcRemain(cat)` = `plan[cat] − 실적 − 확정`.
- 화면 총액은 계정별 `plan` 합 vs 실적/확정/잔여를 총액바에 표시.

### 4.2 예산 이관 (transfer) — 계정 간 조정배분
- 데이터: `data.transfer`(계정별 증감액). 조정배분 = `getBudgetAdjusted(data,acct)` = `plan[acct] + transfer[acct]`(`budget-status.js:1319`).
- 편집: `startBudgetTransferEdit()`/`cancelBudgetTransferEdit()`로 `budgetTransferEditMode` 토글 → `renderAccountTransferTable`(`budget-status-3.js:2160`)이 조정배분 칸을 input(`actr-adjust-<idx>`)으로 렌더.
- **저장 검증 (`saveBudgetTransfer`, 최종본 `budget-status-2.js:2296`)** — 순서대로:
  1. 조정배분 합계 = 원 총액과 **정확히 일치**해야 함(총액 내 이관만 허용).
  2. 각 계정 조정배분 ≥ (실적+투입확정) — 이미 집행/확정된 금액보다 작게 못 줄임.
  3. **경비 특례**: `nextAdjusted['경비'] ≤ getExpenseTransferLimit()`(ERP 기준 가용 한도) 초과 불가.
  4. `validateExpenseErpAvailability()` 통제 계정 재검증.
  5. 통과 시 `data.transfer` 갱신 + 변경분(`changes`) 산출 → `budgetTransferHistory`에 신규 버전 `unshift`(version = 기존 길이+1, `changedBy`=PM, `changedAt`=현재시각) → `persistBudgetTransferState()`(localStorage).
- 초기 원본(`budget-status.js:1338`)에는 경비 3·4 검증이 없음 → **최종 유효본은 경비 한도 검증 포함 버전**.
- UI 규칙 문구(`budget-status-3.js:2266`): "총액 내 계정 간 이관만 가능. 프로젝트 전체 Cost 변경은 AI PMO Cost 재산정 필요."

### 4.3 인건비 상세 (실투입/이관/OT) — `budget-area-labor.js`
- 상세 3계정(`renderLaborKindTabsFinal`, `:112`): **실투입인건비(direct)** / **이관인건비(transfer)** / **OT비(ot)**. `laborKindFinal`로 전환.
- **실투입**: SCM에서 투입계획이 확정(승인)되어 I/F 수신된 인력을 "등록"해야 인건비로 예산화됨(시그널 알림 `renderLaborAlertsFinal`, `:166`). 인력 배정 데이터 `budgetLaborAssignments`(`budget-status.js:1257`): 인력·투입기간·`monthly`(월별 MM)·`status`(MM 입력중→MM 저장완료→SCM 승인대기→SCM 승인완료).
  - 상태 전이: `requestLaborApproval(id)`(`budget-status.js:2628`, MM>0 필요 → '승인대기', SCM 문서번호 발번) → `completeLaborScmApproval(id)`(`:2644`, '승인완료' + 예산 반영).
  - **예산 반영**: `syncLaborAssignmentsToBudget(proj)`(`budget-status.js:2655`) — `SCM 승인완료` 인력만 계획월별 `mm×unitPrice`로 인건비 `q`(투입확정) + details(`source:'laborAssignment'`)에 반영.
- **이관인건비**(`getLaborTransferSummaryFinal`, `:241`): 받은(+)/보낸(−)/순이관(=받은−보낸). 받은 금액은 실적 반영, 보낸 금액은 원가실적 차감. **신규 등록은 Receiver Project만, Sender Project는 집행완료 후 조회 전용**.
- **OT비**(`renderLaborOtPanelFinal`, `:308`): 경비 자원계획처럼 **월별 금액 직접 키인**(`labor-ot-<id>-<idx>`), `saveLaborOtPlanFinal()`로 저장 → 인건비 예산내역 OT비 행 반영. 계정 `701301`(종업원급여-OT) 한 줄만 사용(`701302` 필터 제외, `:302`).
- 알림 시그널 3종(`laborSignalsFinal`, `:134`): ①OT 미계획 실적 발생 ②P레벨 단가 확정으로 인한 초과(단가는 매년 5월경 확정) ③SCM 확정 인력 미등록.

### 4.4 외주비 상세 (6종) — `budget-area-outsource.js` + `budget-status-2.js`

### 4.6 경비 상세 (중계정·통제/비통제·연단위 계획·ERP 한도) — `budget-area-expense.js`
- **중계정(예산통) 9종**(`EXPENSE_MIDDLE_ACCOUNTS_FINAL`, `:20`): 각 `control`='통제'|'비통제'. 예: 조직운영비·소모품비·교육훈련비·접대비(통제), 일반비통제성·인건비(비통제).
- **소계정 11행**(`EXPENSE_ACCOUNT_ROWS_FINAL`, `:32`): `middleCode`로 중계정에 소속, `controlled`, `code`, `name`, `carried`(이전계획), `actual`, `erpAvailable`(통제만, 비통제는 null), `monthly[]`(월별).
- **예산통(pool) 규칙**(`:90~124`): 예산은 **중계정 단위로 한 통**, 사용자는 소계정 단위로 작업 → 같은 중계정 소계정들은 ERP 가용예산을 **나눠 쓰는 게 아니라 함께 쓴다**. 화면은 중계정 코드·이름을 감추고 가용잔액 칸을 병합(`rowspan`)해 공유 표시.
- **계획 = 연단위 입력**(`:65~88`): 월별 입력이 의미 없어 연도(26/27년)로 통합. `expensePlanYearsFinal()`가 `EXPENSE_PLAN_MONTHS`를 연도 구간으로 분해, 헤더는 `expenseYearLabel`("26년 (7월~12월)"). 저장 시(`saveExpensePlan`, `:159`) 연 합계를 **해당 연도 첫 월 슬롯에 통합 저장**(나머지 월 0, 합계 유지).
- **월별 실적 [+] 펼침**(`:228~257`): 실적 헤더의 `＋`(`toggleExpenseActualCols`)로 지난 26년 1~7월(`EXPENSE_ACTUAL_MONTHS`) 월별 실적 열 펼침. 후반월 가중(`EXPENSE_ACTUAL_WEIGHTS`)로 배분, 합계는 `row.actual`과 일치.
- **한도 검증(`validateExpenseErpAvailability`, 최종본 `:133`)**: **통(중계정) 단위** — `통 계획합계(expensePoolPlanFinal) > 통 가용예산(expensePoolAvailableFinal)`이면 오류(소계정 개별 초과는 통 안에서 상쇄되므로 오류 아님). 실시간 재계산 `expenseRecalcRow(id)`(`:271`)가 입력 시 통 잔액을 함께 갱신.
- `getExpenseTransferLimit()`(`:152`): 통제=`erpAvailable` 합, 비통제=계획합계 → §4.2 이관 검증에 사용.
- 가용예산조회 모달 `showExpenseErpAvailabilityModal`(`:181`): 중계정별 이전예산(A)/현재계획(B)/가용예산/잔액 표. 규칙 문구: "통제 계정은 매출귀속부서에 ERP 가용예산이 있어야 계획 수립 가능."

## 8. 사용자 플로우

### 8.1 원가현황 조회
1. 상단 메뉴 "수행원가 > 원가현황" 또는 `#/budget-status` → `showCostStatus()`(`costMode='status'`) → 프로젝트 목록.
2. 홈 Work Feed 등에서 `#/budget-status?pj=cloud` → 그 프로젝트 상세 바로 진입, `openBudgetProjectScreen`이 `showBudgetSummaryGrid()`까지 실행 → 월별 계획/실적 그리드 표시.

### 8.2 원가조정(계정별 예산 수정)
1. `#/budget-adjust` → `costMode='adjust'` → 상세 진입 시 `budgetSetupStage='edit'`.
2. 계정 타일 클릭(예: 외주비) → `openBudgetAccountEditor('외주비')` → URL이 `#/budget-adjust/outsource?pj=<키>`로 갱신.
3. 상세계정 탭 선택 → 등록/수정 → 저장. (경비는 통 단위 ERP 가용예산 초과 시 저장 차단.)
4. 딥링크로 `#/budget-adjust/expense?pj=budgetMock` 직접 접속도 동일 지점 도달(`openCostArea`).

### 8.3 예산 이관
1. 상세 → `budgetDetailStep='overview'`의 계정별 집행 현황 표 → `예산 이관 수정`(`startBudgetTransferEdit`).
2. 계정별 조정배분 입력 → `저장`(`saveBudgetTransfer`) → §4.2 검증 통과 시 `budgetTransferHistory`에 신규 버전 추가 + localStorage 저장 + 토스트.

### 8.4 변경 이력 조회
1. `#/budget-history` → `costMode='history'` → 상세 진입 시 `budgetSetupStage='history'`(실행예산 버전 이력) — 버전 pill 선택으로 열람, `＋신규 버전 생성`.
2. 계정별 예산 집행 현황 표 하단의 이관 변경 이력 탭(`actr-history-tabs`)에서 `selectBudgetHistoryVersion(v)`로 버전별 변경 전/후/증감 조회.

### 8.5 결재
계정별 작성 완료 → `결재 상신 →`(`goBudgetSetupStage('approval')`) → 결재라인(기안자 이봄 → 팀장 김도윤) 승인.
