> 근거 소스: `public/js/si-project.js`, `public/js/proposal-project.js`, `public/js/app.js`(라우팅·진입), `public/js/wg-project.js`, `public/js/internal-project.js`, `public/js/investment-project.js`, `public/js/advance-project.js`
> 대상 코드베이스: SI 예산관리 목업 웹앱 (`C:\Workspace\budget`). 모든 데이터는 JS 상수 기반 목업이며 실제 API 호출은 없음.

## 1. 개요 (프로젝트 유형 구분)

프로젝트 관리는 좌측 메뉴 "프로젝트" 그룹(`sub-ops`) 하위에 6개 유형으로 구성된다. 각 유형은 독립 JS 파일로 관리되며 진입 함수(`show*Project`)와 렌더 함수(`render*Project`)를 가진다.

| 유형 | 메뉴명 | 소스 파일 | 데이터 상수 | 진입 함수 | 성격 |
|------|--------|-----------|-------------|-----------|------|
| 수주형 | 수주형 프로젝트 | `si-project.js` | `SI_PROJECTS` | `showSIProject()` | CRM 계약완료 → 등록, IF(선행시스템) 연동 중심 |
| 제안 | 제안 프로젝트 | `proposal-project.js` | `PROPOSAL_PROJECTS` | `showProposalProject()` | 수주형에 딸린 제안(P00N 채번), 수주형 대시보드 재사용 |
| W/G | W/G 프로젝트 | `wg-project.js` | `WG_PROJECTS` | `showWGProject()` | 결재(기안→승인) 흐름 + 예산 항목 |
| 사내 | 사내 프로젝트 | `internal-project.js` | `INTERNAL_PROJECTS` | `showInternalProject()` | 결재 상신/승인 + 예산 항목 입력 |
| 투자 | 투자프로젝트 | `investment-project.js` | `INVESTMENT_PROJECTS` | `showInvestmentProject()` | 사내 프로젝트와 동일 구조, 라벨/데이터만 상이 |
| 선투입 | 선투입 프로젝트 | `advance-project.js` | `ADVANCE_PROJECTS` | `showAdvanceProject()` | 사내 프로젝트 구조 기반, 선투입 집행·본 PJT 승계 |

핵심 구분:
- **수주형 / 제안**: CRM·ERP 등 선행 시스템에서 인터페이스(IF)로 수신한 데이터를 조회·표시하는 것이 중심. 등록은 외부 계약완료 프로젝트 조회 후 선택 등록(수주형) 또는 원 수주 프로젝트에 P00N 채번(제안). 상세 화면은 **동일한 IF 대시보드(`siDetailHtml`)를 공유**한다 (`proposal-project.js:145`).
- **W/G / 사내 / 투자 / 선투입**: 결재(기안·검토·승인·반려) 상태와 예산 항목(재료비/노무비/외주비/경비) 입력 중심. 사내·투자·선투입은 서로 거의 동일한 화면 구조를 공유하며 라벨·데이터만 다르다(각 파일 상단 AI GUIDE 주석 근거).

> 본 문서는 과제 범위에 따라 수주형·제안을 상세히 기술하고, 나머지 4개 유형은 구분·진입·데이터 구조 수준으로 요약한다.

## 2. 진입 경로 & URL

### 2.1 라우트 매핑 (`app.js`)

해시 기반 SPA 라우팅. 화면 ID ↔ 라우트 문자열 매핑(`SCREEN_ROUTES`, `app.js:71-76`)과 라우트 ↔ 액션 매핑(`ROUTE_ACTIONS`, `app.js:94-99`).

| URL 해시 | 화면 컨테이너 ID | 액션 함수 |
|----------|------------------|-----------|
| `#/si-project` | `s-si-project` | `showSIProject()` |
| `#/proposal-project` | `s-proposal-project` | `showProposalProject()` |
| `#/wg-project` | `s-wg-project` | `showWGProject()` |
| `#/internal-project` | `s-internal-project` | `showInternalProject()` |
| `#/investment-project` | `s-investment-project` | `showInvestmentProject()` |
| `#/advance-project` | `s-advance-project` | `showAdvanceProject()` |

- 해시 변경 시 `routeFromHash()`(`app.js:137`)가 `resolveAction()`으로 정적 `ROUTE_ACTIONS`를 우선 매칭한다(`app.js:132-136`).
- 초기 진입은 `routeInitial()`(`app.js:142`), 매칭 실패 시 `showMain()`.
- 화면 전환 후 `updateHashForScreen()`(`app.js:112`)이 해시를 동기화하며, `_suppressNextHash` 플래그로 중복 라우팅을 방지한다.
- 목록↔상세 전환은 해시를 바꾸지 않고 내부 상태(`siView`/`ppView`)만 바꿔 재렌더한다(딥링크는 목록 화면까지만).

### 2.2 진입 함수 동작 (`app.js:229-270`)

모든 진입 함수는 공통적으로 `openNavGroup('sub-ops')`로 프로젝트 메뉴 그룹을 펼치고, `setScreen(...)`으로 화면 컨테이너를 표시, `setNav(...)`로 네비 항목을 활성화한 뒤 렌더 함수를 호출한다.

- `showSIProject()` (`app.js:229`): `setScreen('s-si-project')` → `setNav('nav-si-project')` → `renderSIProject()`. (siView 상태는 리셋하지 않음)
- `showProposalProject()` (`app.js:236`): `ppView='list'`로 초기화 후 `renderProposalProject()`.

### 2.3 AI 바로가기(딥링크) 키워드

`app.js:1642-1659`의 라우팅 카탈로그에 자연어 키워드 정규식과 이동 함수가 등록되어 있다. 예:
- 수주형: `k:/(수주형|수주|SI프로젝트|si)/i` → `showSIProject`, 경로 `['프로젝트','수주형 프로젝트']`
- 제안: `k:/(제안)/` → `showProposalProject`
- W/G: `k:/(wg|w\/g|워킹그룹)/i`, 사내: `/(사내)/`, 투자: `/(투자)/`, 선투입: `/(선투입)/`

### 3.3 수주형 상세 대시보드 — 공용 `siDetailHtml` (`si-project.js:750`)

> 상세 진입 시 최종 오버라이드된 `renderSIDetail`(`si-project.js:810`)이 `siActiveProject = p`를 설정하고 `el.innerHTML = siDetailHtml(p, "closeSIDetail()")`로 렌더한다.
> (파일 앞부분 `si-project.js:397`에 옛 버전 `renderSIDetail`(진행 스텝 3단계 + 기본정보 + 단계별 기간 + IF 변경이력)이 정의되어 있으나, `si-project.js:810`에서 함수 자체를 재할당하여 **공용 대시보드 버전이 실제 사용**된다. 옛 버전에서 쓰이던 `buildSIProgressV2`·`buildSIPhaseSection`·`buildSIHistory` 등은 현재 상세 화면에서 호출되지 않음.)

`siDetailHtml(p, backOnclick, extraMeta)` 구성 (모두 `.sifr` 클래스 스코프):

1. **헤더 행** (`si-project.js:773-789`): 프로젝트코드, 프로젝트명(h1), 메타줄(단계 pill + `고객사 · 매출귀속조직` + `기간` + `extraMeta`). 우측 버튼: "← 목록"(`backOnclick`), "종료 처리 →"(현재는 `showToast('종료 처리는 준비 중입니다.')` 목업).
2. **진행 스텝 카드**(`si-project.js:791-794`): `siStepper(p.stage)` — 착수/수행/종료 3단계 노드. 안내 문구 "착수·종료는 조건 충족 시 자동 실행되며, 필요 시 수동으로도 처리".
3. **선행 시스템 동기화 상태 섹션**(`si-project.js:796-800`): 기준시각(`d.asOf`) + 시스템별 동기화 카드(`d.sync`) 그리드. 각 카드 = 시스템 배지 + IF 방향 칩(⇄/←/→) + 상태(정상/지연) + 마지막 교환시각 + 최근 30일 변경건수. **카드 클릭 시 `siOpenSyncPopup(sys)`로 해당 시스템 IF 이력 팝업**. 하단 노트: IF는 송수신 양방향(ERP는 송신 위주, AI SCM·AI CRM·구매는 수신).
4. **기본정보 섹션**(`si-project.js:802-805`): `d.basic` 필드 그리드. 각 필드 = 라벨 + 출처 시스템 배지(`sifr-src`) + (최근변경 시) 변경 태그 + 값. 노란 배경(`changed`)은 최근 변경 항목.

### 3.4 IF 이력 팝업 (`siOpenSyncPopup` / `siSyncPopupBody`, `si-project.js:819-865`)

- 동기화 카드 클릭 → 오버레이 모달(`#sifr-sync-modal`) 생성/표시.
- 헤더: 시스템 배지 + IF 방향 배지 + "IF 변경이력" + 건수.
- 본문: 해당 시스템(`e.sys === sys`)의 로그(`d.log`)를 날짜별 그룹핑하여 타임라인으로 표시. 각 행 = 시각 + 송/수신 배지(`siIo` 판정) + 필드명 + delta + before→after diff + note.
- 닫기: `siCloseSyncPopup()`(오버레이 클릭 또는 ✕). `miss()` 헬퍼로 '미등록'/'—'/빈값을 "미등록"으로 표기.

### 3.5 제안 목록/상세

## 4. 비즈니스 로직 & 규칙 (채번 · IF 동기화 · 상태)

### 4.1 채번 규칙

- **수주형 코드**: `30142101-D001` 형태 = `{8자리 프로젝트 base}-D{3자리}` (D 시리즈). CRM 풀(`CRM_PROJECTS_POOL`)의 코드를 그대로 승계(`siConfirmRegister`, `si-project.js:357`은 `code: p.code`로 CRM 코드 유지).
- **제안 코드**: `30142101-P001` 형태 = `{수주형 base}-P{3자리}` (P 시리즈, P00N 채번). 예: 원 수주 `30142101-D001` → 제안 `30142101-P001`, `30142101-P002` (`proposal-project.js:12,47`). 즉 **원 수주 프로젝트 base 코드를 공유하고 접미사만 D→P로 구분**하며, 제안은 `parent`/`parentName` 필드로 원 수주와 연결된다.
- **내부 식별자(맵 key)**: 수주형 `SI-00N`(`siConfirmRegister`에서 `SI-${idx.padStart(3,'0')}`, idx = 기존 키 수 + 1, `si-project.js:353-354`), 제안 `PP-00N`.

### 4.2 수주형 신규 등록 흐름 (목업)

1. `siMockFetch()` (`si-project.js:271`): 입력값으로 `CRM_PROJECTS_POOL` 필터(코드 또는 PM 이름 부분일치). 결과 0건 → 경고, 1건 → 자동 선택(`siRegSelectProject(0)`), 복수 → 선택 목록 렌더.
2. `siRegSelectProject(idx)` (`si-project.js:318`): 선택 프로젝트의 CRM 기본정보를 읽기전용 필드(`buildSIFieldReadonly`)로 표시. 각 필드는 출처 배지(ERP = `IF·ERP`, 그 외 = `수동입력`)를 가짐(`si-project.js:375-383`).
3. `siConfirmRegister()` (`si-project.js:350`): 새 `SI-00N` 키로 `SI_PROJECTS`에 추가. 초기 `stage:'등록완료'`, `ifSource:'CRM'`, `lastSync = 현재시각`, `ifHistory`에 "프로젝트상태: 최종계약완료 → 등록완료(CRM)" 1건 기록. 이후 상세로 전환.
- 등록 전제: CRM `status === '최종계약완료'`인 프로젝트만 등록 가능(안내 배너 및 풀 데이터 근거).

### 4.3 진행 단계(stage) 모델

- **정식 단계 배열** `SI_STAGES = ['등록완료','착수','수행중','마감준비','종료완료']` (`si-project.js:27`), 배지 스타일 `SI_STATUS_STYLE`(`si-project.js:29-35`).
- **상세 대시보드 3단계 스테퍼** `siStepper(stage)` (`si-project.js:730`): 착수/수행/종료로 압축 매핑.
  - 착수: done = stage ∈ {수행중, 마감준비, 종료완료}, now = (stage==='착수')
  - 수행: done = stage ∈ {마감준비, 종료완료}, now = (stage==='수행중')
  - 종료: done = (stage==='종료완료'), now = (stage==='마감준비')
- (옛 버전 3단계 `siPhase()`/`buildSIProgressV2`, `si-project.js:475-509` — 수동 착수 `siManualStart`/수동 종료 `siManualClose`로 stage를 변경하고 ifHistory에 "수동" 출처 기록. 현재 상세 화면에는 미노출.)

### 4.4 선행 시스템 IF 동기화 규칙

- **시스템 메타** `SI_SYS` (`si-project.js:678-684`): ERP(색 #2563EB, 방향 `both`), SCM=AI SCM(`in`), CRM=AI CRM(`in`), PUR=구매(`in`), ETC=수동입력(`none`).
- **IF 방향** `SI_DIR` (`si-project.js:688-692`): `both`=송수신(⇄, "MIS ⇄ ERP · 송신 위주"), `in`=수신(←, "선행 시스템 → MIS"), `out`=송신(→, "MIS → 선행 시스템").
- **건별 송수신 판정** `siIo(e)` (`si-project.js:696-699`): 이력에 `io`('in'/'out')가 있으면 우선, 없으면 시스템 방향 기준(수신 시스템은 수신, ERP 등은 송신). 즉 ERP는 송신 위주로 표기.
- **동기화 상태 flag**: `sync[].flag`가 `'ok'`면 "정상", 아니면 값 그대로(예: `'지연 3일'`, `'지연 4일'`) 경고 표시(`sifr-flag warn`).
- **파생 로직** `siBuildDetail(p)` (`si-project.js:703-727`): `p.ifDetail`이 있으면 그대로 사용. 없으면 기존 `ifHistory`에서 `ifDetail` 구조(sync/basic/log)를 자동 파생한다.
  - source 매핑: `{ERP:ERP, SCM:SCM, BIX:CRM, CRM:CRM, PUR:PUR, 구매:PUR}`.
  - `log`: ifHistory 각 건을 date/time/sys로 분해. `sync`: 시스템별 그룹의 첫 건 시각 + 건수(flag는 일괄 'ok'). `basic`: 프로젝트 필드(기간/PM/매출귀속조직/유형/상태/계약형태/주수행부서/고객사)를 고정 매핑.

### 4.5 상태(뷰) 규칙

- 수주형 뷰: `siView ∈ {list, detail, register}` (`si-project.js:11`), 선택 ID `siSelectedId`.
- 제안 뷰: `ppView ∈ {list, detail}` (`proposal-project.js:6`), 선택 ID `ppSelectedId`.
- 상세 화면에서 동기화 팝업이 참조하는 현재 프로젝트는 공용 전역 `siActiveProject`(`si-project.js:746`)로 지정 — 수주형/제안 모두 상세 렌더 시 이 값을 세팅한다.

## 6. 백엔드 / API 연동

- **없음(목업).** 모든 데이터는 JS 상수(`SI_PROJECTS`, `PROPOSAL_PROJECTS`, `CRM_PROJECTS_POOL`)에 하드코딩. CRM 조회(`siMockFetch`)·등록(`siConfirmRegister`)·수동 착수/종료·단계 저장은 모두 메모리 내 객체 조작이며 새로고침 시 초기화된다.
- "선행 시스템 IF"는 실제 인터페이스가 아니라 `ifDetail`/`ifHistory` 목업 데이터를 표시하는 개념. 향후 실제 요구사항: ERP·AI SCM·AI CRM·구매 시스템과 송수신 인터페이스로 프로젝트 기본정보·계약금액·투입인원·발주금액 등을 동기화. IF 방향(송신/수신)과 마지막 교환시각·지연 여부를 모니터링.
- "종료 처리" 버튼은 현재 `showToast('종료 처리는 준비 중입니다.')` 목업(`si-project.js:787`).

## 7. 데이터 모델

### 7.1 `SI_PROJECTS` 항목 필드 (`si-project.js:45-149`)

| 필드 | 타입/예시 | 설명 |
|------|-----------|------|
| `code` | `'30142101-D001'` | 프로젝트 코드(D 시리즈) |
| `name` | 문자열 | 프로젝트명 |
| `start` / `end` | `'2026-05-01'` | 프로젝트 기간 |
| `pm` | `'한민석'` | 수행 PM |
| `revOrg` | `'NOVA PMO팀'` | 매출귀속조직 |
| `projType` | `'원가-선투입'`, `'SI-AD'`, `'OS-운영'` | 프로젝트 유형 |
| `stage` | `SI_STAGES` 중 하나 | 진행 단계 |
| `contractType` | `'IV'`, `'단가계약'`, `'총액계약'` | 계약형태 |
| `mainDept` | 문자열 | 주(수행)부서 |
| `customer` | `'SK C&C'` | 고객사 |
| `ifSource` | `'ERP'`/`'CRM'` | 마지막 동기화 출처 |
| `lastSync` | `'2026-04-15 09:30'` | 마지막 IF 시각 |
| `phases[]` | `{name,start,end,status,source}` | 단계별 기간(착수~종료 7단계). source='ERP'/'IF'면 읽기전용, 'PM'이면 편집. (현 상세화면 미사용) |
| `ifHistory[]` | `{date,field,before,after,source}` | IF 변경이력(간이) |
| `ifDetail` | `{asOf, sync[], basic[], log[]}` | IF 대시보드용 상세(있으면 우선 사용) |

`ifDetail.sync[]`: `{sys, when, cnt, flag}` (sys = ERP/SCM/CRM/PUR, flag = 'ok' 또는 '지연 N일').
`ifDetail.basic[]`: `{k(라벨), v(값), sys(출처), changed?(변경설명), num?(숫자정렬)}`.
`ifDetail.log[]`: `{date, rel(상대시각), time, sys, field, before, after, delta?, num?, note?, io?}`.

`CRM_PROJECTS_POOL` 항목(`si-project.js:19-25`): `{code, name, pm, revOrg, projType, start, end, contractType, mainDept, customer, status}` — status는 `'최종계약완료'`.

## 8. 사용자 플로우

### 8.1 수주형 — 신규 등록
1. 좌측 메뉴 프로젝트 > 수주형 프로젝트(`#/si-project`) → 목록.
2. "+ 신규 등록" → CRM 조회 화면.
3. 프로젝트 코드/PM 입력 → 조회(`siMockFetch`) → (복수 시) 프로젝트 선택.
4. 가져온 CRM 기본정보(출처 배지) 확인 → "등록 완료"(`siConfirmRegister`) → stage='등록완료'로 `SI_PROJECTS`에 추가, 상세 화면 전환.

### 8.2 수주형 — 조회 및 IF 모니터링
1. 목록에서 검색/단계 필터로 프로젝트 탐색.
2. 행 클릭 → 상세 대시보드(`siDetailHtml`): 진행 스텝(착수/수행/종료), 선행 시스템 동기화 카드, 기본정보(출처 배지·최근변경 강조).
3. 동기화 카드 클릭 → 해당 시스템 IF 변경이력 팝업(날짜별 타임라인, 송/수신·before→after).
4. "← 목록"으로 복귀.

### 8.3 제안
1. 프로젝트 > 제안 프로젝트(`#/proposal-project`) → 목록(원 수주 프로젝트 표시). 신규 등록 UI 없음(수주형에서 P00N 채번되는 개념).
2. 행 클릭 → 수주형과 동일한 IF 대시보드(메타줄에 "원 수주 {parent}" 추가) → 동일 동기화/이력 흐름.
