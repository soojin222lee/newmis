# 인사이트 > 버전별 예산 (version)
> SRS Agent 입력용. 이 탭에 집중한 심화 명세.

## 1. 개요
- **목적**: 기준선(계약 원가 `base` 배분) 대비 실행예산 버전(V1~V4)의 **계정 간 예산 돌려쓰기**를 분석한다. 총액은 버전 내내 동일하고, 계정 간 배분만 이동한다.
- **위치**: 인사이트 세 번째 탭. `insTab='version'` (showInsights insights.js:278-283, 탭 라벨 "버전별 예산" insights.js:307).
- **핵심 개념**: **총액 불변, 계정 이동**. 인건비→외주비로 배분이 옮겨가는 추세를 시각화(차트+표)하고 AI로 요약.
- **부가 기능**: 계정별 필터(전체/4대계정), 금액↔비율 토글, 계정 [+] 상세계정 펼침.

## 2. 진입 경로 & URL (#/insights/version?pj=)
- **해시 라우트**: `#/insights/version?pj=<프로젝트ID>` (app.js:130, insHash('version') app.js:1248).
- **진입**: `showInsights('version')` (insights.js:278) 또는 탭바 클릭. 딥링크 `gotoInsights(pj,'version')`.
- **pj 파라미터**: 불투명 ID → `insProjectIndexById` (insights.js:276).
- **메인 챗 네비게이터 연계**: `localNavigate` (server.js:498)에서 "버전/돌려/배분" 키워드 → `insights-version`.

## 3. 화면 구성 (섹션별 UI)
렌더 진입점: `insVersionHtml(p)` (insights.js:707-717) → 핵심 패널 `insVerPanel(p)` (insights.js:91-103).

1. **탭 인트로** `insTabIntro` (insights.js:709): "버전별 예산 — 기준(계약 원가) 대비 실행예산 버전(V1~V4)의 계정 간 돌려쓰기 분석".
2. **패널 헤더** (insights.js:711-714): 제목 + 4대계정 범례(`INS_ACCTS` insights.js:49-52: 인건비/외주비/재료비/경비).
3. **컨트롤 바** `ins-ver-ctrl` (insVerPanel insights.js:94-100):
   - 계정 세그먼트 `[전체][인건비][외주비][재료비][경비]` → `selectInsVerAcct(t)`.
   - 단위 세그먼트 `[금액][비율]` → `setInsVerUnit(u)`.
   - 우측 `[✦ AI 요약]` → `insBudgetAiSummary()`.
4. **차트** `ins-ver-chart` (insights.js:101-102): `insVerAcct==='전체'`면 `insVerAllChart(cols)`, 아니면 `insVerOneChart(cols, acct)`.
5. **표** `insVerTable(cols)` (insights.js:212-242): 계정별 행(기준+V1~V4+증감) + [+] 상세계정 펼침 + 합계행.

## 4. 비즈니스 로직 & 규칙 (지표 수식·차트 데이터·계산)

### 4.1 버전 컬럼 구성 — `insVerCols(p)` (insights.js:82-85)
- `[{label:'기준', sub:'계약원가', vals:projBaseline(p), isBase:true}, ...projVersions(p) 4개]`.
- 총 5개 컬럼: 기준 + V1~V4.

### 4.2 기준선 배분 — `projBaseline(p)` (insights.js:78-81)
- 계약 원가 `base`를 고정 비율 `{인건비:0.42, 외주비:0.33, 재료비:0.17, 경비:0.08}`로 안분.
- 예: 인건비 = `base*0.42` (소수1자리).

### 4.3 버전별 배분 — `projVersions(p)` (insights.js:68-77) **(돌려쓰기 핵심)**
- `B = p.budget` (총 실행예산, **모든 버전 동일**).
- 현재(V4) 배분 비율 `cur = {인건비:0.40, 외주비:0.35, 재료비:0.17, 경비:0.08}`.
- 이동량 `shift = [0.055, 0.036, 0.018, 0]` (V1→V4, 인건비→외주비 이동 비율).
- 각 버전 vals: `인건비 = B*(cur.인건비 + s)`, `외주비 = B*(cur.외주비 - s)`, `재료비 = B*cur.재료비`, `경비 = B*cur.경비`.
- **불변식**: 인건비 증가분 = 외주비 감소분 → 총액 일정. V1이 인건비 최대(초기), V4가 외주비 최대(현재).

### 4.4 값 계산 & 단위 토글
- `colTotal(c)` (insights.js:86): 컬럼 4계정 합.
- `insVerVal(c, key)` (insights.js:87): 비율 모드면 `vals[key]/colTotal*100`, 금액 모드면 원값.
- `insVerFmt(v)` (insights.js:88): 비율 "N.N%" / 금액 "N.N억".
- `insVerDeltaUnit()` (insights.js:89): 비율 "%p" / 금액 "억".

### 4.5 전체 차트 — `insVerAllChart(cols)` (insights.js:186-210)
- **비율 모드** (insights.js:190-199): 100% 누적 스택바. 각 컬럼에 4계정을 아래→위로 쌓음.
- **금액 모드** (insights.js:200-209): 그룹 클러스터 컬럼(계정별 얇은 막대). 기준 컬럼은 opacity 0.4로 흐리게, 라벨에 "(원가)" 표기.

### 4.6 개별 계정 차트 — `insVerOneChart(cols, acct)` (insights.js:167-184)
- 선택 계정 하나만: 기준선(점선 `#8a94a6` + "기준 값" 라벨) + 컬럼 막대(기준=회색, 버전=계정색) + 각 버전 위에 기준 대비 증감(`d=v-baseVal`, 색상 up/down).

### 4.7 표 — `insVerTable(cols)` (insights.js:212-242)
- 헤더: 계정 | 기준(계약원가) | V1 | V2 | V3 | V4 | 증감(V4−기준).
- 행 필터: `insVerAcct==='전체'`면 4계정 모두, 아니면 선택 계정만.
- **증감** = `insVerVal(lastCol) − insVerVal(baseCol)` (V4−기준), up/down 색상.
- **상세계정 펼침**(insights.js:226-235): `insVerExpanded[key]` true면 `INS_SUB_ACCTS[key]`(insights.js:61-66) 하위계정 행 추가. 하위 값 = 부모값 × 비율 `s.r`, 하위 증감 = 부모증감 × `s.r`.
- **합계행**(insights.js:240): 전체 모드에서만. 비율="100.0%", 금액=`colTotal` 합.

### 4.8 상세계정 매핑 `INS_SUB_ACCTS` (insights.js:61-66)
- 인건비(3): 실투입인건비 0.72 / 이관인건비 0.18 / OT비 0.10.
- 외주비(6): 실투입 0.40 / 전문직 0.16 / 외주출장비 0.10 / 공사MA 0.14 / 이관외주비 0.12 / 기타외주비 0.08.
- 재료비(3): 상품재료비 0.68 / 감가상각비 0.20 / 기타재료비 0.12.
- 경비(5): 조직운영비 0.34 / 소모품비 0.22 / 접대비 0.14 / 교육훈련비 0.12 / 기타경비 0.18.

## 5. 프론트엔드 로직 (함수/상태 — 파일:함수 인용)

### 5.1 전역 상태 (insights.js:53-58)
- `insVerAcct` ('전체'|계정명) — 계정 필터.
- `insVerUnit` ('금액'|'비율') — 단위 토글.
- `insVerExpanded{}` — 계정별 상세 펼침.
- 상태 변경 함수(모두 `renderInsights()` 재렌더): `selectInsVerAcct(a)`(56), `setInsVerUnit(u)`(57), `toggleInsVerAcct(key)`(58).

### 5.2 렌더
- `insVersionHtml(p)` (707) → `insVerPanel(p)` (91): 컨트롤 + 차트(전체/개별 분기) + 표.
- 차트: `insVerAllChart`(186) / `insVerOneChart`(167). 표: `insVerTable`(212).
- 정의 상수: `INS_ACCTS`(49, 4대계정+색), `INS_SUB_ACCTS`(61).

### 5.3 AI 요약 팝업 — `insBudgetAiSummary()` (insights.js:106-122)
1. `cols=insVerCols(p)`, `last=cols[마지막]=V4`, `base=cols[0]=기준`.
2. payload: project, total(=budget), baseTotal(=base), accounts=[{name, base(기준 vals), current(V4 vals), delta=current−base}].
3. `openInsAiModal('loading')` (기본 title "예산 변동 요약").
4. `POST /api/budget-summary` → `openInsAiModal('done', d.summary, d.source)`. 실패 시 'error'.
- 모달 공통 함수 `openInsAiModal`(123)/`closeInsAiModal`(165)은 원가 소진율 탭과 공유.

## 6. 백엔드/API/LLM 연동 (해당 탭 AI 기능 스키마·프롬프트·폴백)

### 6.1 엔드포인트 `POST /api/budget-summary` (server.js:119, handler server.js:216-226)
- **요청 스키마**(insights.js:109-115):
```json
{
  "project":"SKON 통합관제",
  "total":27.2, "baseTotal":26.5,
  "accounts":[
    {"name":"인건비","base":11.1,"current":10.9,"delta":-0.2},
    {"name":"외주비","base":8.7,"current":9.5,"delta":0.8},
    {"name":"재료비","base":4.5,"current":4.6,"delta":0.1},
    {"name":"경비","base":2.1,"current":2.2,"delta":0.1}
  ]
}
```
- **응답**: `{ "summary":"<한국어 3~4문장>", "source":"ai"|"fallback", "note?":"..." }`.
- **검증**: `body.accounts`가 배열 아니면 400 (server.js:217).
- **분기**: 키 없으면 `localBudgetSummary` 폴백, 있으면 LLM(실패 시 폴백+note).

### 6.2 프롬프트 — `buildBudgetPrompt(d)` (server.js:167-176)
- 지시: "총 실행예산을 유지하면서 계정 간 배분만 이동하는 '예산 돌려쓰기'를 비개발자 PM이 이해하기 쉽게 3~4문장 요약. 억 단위, 어느 계정이 늘고 줄었는지+주의점 중심. 마크다운·불릿 금지, 자연스러운 한국어."
- 본문: 프로젝트/총 실행예산(계약 원가 기준 대비)/계정별(기준→현재, 증감).

### 6.3 로컬 폴백 — `localBudgetSummary(d)` (server.js:156-166)
- 증가 계정(ups)/감소 계정(dns) 분리·정렬 → "총액은 동일하나 배분 이동, dns가 줄고 ups로 옮겨감, 특히 최대증가 계정 주의" 문장 생성.

### 6.4 LLM 호출 공통 — `callLLM` (server.js:178-215)
- 종합현황/원가소진율 문서와 동일(gpt-4o-mini, 키=env only, 20s timeout, 클라이언트 키 미노출).

## 7. 데이터 모델

### 7.1 컬럼 객체 (insVerCols 반환 요소)
- 기준: `{label:'기준', sub:'계약원가', vals:{인건비,외주비,재료비,경비}, isBase:true}`.
- 버전: `{label:'V1'..'V4', sub:'', vals:{...}}`.

### 7.2 배분 상수
- 기준 비율 `{인건비:0.42, 외주비:0.33, 재료비:0.17, 경비:0.08}` (projBaseline insights.js:79).
- V4 비율 `{인건비:0.40, 외주비:0.35, 재료비:0.17, 경비:0.08}` + 이동량 `shift=[0.055,0.036,0.018,0]` (projVersions insights.js:70-71).

### 7.3 계정/상세 정의
- `INS_ACCTS` (insights.js:49-52): 4대계정 + 색(인건비 #2f6bed, 외주비 #ea002c, 재료비 #f5a623, 경비 #22b07d).
- `INS_SUB_ACCTS` (insights.js:61-66): 계정별 상세계정 배분비율(합 1.0).

### 7.4 입력 원천 `INS_PROJECTS[i]` (insights.js:23-34)
- 사용 필드: `base`(기준 배분 총원), `budget`(버전 총액).

## 8. 사용자 플로우
1. 인사이트 진입 후 "버전별 예산" 탭 → `#/insights/version`.
2. `insVersionHtml` 렌더: 기본 전체(금액) 모드. 그룹 컬럼 차트로 기준+V1~V4 계정 배분 비교(기준 컬럼 흐리게).
3. 표에서 계정별 기준→V1~V4 값과 증감(V4−기준) 확인.
4. 계정 세그먼트로 특정 계정 선택 → 개별 차트(기준선 + 버전 막대 + 증감)로 전환.
5. 단위 세그먼트 `[비율]` → 100% 누적 스택 차트·표 %로 전환(증감 단위 %p).
6. 표에서 계정 [+] 클릭 → 상세계정(실투입/이관/OT 등) 행 펼침, 부모값×비율로 안분.
7. `[✦ AI 요약]` → 모달 스피너 → `/api/budget-summary` 응답을 3~4문장으로 표시(AI/샘플 라벨).
8. 다른 프로젝트 전환 시 재계산·재렌더(필터/단위/펼침 상태는 전역 유지).

## 10. 요구사항 후보 (bullet)
- 버전별 예산은 총 실행예산을 버전 내내 고정한 채 계정 간 배분 이동('돌려쓰기')을 표현해야 한다.
- 기준선(계약 원가 배분) 대비 각 버전(V1~V4)의 계정 증감을 차트와 표로 제공해야 한다.
- 인건비 증가분과 외주비 감소분이 상쇄되어 총액이 일정하다는 불변식을 데이터가 만족해야 한다.
- 계정 필터(전체/인건비/외주비/재료비/경비)를 제공하고, 전체는 그룹/누적 차트, 개별은 기준선+막대 차트로 전환해야 한다.
- 금액↔비율 단위 토글을 제공하고, 비율 모드에서는 100% 누적 차트와 %/‰p 단위로 표현해야 한다.
- 표에서 계정별 [+]로 상세계정(실투입인건비/이관인건비/OT 등)을 펼치고, 배분비율로 안분한 값과 증감을 보여야 한다.
- 전체 모드 표에는 합계행을 제공해야 한다(금액=합, 비율=100%).
- AI 요약은 기준 대비 V4 계정 증감을 근거로 3~4문장 돌려쓰기 요약을 생성하고, LLM 미설정/실패 시 규칙 기반 폴백을 제공해야 한다.
- AI 요약 모달은 생성 출처(AI/샘플)를 표시하고 원가 소진율 탭과 동일한 모달 컴포넌트를 재사용해야 한다.
- 계정/단위/펼침 상태는 전역으로 유지되어 프로젝트 전환 시에도 사용자의 보기 설정이 보존되어야 한다.
