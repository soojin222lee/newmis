# 인사이트 > 종합 현황 (overview)
> SRS Agent 입력용. 이 탭에 집중한 심화 명세.

## 1. 개요
- **목적**: 선택한 프로젝트의 손익·원가 핵심 지표(KPI)와 월별 원가 추세, AI 자동 인사이트, 계정별 원가 상세를 한 화면에서 조망한다.
- **위치**: 인사이트 3개 탭 중 첫 번째(기본) 탭. `insTab='overview'` (insights.js:7, showInsights insights.js:278-283).
- **핵심 특징**:
  - 프로젝트를 바꾸면(`selectInsProject`) 전체 화면이 재렌더된다.
  - AI Insight는 진입 시 자동 비동기 로드되고 **프로젝트 단위로 캐시**된다(재방문 시 재요청 안 함).
  - 계정별 원가 표는 정렬/컬럼토글/소계정 [+] 펼침을 지원한다.
- **데이터 성격**: 전부 프론트엔드 mock(`INS_PROJECTS`, insights.js:23-34). 서버는 AI 텍스트 생성만 담당.

## 2. 진입 경로 & URL (#/insights/overview?pj=)
- **해시 라우트**: `#/insights/overview?pj=<프로젝트ID>` (app.js:130 DYNAMIC_ROUTES, app.js:1242-1246 `insHash`).
  - `#/insights` (탭 생략) → `gotoInsights(pj, 'overview')`로 기본 overview 진입 (app.js:91).
  - 탭 파라미터가 `overview|progress|version` 외 값이면 overview로 폴백 (showInsights insights.js:279).
- **pj 파라미터**: URL에는 프로젝트 배열 인덱스가 아닌 **불투명 ID**(예: `pj7f3a9c`)를 노출한다.
  - `insRouteId()` (insights.js:275): 현재 프로젝트의 `id` 반환.
  - `insProjectIndexById(id)` (insights.js:276): ID→인덱스 역변환, 없으면 0.
  - `routeQueryParam('pj')` (app.js:121-126): 해시 뒤 `?pj=` 값 파싱.
- **진입 함수**:
  - `showInsights('overview')` (insights.js:278): 화면 전환(`setScreen('s-insights')`) + 좌측 네비 활성(`setNav('ngbtn-sub-insight')`) + `renderInsights()`.
  - `gotoInsights(id, tab)` (insights.js:285-288): 딥링크/AI 바로가기용. id 있으면 프로젝트 먼저 선택 후 탭 표시.
- **프로젝트 변경 시**: `selectInsProject(i)` (insights.js:289-293)가 `updateHashForScreen('s-insights')`로 URL의 pj도 갱신.

## 4. 비즈니스 로직 & 규칙 (지표 수식·차트 데이터·계산)

### 4.1 데이터 용어 정의 (insights.js:22)
- `contract` = 계약금액(수주). `base` = 원가(계약 시 수립 기준). `budget` = 계획(실행예산). `actual` = 실적(누적 집행). `forecast` = 예상원가. `rate` = 예상 원가율(%). `diff` = 원가율 계획 대비 증감(%p).

### 4.2 KPI 5종 — `projKpis(p)` (insights.js:253-264)
| KPI | 값 | 증감칩(chg) | 색상 규칙(dir) |
|---|---|---|---|
| 계약금액 | `contract`억 | "기준" | flat |
| 실행예산 | `budget`억 | "승인" | flat |
| 실적 | `actual`억 | "진행 N%" | flat. `prog=round(actual/forecast*100)` |
| 예상원가 | `forecast`억 | "▲/▼ |overCost|억" | `overCost=forecast-budget`; ≥0 이면 bad(빨강), <0 good |
| 예상 원가율 | `rate`% | "▲/▼ |diff|%p" | `diff`≥0 bad, <0 good |
- 파생: `profit=contract-forecast`(계산되나 KPI에는 미표시, 보고서에서 사용).

### 4.3 월별 원가 Trend 데이터 — `projTrend(p)` (insights.js:244-252)
- 월별 가중치 `MW`(12개월 배열, insights.js:16)를 정규화한 `w`로 예산을 월배분.
- `plan[i] = budget * w[i]` (12개월 전체).
- `actual[i]` = `i < INS_CUR(8)`인 달만; `plan[i]*(1+(r-1)*1.15)`, 여기서 `r=forecast/budget`. (실적을 예상원가 비율보다 1.15배 과장 반영)
- `forecast[i]` = `i >= INS_CUR-1`인 달만; `plan[i]*r`. (7월부터 예측선, 실적선과 1개월 겹침)
- 결과는 `insCurTrend` 전역에 저장(insights.js:500) → hover 툴팁에서 재사용.

### 4.4 계정 파생 데이터 — `projAccounts(p)` (insights.js:37-46)
- 5대 원가 카테고리 `COST_CATS`(인건비/외주비/구매/경비/기타, insights.js:17-20)의 `cost` 금액 비중(`sh = fc/fcSum`)으로 base/plan/actual을 안분.
- 계정별 산출: `base=p.base*sh`, `plan=p.budget*sh`, `actual=p.actual*sh`, `forecast=cost[key]`(원본), `share=round(sh*100)`, `delta=forecast-plan`, `deltaBase=forecast-base`.

### 4.5 규칙 기반 AI 폴백 인사이트 — `projAI(p)` (insights.js:265-271)
- `diff>=0`: danger "예상원가 초과", 아니면 info "원가 절감".
- 항상 warning "외주비 비중 주의"(외주비/forecast %) 추가.
- LLM 실패 시 이 텍스트를 인사이트로 사용(insights.js:489).

### 4.6 계정별 원가 표 상호작용
- **정렬** `insSortBy(k)` (insights.js:913): 같은 키 재클릭 시 asc/desc 토글, 다른 키는 desc 시작. 기본 `insSort={key:'forecast',dir:'desc'}` (insights.js:9).
- **컬럼 토글** `insToggleCol(k)` (insights.js:914): `insCols`(plan/actual/forecast/share, insights.js:10)로 표시 여부 제어. 표만 부분 재렌더.
- **소계정 펼침** `toggleInsOvAcct(name)` (insights.js:878-882): `insOvExpanded` 상태로 [+]/[−]. 계정명→상세계정 매핑 `insOvSubs(name)` (insights.js:874-877): 구매→재료비 매핑 후 `INS_SUB_ACCTS`(insights.js:61-66) 하위계정 배열 반환. 하위 값은 부모값×비율 `r`.

## 5. 프론트엔드 로직 (함수/상태 — 파일:함수 인용)

### 5.1 전역 상태 (insights.js:7-13)
- `insTab`(현재 탭), `insProject`(현재 프로젝트 인덱스), `insSort`, `insCols`, `insCurTrend`(현 Trend 데이터), `insAiInsightCache`(프로젝트별 AI 캐시), `insAiInsightLoading`(중복로드 방지).
- `insOvExpanded` (insights.js:873): 계정표 소계정 펼침 상태.

### 5.2 렌더 파이프라인
- `renderInsights()` (insights.js:300-303): `#s-insights`.innerHTML = `insightsHtml()`.
- `insightsHtml()` (insights.js:306-341): 탭 분기 → overview면 `insOverviewHtml(p)`.
- `insOverviewHtml(p)` (insights.js:498-542): KPI/Trend/AI/표 조립. **AI 자동 로드 트리거 포함**(아래 5.3).

### 5.3 AI Insight 자동 로드 (핵심)
- 진입 조건(insights.js:501-502): 캐시(`insAiInsightCache[p.id]`) 없고 로딩중 아니면 `insAiInsightLoading[p.id]=true` 설정 후 `setTimeout(loadInsOverviewAI(p), 30)`.
- `loadInsOverviewAI(p)` (insights.js:474-496):
  1. payload 구성: project/status/cause + metrics(contract/base/budget/actual/forecast/rate/diff/prog) + accounts(name/plan/actual/forecast/share).
  2. `POST /api/insight` → `d.insight`를 줄바꿈 분리, 불릿기호/번호 제거하여 items 배열화, `source=d.source`.
  3. 실패/빈결과 시 `projAI(p)` 텍스트로 폴백, source='fallback'.
  4. 캐시 저장(`insAiInsightCache[p.id]`), 로딩 플래그 해제.
  5. **여전히 같은 탭·프로젝트일 때만** DOM 직접 갱신(`ins-ai-insight-body`, `ins-ai-conf`). (비동기 반환 시점에 사용자가 이동했으면 무시)
- 표시 헬퍼 `insAiInsightItemsHtml(items)` (insights.js:470-473): items를 `ins-ai-item` 리스트로. 빈배열이면 "표시할 인사이트가 없습니다."
- 신뢰도 라벨: source==='ai' → "✦ AI 생성", 아니면 "샘플 분석"(로딩중엔 "AI 분석 중…").

### 5.4 Trend 차트 & 툴팁
- `insTrendSvg(tr, noHover)` (insights.js:758-789): 라인차트. plan(점선), actual(실선, 1~8월), forecast(점선, 8~12월), area 채움, 현재월 세로선. noHover=false면 월별 투명 hover rect 삽입.
- `insTrendShow(m, el)` (insights.js:790-805): 툴팁 표시. 계획/실적(또는 예상)/차이(억·%) + "원인 분석 →" 버튼. 위치는 wrap 기준 클램프.
- `insTrendHide()` (insights.js:806) / `insTrendClick(m)` (insights.js:807): 클릭 시 `openAiChat('main', "<프로젝트> N월 외주비 왜 늘었어?")`로 메인 챗 연계.

### 5.5 ASK AI 연계
- `insAskBudgetQ()` (insights.js:919-923): `openAiChat('q')` 후 `aiAgentMsg('q', ...)`로 현재 프로젝트 기준 예시질문(`원가 왜 올랐어?`, `외주비 상세`) 주입.

### 5.6 계정표 렌더
- `insAccountTableHtml(p)` (insights.js:883-912): rows=`projAccounts(p)` 정렬 → 헤더(정렬 클릭 th) + 본문(부모행 + open 시 소계정 detail행). 컬럼은 `insCols`로 조건부.

## 6. 백엔드/API/LLM 연동 (해당 탭 AI 기능 스키마·프롬프트·폴백)

### 6.1 엔드포인트 `POST /api/insight` (server.js:135, handler server.js:298-308)
- **요청 스키마**:
```json
{
  "project": "SKON 통합관제", "status": "관리필요", "cause": "개발 외주 인력 3명 투입기간 연장",
  "metrics": { "contract":32.0,"base":26.5,"budget":27.2,"actual":18.4,"forecast":28.1,"rate":87.8,"diff":3.2,"prog":65 },
  "accounts": [ {"name":"인건비","plan":11.5,"actual":7.8,"forecast":11.2,"share":40}, ... ]
}
```
- **응답 스키마**: `{ "insight": "<줄바꿈 구분 3문장>", "source": "ai" | "fallback", "note?": "<에러메시지>" }`.
- **검증**: `body.project` 없으면 400 (server.js:299).
- **분기**: `OPENAI_API_KEY` 없으면 즉시 `localInsight(body)` 폴백(source='fallback', server.js:301-302). 있으면 LLM 호출, 실패/빈응답 시 폴백+note.

### 6.2 프롬프트 — `buildInsightPrompt(d)` (server.js:286-297)
- 지시: "PM이 지금 주목해야 할 핵심 인사이트 3가지를 각각 한국어 한 문장. 줄바꿈으로만 구분, 불릿/번호/마크다운 금지. 숫자는 억·% 그대로."
- 본문에 프로젝트/상태/계약·원가·실행예산/실적·예상원가·원가율(계획대비 %p)/주요원인/계정별(계획·실적·예상·비중) 삽입.

### 6.3 로컬 폴백 — `localInsight(d)` (server.js:276-285)
- 3줄 생성: (1) diff≥0면 "원가율 +Δ%p 상승…원인" / 아니면 "개선", (2) 실적/진행/예상원가, (3) forecast 최대 계정을 "비중 N%로 우선 점검".

### 6.4 LLM 호출 공통 — `callLLM(prompt, cb, system)` (server.js:178-215)
- OpenAI Chat Completions. 모델=`OPENAI_MODEL || gpt-4o-mini`. 키=`process.env.OPENAI_API_KEY`(trim). temperature=0.3(system 미지정 시), max_tokens=600, timeout 20s. 시스템 기본 프롬프트="비개발자 PM이 이해하기 쉽게 간결한 한국어, 마크다운·불릿 금지".
- **보안**: 브라우저는 이 서버 경유만 하므로 API 키가 클라이언트로 노출되지 않음.

## 7. 데이터 모델

### 7.1 `INS_PROJECTS[i]` (insights.js:23-34) — 프로젝트 1건
| 필드 | 의미 |
|---|---|
| id | 불투명 프로젝트 ID(URL 노출용, 예 `pj7f3a9c`) |
| name / pm | 프로젝트명 / PM |
| contract | 계약금액(억) |
| base / budget / actual / forecast | 원가(계약) / 계획(실행예산) / 실적 / 예상원가 (억) |
| rate | 예상 원가율(%) |
| diff | 원가율 계획 대비 증감(%p) |
| status | '관리필요' | '정상' |
| cost | {인건비,외주비,구매,경비,기타} 예상원가 배분(억) |
| cause | 증감 주요 원인 텍스트 |

### 7.2 상수
- `INS_CUR=8` (현재월), `MW`(12개월 가중치), `COST_CATS`(5대 카테고리+색), `INS_SUB_ACCTS`(계정별 상세계정, insights.js:61-66).

### 7.3 캐시 구조
- `insAiInsightCache[projectId] = { items: string[], source: 'ai'|'fallback' }`.

## 8. 사용자 플로우
1. 좌측 네비 "인사이트" → `#/insights/overview` 진입, 기본 프로젝트(index 0) 표시.
2. `insOverviewHtml` 렌더 → AI Insight 영역은 "AI 분석 중…" 스피너, 30ms 뒤 `loadInsOverviewAI` 비동기 호출.
3. `/api/insight` 응답 도착 → 같은 탭/프로젝트면 인사이트 3줄 + 신뢰도 라벨 갱신. 캐시 저장.
4. 사용자가 프로젝트 캐러셀에서 다른 프로젝트 선택 → 전체 재렌더, 해당 프로젝트 캐시 없으면 다시 자동 로드(URL의 pj도 갱신).
5. Trend 차트 월 hover → 툴팁(계획/실적/차이), "원인 분석 →" 클릭 시 메인 AI 챗으로 질문 전달.
6. 계정별 표에서 헤더 클릭 정렬 / 계정 [+]로 소계정 펼침 / Excel(준비중).
7. ASK AI 버튼 → AI 챗 패널에 현재 프로젝트 컨텍스트 예시질문 노출.
8. 상단 "AI 보고서 생성" → `insGenerateReport()`(3개 탭 종합 → `/api/report-summary`).

## 10. 요구사항 후보 (bullet)
- 사용자는 프로젝트를 선택해 계약금액·실행예산·실적·예상원가·예상원가율 5개 KPI를 즉시 확인할 수 있어야 한다.
- 예상원가·예상원가율 KPI는 계획 대비 증감 방향에 따라 색상(악화=빨강/개선=파랑)과 ▲▼ 기호로 구분 표시해야 한다.
- 월별 원가 Trend는 계획(전체)·실적(현재월 이전)·예측(현재월 이후)을 한 차트에 그려야 하며, 현재월(8월) 경계를 표시해야 한다.
- Trend 각 월에 마우스를 올리면 계획/실적(예상)/차이(억·%)를 툴팁으로 보여주고, "원인 분석"으로 AI 챗에 질문을 넘길 수 있어야 한다.
- 종합현황 진입 시 AI Insight 3줄이 자동 생성되어야 하며, 생성 여부(AI 생성/샘플)를 명시해야 한다.
- AI Insight는 프로젝트 단위로 캐시하여 동일 프로젝트 재방문 시 재요청하지 않아야 한다.
- 비동기 AI 응답 도착 시 사용자가 이미 다른 탭/프로젝트로 이동했다면 화면을 덮어쓰지 않아야 한다.
- LLM 미설정/실패 시 규칙 기반 폴백 인사이트로 화면이 비지 않아야 하며 'source'로 구분되어야 한다.
- 계정별 원가 표는 계획/실적/예상원가/비중 정렬, 컬럼 표시 토글, 계정별 상세계정 [+] 펼침을 지원해야 한다.
- OpenAI 키는 서버 환경변수로만 관리하고 클라이언트에 노출되지 않아야 한다.
- URL에는 내부 인덱스가 아닌 불투명 프로젝트 ID(pj)를 사용하고 딥링크 진입을 지원해야 한다.
