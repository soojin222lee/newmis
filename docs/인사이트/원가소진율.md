# 인사이트 > 원가 소진율 (progress)
> SRS Agent 입력용. 이 탭에 집중한 심화 명세.

## 1. 개요
- **목적**: 프로젝트 전체 기간(12개월)에서 **계획율 대비 소진율(실적)**을 비교하고, 합의 Cost(=실행예산)를 실적·집행예정·잔여·손실예비비로 분해하여 원가 소진 속도와 최종 착지를 진단한다.
- **위치**: 인사이트 두 번째 탭. `insTab='progress'` (showInsights insights.js:278-283, 탭 라벨 "원가 소진율" insights.js:307).
- **핵심 질문**: "지금 속도로 쓰면 계획을 넘기나? 잔여는 얼마고 그중 절감 여지는 얼마인가?"
- **핵심 개념**: **합의 Cost**(써도 되는 합의 금액=실행예산 `budget`)를 기준으로 소진율을 계산한다(예상원가 `forecast`가 아님).

## 2. 진입 경로 & URL (#/insights/progress?pj=)
- **해시 라우트**: `#/insights/progress?pj=<프로젝트ID>` (app.js:130, insHash('progress') app.js:1247).
- **진입**: `showInsights('progress')` (insights.js:278) 또는 탭바 클릭. 딥링크 `gotoInsights(pj,'progress')` (insights.js:285).

## 4. 비즈니스 로직 & 규칙 (지표 수식·차트 데이터·계산)

### 4.1 합의 Cost 분해 — `projMoney(p, i)` (insights.js:566-576)
- `cost = budget` (합의된 실행예산, 소진율 분모).
- `actual = p.actual` (전표 발생 실적).
- `rest = cost - actual` (미집행 잔여 풀).
- `cRatio` = 집행예정 비중(잔여 대비), 프로젝트별 배열 `[0.42,0.34,0.46,0.30,0.33][i]` (없으면 0.35).
- `committed = rest * cRatio` (구매완료·전표 미집행).
- `remaining = rest - committed` (잔여).
- `reserve = remaining * 0.4` (손실예비비 = 잔여 중 언더런 잠재).
- `remainFree = remaining - reserve` (순수 가용 잔여).
- **관계식**: `cost = actual + committed + remainFree + reserve`, 그리고 `remaining = remainFree + reserve`.

### 4.2 전체 기간 누적 진척 — `projProgress(p)` (insights.js:579-594)
- 월별 가중치 `MW` 누적합 `cum[]`, `total=cum[11]`.
- `planPct[i] = cum[i]/total*100` (누적 계획율, 12개월).
- `idxNow = INS_CUR-1` (0-based 현재월=7), `cumNow=cum[7]`.
- `actualNow = actual/cost*100` (현재 누적 소진율).
- `actualPct[i]` (0..idxNow) = `cum[i]/cumNow*actualNow` (현재월까지 실적 곡선을 소진율에 맞춰 스케일).
- `fcEnd = forecast/cost*100` (예상 최종 소진율).
- `fcPct[i]` (idxNow..11) = `actualNow + f*(fcEnd-actualNow)`, `f=(cum[i]-cumNow)/(total-cumNow)` (잔여 구간 선형보간, 예측선).
- 반환: `{planPct, actualPct, fcPct, planNow=planPct[idxNow], actualNow, fcEnd, idxNow}`.

### 4.3 KPI 4종 수식 & 툴팁 (insights.js:634-639)
| KPI | 값 | 수식(툴팁) | 색상 규칙 |
|---|---|---|---|
| 계획율 | `g.planNow`% | 누적 계획금액 ÷ 총 계획 × 100 (현재 8/12개월 시점) | 기본 |
| 소진율(실적) | `g.actualNow`% | 누적 실적(전표) ÷ 합의 Cost × 100 (실적÷Cost) | act 강조 |
| 진척 편차 | `dev=actualNow-planNow`%p | 소진율 − 계획율. +=조기소진(주의), −=계획 내 | dev≥0 up(빨강)/<0 down |
| 예상 최종 | `g.fcEnd`% | 예상원가 ÷ 합의 Cost × 100. 100% 초과=오버런 | fcEnd>100 up/else down |
- 툴팁 헬퍼 `tip(t)` (insights.js:605): ⓘ 아이콘 + hover 말풍선, `<br>`/`<b>` 제거한 title 병행.
- 기간 경과율 `elapsed = round(INS_CUR/TM*100)` (insights.js:604).

### 4.4 소진율 S커브 데이터 — `insProgressSvg(p, g)` (insights.js:663-681)
- 12포인트 라인 3종: 계획율(회색 `#9aa6b6` 실선), 예상(주황 `#f5a623` 점선, idxNow부터), 소진율(진회색 `#1f2937` 굵은선, 0~idxNow), 현재월 세로선 + 현재점 마커.
- Y축 그리드 0/25/50/75/100.

### 4.5 합의 Cost 4분할 — `insMoneyBreakdown(p, m)` (insights.js:683-705)
- 4세그먼트: 실적(`#1f2937`) / 집행예정(`#f5a623`) / 잔여(가용)=`remainFree`(`#cdd5df`) / 손실예비비=`reserve`(`#22b07d`).
- 각 세그 폭 = `v/cost*100%`. 상단 총 Cost 표기 + 가로 스택바 + 집행/잔여 bracket(집행=actual+committed, 잔여=remaining) + 행 리스트(라벨/설명/금액/%) + footer(손실예비비 언더런 안내).

### 4.6 계정별 가로막대 — `insGroupedBarSvg(p)` (insights.js:720-751)
- **4대계정**: 인건비/외주비/재료비(=`cost.구매` 매핑)/경비. **기타 제외**.
- 계정별 비중 `sh = cost[key]/fcSum`으로 base/plan/actual 안분.
- 각 계정 행에 3개 가로막대: 원가(`#b7c0cc`)/계획(`#2f6bed`)/실적(`#17161f`), 값 라벨 우측 표기. X축=금액(억) 그리드 0/½/max.

## 6. 백엔드/API/LLM 연동 (해당 탭 AI 기능 스키마·프롬프트·폴백)

### 6.1 엔드포인트 `POST /api/progress-summary` (server.js:131, handler server.js:335-345)
- **요청 스키마**(insights.js:152-156):
```json
{
  "project":"SKON 통합관제",
  "period": { "total":12, "current":8 },
  "planRate":67, "actualRate":68, "dev":1, "fcEnd":103,
  "cost":27.2, "actual":18.4, "committed":3.7, "remaining":5.1, "reserve":2.0,
  "accounts":[ {"name":"인건비","base":11.2,"plan":11.5,"actual":7.8}, ... ]
}
```
- **응답**: `{ "summary":"<한국어 4~5문장>", "source":"ai"|"fallback", "note?":"..." }`.
- **검증**: `body.project` 없으면 400 (server.js:336).
- **분기**: 키 없으면 `localProgressSummary` 폴백, 있으면 LLM(실패 시 폴백+note).

### 6.2 프롬프트 — `buildProgressPrompt(d)` (server.js:323-334)
- 지시: "원가 소진율 분석을 비개발자 PM이 이해하기 쉽게 4~5문장. 진행 속도(계획율 vs 소진율)+편차 해석 → 합의 Cost 분해 → 예상 최종 착지+다음 행동 제언 순서. 마크다운·불릿 금지."
- 본문: 프로젝트/기간(N/M개월)/계획율·소진율·편차·예상최종/합의 Cost 분해식(실적+집행예정+잔여(손실예비비))/계정별(원가·계획·실적).
- 주의: 프롬프트는 `d.period.total/current`를 사용(insights.js payload는 `period` 객체 전달). 폴백도 동일.

### 6.3 로컬 폴백 — `localProgressSummary(d)` (server.js:311-322)
- 계획율/소진율 서술 → 편차 해석: `dev>2` 조기소진 주의 / `dev<-2` 계획 내 / 그 외 정상.
- 합의 Cost·실적·집행예정·잔여·손실예비비 서술.
- `fcEnd>100`이면 "Cost 초과 전망, 실행예산 재검토 필요" / 아니면 "Cost 범위 내 착지 예상".

### 6.4 LLM 호출 공통 — `callLLM` (server.js:178-215)
- 종합현황 문서 6.4와 동일(gpt-4o-mini, 키=env, 20s timeout, 키 미노출).

## 10. 요구사항 후보 (bullet)
- 소진율은 실행예산(합의 Cost)을 분모로 계산해야 하며, 예상원가가 아닌 계획 기준임을 명확히 해야 한다.
- 전체 기간 대비 경과 개월/경과율을 기간 스트립으로 표시해야 한다.
- KPI 4종(계획율/소진율/진척 편차/예상 최종)을 제공하고 각 지표에 수식 툴팁을 붙여야 한다.
- 진척 편차는 부호(+조기소진/−계획내)에 따라 색상으로 경고를 구분해야 한다.
- 예상 최종 소진율이 100%를 초과하면 오버런으로 강조하고 실행예산 재검토를 유도해야 한다.
- 소진율 S커브는 계획율(전체)·소진율(현재월까지 실적)·예측(잔여 구간)을 한 차트에 현재월 경계와 함께 표시해야 한다.
- 합의 Cost는 실적·집행예정·잔여(가용)·손실예비비 4구성으로 분해하고 각 금액과 비중을 보여야 하며, 불변식(합=Cost)을 만족해야 한다.
- 손실예비비는 잔여의 40%로 산정하고 언더런(절감) 잠재 금액임을 안내해야 한다.
- 계정별 원가·계획·실적 비교는 4대계정(인건비/외주비/재료비/경비) 기준으로 제공하고 '구매'를 재료비로 매핑, 기타는 제외해야 한다.
- AI 분석 버튼은 현재 소진 데이터를 근거로 4~5문장 진단을 생성하고, LLM 실패/미설정 시 규칙 기반 폴백을 제공해야 한다.
- AI 분석 모달은 생성 출처(AI/샘플)를 표시해야 한다.
