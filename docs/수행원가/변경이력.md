# 수행원가 > 변경 이력 (history)
> SRS Agent 입력용. 코드 근거(파일:라인) 기반. 경로 접두는 `C:\Workspace\budget\public\js\`, 이하 파일명만 표기.
> ⚠️ 렌더러는 `budget-status.js`+`budget-status-2~5.js` 5분할이며 동일 함수를 여러 번 override 한다. 본 문서는 최종 유효 버전 기준.

## 1. 개요
- **정의**: 수행원가 3개 소메뉴 중 하나. 진입 모드 `costMode='history'`(전역 기본값, `budget-status-5.js:69`)로 프로젝트 실행예산의 **버전 이력을 조회·비교** 하는 화면.
- **변경 이력 고유 진입 지점**: `openBudgetProjectScreen`에서 `costMode!=='adjust'`이면 `budgetSetupStage='history'`(이력 스테이지)로 진입한다(`budget-status-5.js:76`, 주석 `budget-cost-history.js:4`). status와 달리 요약 그리드로 넘어가지 않고 이력 스테이지에 머문다.
- **두 종류의 이력**(코드상 병존):
  1. **실행예산 버전 이력** (`budgetSetupStage==='history'` 랜딩) — V1/V2/V3 스냅샷 + 결재 상태. 버전 선택·상세 열람·신규 버전 생성.
  2. **예산 이관 변경 이력** (`budgetTransferHistory`) — 계정 간 이관 저장 시 누적되는 변경 로그(버전별 계정 변경 전/후/증감). 원가조정 이관 테이블 내 이력 탭에서 노출.

## 2. 진입 경로 & URL (딥링크)
| 항목 | 값 |
|---|---|
| costMode | `'history'` (전역 기본) |
| 목록 진입 | `showCostHistory()` → `costMode='history'; showBudget()` (`budget-cost-history.js:8`) |
| 프로젝트 진입 | `openCostHistory(k)` → `costMode='history'; openBudgetProjectScreen(k)` (`budget-cost-history.js:10`) |
| 라우트 | `#/budget-history` (`budget-cost-history.js:14`) |
| 딥링크 | `#/budget-history?pj=<프로젝트키>` |

- **URL → 화면**: `ROUTE_ACTIONS['budget-history']`가 `?pj=` 있으면 `costMode='history'` 후 `openBudgetProjectScreen(pj)`(이력 스테이지 진입), 없으면 `showCostHistory()`로 목록(`budget-cost-history.js:15~17`).
- **화면 → URL**: `SCREEN_ROUTES['s-budget']`(`app.js:56`)가 `costMode==='history'`이면 base=`budget-history`, 상세면 `?pj=<currentBudgetProj>` 부착. `updateHashForScreen`(`app.js:112`)로 반영.
- Budget Navi 등에서 버전 이력 확인 목적으로 `openCostHistory(k)` 호출(주석 `budget-cost-history.js:9`).

## 3. 화면 구성
### 3.1 실행예산 버전 이력 (랜딩)
`renderBudgetSetupOverview` 이력 스테이지(`budget-status-4.js:1650~1675`):
- 3단계 스테퍼(`1 이력 · 2 계정별 작성 · 3 결재`).
- **버전 목록(세로 탭)**: V3/V2/V1 각 pill — `label · date`, `승인 총액/총액 …원`, 상태(`작성중`/`승인요청`/`승인완료`). 선택 `selectExecBudgetVersionFinal(key)`(`:1431`).
- **선택 버전 상세 카드**(`renderBudgetVersionDetailFinal`, `:1601`): 계정별 금액(인건비·외주비·재료비·경비·A/S비) + 작성/승인 총액 + memo + 상태.
- `＋ 신규 버전 생성`(`createBudgetVersionFinal`, `:1544`), 작성중이면 `이 버전 계정별 작성 →`, 아니면 `계정 내역 보기 →`(`goBudgetSetupStage('edit')`).

### 3.2 예산 이관 변경 이력 (이관 테이블 내)
`renderAccountTransferTable` 이력 영역(`budget-status-3.js:2223~2259`):
- **버전 탭**: `budgetTransferHistory[proj]` 각 항목 `v<n> · changedBy · changedAt`. 선택 `selectBudgetHistoryVersion(version)`(`budget-status.js:1402`).
- **변경 패널**: 선택 버전의 `changes[]`를 표로 — `계정 / 변경 전(oldAdjusted) / 변경 후(newAdjusted) / 증감(diff, +초록·−빨강)`.
- 이력 없으면 `"아직 저장된 이관 변경 이력이 없습니다."`.

## 4. 비즈니스 로직 & 규칙
- **버전 선택 상태**: 실행예산 버전은 `selectedExecBudgetVersionFinal`(기본 `'v3'`, `budget-status-4.js:1344`), 이관 이력 버전은 `budgetHistorySelectedVersion`(진입 시 최신 버전으로 초기화, `budget-status.js:1181` / `budget-status-5.js` 진입부).
- **버전 비교(diff)**: `getPreviousExecBudgetVersionFinal`(`budget-status-4.js:1437`)로 직전 버전을 찾아 `renderExecBudgetVersionDiffRowsFinal`(`:1460`)이 계정별 이전/현재/증감 산출. 최초 버전이면 `"이전 버전이 없는 최초 실행예산입니다."`(`:1471`).
- **버전 총액**: `budgetVersionTotalFinal(version)` = Σ budgets(`budget-status-4.js:1596`).
- **버전 상태 값**: `작성중`/`승인요청`/`승인완료`(`execBudgetApprovalStateFinal`, `:1345~1349`). 스냅샷 적용 시 `plan` 대비 비율로 월별 재분배(`applyExecBudgetVersionSnapshotFinal`, `:1407`).
- **이관 이력 생성 규칙**: 원가조정 `saveBudgetTransfer` 저장 성공 시에만 `budgetTransferHistory`에 새 버전이 unshift 되고(version=기존+1, changedAt=현재시각, changedBy=PM), `budgetHistorySelectedVersion`이 최신으로 갱신(`budget-status.js:1385~1394`). 즉 변경 이력은 이관 저장의 부산물로 누적.
- **영속화**: 이관 이력은 `localStorage['budgetTransferState']`에 저장/복원(`persistBudgetTransferState`/`restoreBudgetTransferState`, `budget-status.js:1407/1415`). 실행예산 버전 스냅샷/결재 상태는 목업 상수(메모리) 기반.

## 5. 프론트엔드 로직 (파일:함수 인용)
- 진입/라우트: `showCostHistory`/`openCostHistory`/`ROUTE_ACTIONS['budget-history']`(`budget-cost-history.js:8,10,14`).
- 공통 진입: `openBudgetProjectScreen`(`budget-status-5.js:71`) — `costMode!=='adjust'` → `budgetSetupStage='history'`(`:76`), 이관 선택 버전 초기화.
- 실행예산 버전 이력: `renderBudgetSetupOverview` history 분기(`budget-status-4.js:1650`), `getExecBudgetVersionSnapshotsFinal`(`:1351`), `getSelectedExecBudgetVersionFinal`(`:1402`), `selectExecBudgetVersionFinal`(`:1431`), `renderBudgetVersionDetailFinal`(`:1601`), `createBudgetVersionFinal`(`:1544`).
- 버전 비교: `getPreviousExecBudgetVersionFinal`(`:1437`), `renderExecBudgetVersionDiffRowsFinal`(`:1460`), `renderExecBudgetApprovalSummaryFinal`(`:1489`).
- 이관 변경 이력: 렌더 `renderAccountTransferTable`(`budget-status-3.js:2223~2259`), 선택 `selectBudgetHistoryVersion`(`budget-status.js:1402`), 적재 `saveBudgetTransfer`(`:1338`).

## 6. 데이터 모델
- **실행예산 버전 스냅샷**(`getExecBudgetVersionSnapshotsFinal`, `budget-status-4.js:1351~1400`): 배열 `[{key:'v3',label:'V3',date,status,owner:'이봄',memo,budgets:{인건비,외주비,재료비,경비,'A/S Cost':금액}}, …]`.
- **결재 상태**(`execBudgetApprovalStateFinal`, `:1345`): `{v3|v2|v1: {status, approvalStatus, requestedAt, approver:'김도윤 팀장', comment}}`.
- **예산 이관 변경 이력**(`budgetTransferHistory[projKey]`, `budget-status.js:1279~1311`): `[{version, changedAt, changedBy, changes:[{acct, oldAdjusted, newAdjusted, diff, transfer}]}]` — 목업 초기값 v1~v3 존재.
- **선택 상태 변수**: `selectedExecBudgetVersionFinal`(버전), `budgetHistorySelectedVersion`(이관 이력 버전), `budgetSetupStage`.

## 7. 사용자 플로우
1. "변경 이력" 메뉴 → `#/budget-history` → 목록. (딥링크 `?pj=`로 바로 진입.)
2. 프로젝트 선택 → `openBudgetProjectScreen(k)` → **실행예산 이력** 스테이지 진입.
3. 좌측/세로 버전 탭(V3/V2/V1) 선택 → 우측 상세 카드에서 계정별 금액·총액·상태·memo 열람.
4. 결재 스테이지로 이동하면 직전 승인 버전 대비 계정별 증감(diff)과 총 증감을 비교 확인.
5. (원가조정에서 이관 저장 시) 이관 테이블 이력 탭에서 `v<n>` 선택 → 계정별 변경 전/후/증감 확인.
6. 작성중 버전이면 `계정별 작성 →`으로 원가조정 편집으로 이어가거나, 승인본은 읽기 전용 열람.

## 9. 요구사항 후보
- 변경 이력은 `#/budget-history?pj=<key>` 딥링크로 특정 프로젝트 이력에 바로 진입할 수 있어야 한다.
- 진입 시 실행예산 버전 이력(V1/V2/V3) 스테이지로 열려야 한다.
- 사용자는 버전을 선택해 계정별 금액·총액·상태·메모를 열람할 수 있어야 한다.
- 각 버전은 상태(작성중/승인요청/승인완료)와 작성자·일시를 표시해야 한다.
- 선택 버전은 직전 버전과 계정별/총액 증감(diff)을 비교 제공해야 한다(최초 버전 예외 처리).
- 예산 이관 저장 시 발생한 변경 내역을 버전별(계정 변경 전/후/증감)로 조회할 수 있어야 한다.
- 이관 변경 이력은 로컬 영속화되어 재진입 시 복원되어야 한다.
- 작성중 버전은 계정별 작성(원가조정)으로 이어갈 수 있고, 승인 버전은 읽기 전용으로 열람되어야 한다.
