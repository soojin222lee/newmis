## 1. 개요

- **정의**: 수행원가(실행예산) 5대 비용계정 중 두 번째 계정 `외주비`(`CATS = ['인건비','외주비','재료비','경비','A/S Cost']`, `budget-status.js:742` → `CATS[1]`). 외부 업체에 위탁하는 개발·컨설팅·출장·유지보수(MA)·이관·기타 외주성 비용을 프로젝트 단위로 편성/조정한다.
- **6개 상세계정 구조**(`BPO_OUTSOURCE_KINDS_V2`, `budget-status-2.js:271~278`): 실투입대상 외주비 / 전문직수수료·제안·기타 / 외주출장비 / 공사MA / 이관외주비 / 기타외주비. 상세계정 탭(`renderBpoOutsourcePanelFinal`, `budget-area-outsource.js:1100`)으로 하나를 골라 편집한다.
- **핵심 컨셉 — 실투입대상만 재설계됨**: `budget-area-outsource.js`의 AI GUIDE 주석(`:1~16`)대로, 실투입대상 외주비만 "**업체별 예산 1행 + PO(구매계약) N건 + PO별 월별 검수계획**" 3계층 구조로 교체됐고, PM이 직접 입력하는 값은 **월별 검수계획뿐**이다. PO의 금액·MM·견적은 구매시스템 수신값(조회 전용)이다(`:358~359`).
- **분기 편중 통제**: 업체 예산은 전체기간 1건인데 PO는 분기별로 발생하므로, 앞 분기에 예산을 과도하게 발행하면 잔여기간 예산이 부족해진다. 기간 경과율(time) 대비 예산 발행율(pace)로 warn/ok 2단계 경고를 낸다(`osv3ControlV3`, `:516~527`).
- **기준월(목업)**: `2026-06`. 이 월 이하(과거)는 실적확정으로 간주해 검수계획 수정을 잠근다(`osv3TodayMonthV3`/`osv3LockedV3`, `:501~503`, `:471~473`).

### 3.1 실투입대상 외주비 (direct) — 3계층
- **① 업체(Vendor)**: 프로젝트 전체기간 예산 1줄. 필드 `{ id, vendor, contract, budget, start, end, pos[] }`(`osv3VendorsV3`, `:360~444`).
- **② PO(구매계약)**: 분기별 N건. `{ poNo, fx, start, end, amount, mm, actual, planned, plan{}, quote{} }`(`:365~393`). PO 금액·MM·견적은 구매시스템 수신값.
- **③ 월별 검수계획(plan)**: PO 하위. `plan[YYYY-MM] = { amount, mm }`(`:367`). PM이 편집하는 유일한 입력값. 검수(대금지급) 금액과 투입 MM.
- **④ 견적(quote)**: PO 하위 조회전용. `grades[]`(등급별 MM·단가·금액) + `monthly[]`(월별 등급 MM 비중·검수제안금액)(`:368~379`).

### 3.2 전문직수수료/제안/기타 (professional)
- 견적상세 `bpoProfessionalQuoteDetailsV2`는 **역할(role) 기반**(PMO/제안전략/품질검토, `assignType` Full/Part, people, mm)(`:311~315`). 실투입(직무/등급 기반)과 데이터 스키마가 다르다.
- 실투입과 같은 공유 폼 `renderBpoContractFormV2('professional')`/`renderBpoQuoteBreakdownV2`를 쓰되 `isProfessional` 분기로 컬럼이 갈린다(`:526~529`, `:620~674`).

### 3.3 외주출장비 (travel)
- 필드: `{ requestNo, contractNo, buyer, person, detail, month, amount, air, hotel, traffic, day, etc, etcText, actualized }`(`:326~329`). 출장금액은 항공+숙박+교통+일당+기타 세부 구성.
- PO 매핑: 폼에서 계약번호 옆 ⌕ 버튼으로 PO 리스트 팝업(`renderBpoPoPopupInlineV2`, `:1192~1195`).

### 3.4 공사MA (construction)

- 필드: `{ direction, month, amount, reason, status }`(`:331~334`). `direction`은 `Receiver Project`(+금액) 또는 `Sender Project`(-금액).

## 5. 비즈니스 로직 & 규칙 (예산·PO·검수·분기 편중 통제·검증)

### 5.1 분기 편중 통제 (핵심)
`osv3ControlV3(vendor)`(`:516~527`):
- `sum = osv3VendorSumV3(vendor)` — PO들의 발행액/실적/집행예정/MM 합계(`:504~511`).
- `remain = vendor.budget - sum.issued` (잔여예산).
- `quarters = osv3QuarterListV3(start, end)` — 전체기간 분기 목록(`:488~500`).
- `elapsed` = 현재분기(`osv3QuarterOfV3(osv3TodayMonthV3())`=2026 Q2) 이하 분기 수 → `timeRatio = elapsed / quarters.length` (**기간 경과율**).
- `paceRatio = sum.issued / vendor.budget` (**예산 발행율**).
- **판정**: `level = (paceRatio - timeRatio > 0.15) ? 'warn' : 'ok'` — 발행율이 경과율보다 **15%p 초과** 앞서면 경고.
- **2단계만 존재**(초과 없음): PO 발행이 예산을 넘는 상태는 구매계약 시점에 예산 체크로 막히므로 ok/warn 2단계(`:515` 주석).
- 경고 배너(`osv3RenderAlertV3`, `:824~855`): warn이면 "분기 편중 주의" + 경과율/발행율/잔여예산 표시 + [AI 해설] 버튼(서버 `/api/ai/explain`). 2건 이상이면 한 배너로 합치고 상세는 툴팁(`osv3RenderAlertRowV3`, `:858~870`).

### 5.2 PO 수신 통제
`osv3ReceivePoV3(vendorId)`(`:622~639`) — 구매시스템 연동 목업:
- `remain <= 0` → "전체기간 예산을 모두 PO로 발행" 토스트, 추가 계약 차단(증액 후 가능).
- `restQuarters <= 0` → "기간 종료" 토스트, 신규 PO 수신 불가.
- 그 외 → 아직 PO 없는 다음 분기(`nextQuarter`)를 조회, "계약 가능 한도 = 잔여예산" 안내. **잔여예산이 계약 상한**(`:621` 주석).

### 5.3 월별 검수계획 편집 규칙
- **과거월 잠금**: `osv3LockedV3(month)`(`:471~473`) = `isPastActualMonth(month)`(없으면 `month < '2026-07'`). 실적확정 과거월은 금액/MM 수정 불가(`osv3SetPlanAmountV3`/`osv3SetPlanMmV3`가 잠금월이면 무시, `:547~558`).
- **균등분배**(`osv3ResetEvenV3`, `:561~584`): 실적확정월은 유지, 남은 금액/MM을 나머지(free)월에 균등 배분(1000원 단위, 마지막 월이 잔차 흡수). free월 없으면 토스트 후 중단.
- **견적대로 채우기**(`osv3ApplyQuoteV3`, `:587~619`): 실적확정월 유지, 남은 금액을 견적 `quote.monthly` 비중대로 배분. MM은 등급별 `mms` 합.
- **합계 검증(표시용)**: `diff = osv3PlanTotalV3(po) - po.amount`(`:876`). diff=0이면 "PO금액과 일치" ok 칩, 아니면 차액 bad 칩(`:900~905`). 저장을 막는 하드 검증은 아니고 시각 경고.

### 5.4 업체 예산 저장 검증 (`osv3SaveVendorV3`, `:740~783`)
- 필수: 업체명·업무명·전체기간(start/end) → 미입력 시 토스트 중단(`:748~751`).
- `end < start` → 종료월이 시작월보다 앞설 수 없음(`:752~755`).
- `budget <= 0` → 예산 필수(`:756~759`).
- **수정 시 추가**: `budget < issued`(이미 발행된 PO 합계) → 저장 즉시 초과되므로 차단(`:762~766`). 전체기간 밖 PO가 있으면 기간 축소 차단(`:768~772`).
- 신규면 `osv3VendorsV3.push`(id=`v-<timestamp36>`, pos:[]), 수정이면 `Object.assign`(`:773~781`).

### 5.5 삭제 규칙
`osv3DeleteVendorV3`(`:648~656`): 실적 발생(`ctrl.actual > 0`) 업체는 삭제 불가 — PO·검수계획 먼저 정리 요구(목업 토스트).

### 5.6 이관외주비 규칙
Receiver만 신규등록, Sender·집행완료는 조회 전용(`:509~511`, `:1114~1121`, `:1197~1205`).

### 5.7 공사MA 규칙
검수완료(inspected) 라인은 검수집행월 수정 불가(`:1247~1251`).

## 6. 데이터 모델 (rows/필드·파생)

### 6.1 실투입 업체 (osv3VendorsV3, `:360~444`)
```
Vendor { id, vendor, contract, budget, start('YYYY-MM-DD'), end, pos:[PO] }
PO { poNo, fx('USD 11,000'), start, end, amount, mm, actual, planned,
     plan:{ 'YYYY-MM':{ amount, mm } },

```
목업 3개 업체: 아크로디자인랩(예산 5천만, PO 2건), 펜타시스템테크놀러지(1.2억, PO 2건), 인젠트(3,800만, PO 2건).

### 6.2 파생값 (계산 함수)
| 파생값 | 함수 | 산식 |
|---|---|---|
| 업체 합계(issued/actual/planned/mm) | `osv3VendorSumV3` (`:504~511`) | Σ PO 필드 |
| 통제 지표(remain/timeRatio/paceRatio/level 등) | `osv3ControlV3` (`:516~527`) | §5.1 |
| PO 검수계획 금액합 | `osv3PlanTotalV3` (`:479~481`) | Σ plan[m].amount |
| PO 검수계획 MM합 | `osv3PlanMmTotalV3` (`:482~484`) | Σ plan[m].mm |
| 월별 계획 총합(전 업체) | `osv3MonthPlanTotalV3` (`:664~667`) | Σ PO.plan[m].amount |
| 계정 총계(budget/issued/actual/planned) | `osv3TotalsV3` (`:669~679`) | Σ 업체 |

### 6.3 예산내역 표 연동 (`getMonthlyBudgetRows` override, `:681~696`)
"실투입대상 외주비" 행만 osv3 실데이터로 대체:
- 계획 = `Σ 업체 전체기간 예산`(totals.budget)
- 실적/확정 = `Σ PO 실적`(totals.actual)
- 월별 = `Σ 월별 검수계획 금액`(= PO 발행분; 미발행 예산은 월 미배정, `:663` 주석)
- 나머지 5개 상세계정 행은 기존 비율 로직 유지.
부모 "외주비" 합계행은 6개 자식행 직접 합산(`:297~301`).

### 6.4 기타 상세계정 목업 데이터
`bpoProfessionalPlansV2`(`:322`), `bpoTravelPlansV2`(`:326`), `bpoTransferPlansV2`(`:331`), `bpoOtherPlansV2`(`:336`), `bpoMaPlansV2`(`:348`), 견적 `bpoQuoteRowsV2`(`:296`)/`bpoMaQuoteRowsV2`(`:341`), 업체마스터 `bpoVendorRowsV2`(`:290`).

## 9. 사용자 플로우

### 9.1 실투입대상 외주비 (핵심 플로우)
1. `#/budget-adjust/outsource?pj=budgetMock` 진입 → 외주비 편집기(예산내역 표 + 상세계정 탭).
2. `실투입대상 외주비` 탭(기본 선택). 헤드라인에 분기 편중 경고 + 요약 표시.
3. **[신규등록]** → 업체 예산폼(`osv3RenderVendorFormV3`): 업체명/업무명/전체기간/예산 입력 → [등록](`osv3SaveVendorV3`) → 업체 1행 추가.
4. 업체 행 **[↓ PO 수신]**(`osv3ReceivePoV3`) → 잔여예산 한도 내 다음 분기 PO 조회(목업 토스트).
5. 업체 행 ∨ 펼침 → PO 블록. PO 행 **[∨ 월별 검수 계획]** → 월별 금액/MM 편집.
6. **[▦ 견적]** → 견적 팝업 → **[이 견적대로 검수계획 채우기]**(`osv3ApplyQuoteV3`) 또는 **[균등분배로 재설정]**(`osv3ResetEvenV3`).
7. 합계 칩으로 PO금액 일치 확인. 과거 실적확정월은 잠김.
8. 분기 편중 warn 시 [AI 해설]로 원인/영향/조치 확인.

### 9.2 나머지 상세계정
- **전문직/공사MA**: 탭 선택 → [신규등록] → 견적 Y/N 선택 → 견적라인 선택/직접입력 → 검수집행월 조정 → 저장.
- **외주출장비**: [신규등록] → 계약번호 ⌕로 PO 선택 → 출장내역/집행월/금액 → 등록.
- **이관외주비**: Receiver만 [신규등록](이관월/금액/사유). Sender는 조회 전용.
- **기타외주비**: [신규등록] → 집행월/금액/설명 → 등록.

## 11. 요구사항 후보 (bullet)

- **RQ-OS-01** 외주비는 6개 상세계정(실투입/전문직/외주출장/공사MA/이관/기타)으로 분류하고 상세계정 단위로 계획을 등록·수정할 수 있어야 한다.
- **RQ-OS-02** 실투입대상 외주비는 "업체별 전체기간 예산 1건 → 분기별 PO N건 → PO별 월별 검수계획"의 3계층으로 편성되어야 한다.
- **RQ-OS-03** PO의 금액·MM·견적은 구매시스템 수신값으로 조회 전용이며, PM은 월별 검수계획(금액·MM)만 입력할 수 있어야 한다.
- **RQ-OS-04** 시스템은 기간 경과율 대비 예산 발행율이 15%p 초과 앞서면 "분기 편중" 경고를 표시해야 한다(warn/ok 2단계).
- **RQ-OS-05** PO 수신은 잔여예산(전체기간 예산 − 발행액)을 계약 상한으로 하고, 잔여예산 소진 또는 계약기간 종료 시 신규 PO 수신을 차단해야 한다.
- **RQ-OS-06** 실적이 확정된 과거월(기준월 이전)의 월별 검수계획은 수정할 수 없어야 한다.
- **RQ-OS-07** 월별 검수계획은 균등분배 재설정 및 견적 비중대로 자동 채우기를 제공하되, 실적확정월은 보존해야 한다.
- **RQ-OS-08** 월별 검수계획 합계는 PO 금액과 일치 여부를 시각적으로 표시해야 한다.
- **RQ-OS-09** 업체 예산 저장 시 필수값·기간 유효성·발행 PO 합계 미만 예산·기간 외 PO 여부를 검증해야 한다.
- **RQ-OS-10** 실적이 발생한 업체는 삭제할 수 없어야 한다.
- **RQ-OS-11** 이관외주비는 Receiver Project만 신규등록 가능하고, Sender Project(집행완료)는 조회 전용으로 처리해야 한다.
- **RQ-OS-12** 공사MA는 구매 견적라인(표준품명·단위·주기·단가)을 선택해 검수집행월을 지정하되, 검수완료 라인은 검수집행월을 수정할 수 없어야 한다.
- **RQ-OS-13** 외주출장비는 PO를 매핑하고 항공·숙박·교통·일당·기타로 구성된 출장금액과 집행예정월을 등록해야 한다.
- **RQ-OS-14** 외주비 예산내역은 6개 상세계정 합계 부모행 + 접기/펼치기 자식행으로 표시하고, 실투입 행은 업체/PO/검수계획 실데이터로 산출해야 한다.
- **RQ-OS-15** 분기 편중 경고에 대해 AI 해설(원인/영향/조치)을 요청할 수 있어야 하며, API 키는 서버에만 보관하고 브라우저로 노출하지 않아야 한다.
- **RQ-OS-16** 외주비 편집기는 `#/budget-adjust/outsource?pj=<프로젝트키>` 딥링크로 직접 진입 가능해야 한다.
- **RQ-OS-17** 검수계획 저장·확정 시 해당 월이 월별 외주비 원가 등록 대상에 반영되어야 한다.
