# 수행원가 > 원가조정 > 인건비
> SRS Agent 입력용. 이 계정에 집중한 심화 명세.
> 근거 소스: `public/js/budget-area-labor.js`, `budget-status.js`, `budget-status-4.js`, `budget-status-3.js`, `budget-area-routes.js` (인용은 `파일:라인` 형식, 목업 코드 기준·추측 배제)

---

## 1. 개요 (정의·역할·특수성)

인건비는 수행원가 5대 비용계정 중 **첫 번째 계정**(`CATS[0]`, `budget-status.js:742` = `['인건비','외주비','재료비','경비','A/S Cost']`)이다. 원가조정(costMode='adjust') 단계에서 PM이 계정별 예산내역과 상세계정 계획을 편집하는 화면의 인건비 전용 진입점이다.

인건비 계정의 특수성(다른 계정 대비):
- **상세계정 3분할**: 실투입인건비 / 이관인건비 / OT비 (`budget-area-labor.js:113-116`). 각각 계획 수립 방식·데이터 출처·연동 대상이 서로 다르다.
- **SCM I/F 종속**: 실투입인건비는 자유 입력이 아니라 **SCM에서 확정(승인)완료된 인력만** 목록에서 선택·등록해 계획화한다(`budget-status-4.js:1109`, `1181`).
- **부모합계 + 접힘 트리**: 예산내역 표에서 "인건비" 부모행 1줄만 기본 노출하고 화살표로 상세 3계정을 펼친다(`budget-area-labor.js:19`, `29-32`, `64-74`).
- **계정 시그널 알림 3종**: SCM 확정 수신 / 미계획 OT 실적 선발생 / P레벨 단가 확정 초과(`budget-area-labor.js:166-233`).

파일 로드 순서 규칙: `budget-area-labor.js`는 데코레이터 체인(이전 정의를 변수에 백업 후 재정의)을 쓰므로 **반드시 `budget-status-*.js` 전부 뒤에 로드**되어야 한다(`budget-area-labor.js:6`). 실제 활성 구현은 "가장 나중에 재정의된 것"이 이긴다(예: `renderLaborAssignmentPanel`, `syncLaborAssignmentsToBudget`는 `budget-status.js`의 초기 정의를 `budget-status-4.js`가 override).

## 2. 진입 경로 & URL (#/budget-adjust/labor?pj=)

- 슬러그 매핑: `BUDGET_AREA_SLUGS['인건비'] = 'labor'`, 역매핑 `BUDGET_AREA_BY_SLUG.labor = '인건비'` (`budget-area-routes.js:13-14`).
- 라우트 등록: `ROUTE_ACTIONS['budget-adjust/labor']` (`budget-area-routes.js:37-43`).
- 딥링크 형식: `#/budget-adjust/labor?pj=<프로젝트키>`. 쿼리 `pj` 미지정 시 기본 `'budgetMock'` (`budget-area-routes.js:40-41`).
- 진입 동작: `openCostArea('인건비', pj)` → `costMode='adjust'` 설정 → `openBudgetProjectScreen(pj)` (원가조정 단계 진입) → `openBudgetAccountEditor('인건비')` (계정 선택 + 해시 갱신) (`budget-area-routes.js:30-34`).
- 편집기 헤드(← 계정 선택 버튼, "인건비 수정" 제목/설명)는 5개 계정 공통 정책으로 제거됨. 계정 선택으로 돌아가는 경로는 **브라우저 뒤로가기(#/budget-adjust)**로만 유지된다(`budget-area-labor.js:408-409`).

## 3. 상세계정 구조 (실투입/이관/OT 각 의미)

인건비 상세계정은 3개(`renderLaborKindTabsFinal`, `budget-area-labor.js:112-127`). 상태 변수 `laborKindFinal`('direct'|'transfer'|'ot', 기본 'direct', `budget-status-4.js:1728`)로 활성 탭을 전환한다(`switchLaborKindFinal`, `budget-status-4.js:1782-1787`).

| 탭 | step | label | 부제(desc) | kind 값 |
|---|---|---|---|---|
| 1 | 01 | 실투입인건비 | SCM 확정 인력 | `direct` |
| 2 | 02 | 이관인건비 | Receiver/Sender 이관 | `transfer` |
| 3 | 03 | OT비 | 월별 금액 키인 | `ot` |

패널 디스패치: `renderLaborDetailPlanPanelFinal(data)` (`budget-status-4.js:1997-2001`)
- `transfer` → `renderLaborTransferPanelFinal()`
- `ot` → `renderLaborOtPanelFinal()`
- 그 외(direct) → `renderLaborAssignmentPanel(data)`

### 3-1. 실투입인건비 (direct)
- 의미: 프로젝트에 실제 투입되는 인력의 인건비. **SCM에서 확정완료된 인력만** 선택 등록 가능(자유 입력 불가).
- 데이터: 인력 배정 rows(`budgetLaborAssignments[proj]`, `getLaborRows`). 각 인력은 P레벨 단가 × 월별 MM로 금액 산출.
- 계획 방식: "투입가능 인력 리스트" 팝업(SCM 확정 풀)에서 인력 선택 → 등록 시 SCM 수신값(시작/종료일, 총MM)으로 월별 MM·금액 **자동 배분**(`budget-status-4.js:1013-1014`, `1181`).

### 3-2. 이관인건비 (transfer)
- 의미: 타 프로젝트와의 인건비 이관. **이관받은(+)** 금액은 우리 프로젝트 인건비 실적으로 반영, **이관보낸(−)** 금액은 우리 원가실적에서 차감(`budget-area-labor.js:239-240`, `275-276`).
- 규칙: 신규 계획 등록은 **Receiver Project만** 가능. Sender Project는 타 시스템에서 집행완료 후 이관 결과로 수신되어 **조회만** 가능(`budget-area-labor.js:277`, `budget-status-4.js:1877`).
- 순 이관금액 = 받은 − 보낸 (`getLaborTransferSummaryFinal`, `budget-area-labor.js:241-246`).

### 3-3. OT비 (ot)
- 의미: 초과근무(OT) 비용. 경비 자원계획과 동일하게 **월별 계획금액을 직접 키인**(`budget-area-labor.js:328`, `budget-status-4.js:1727`).
- 계정 정합: 공유 목업에는 701301(종업원급여-OT)·701302(월별 OT 계획) 2줄이 있으나, 인건비 화면에서는 **701301 한 줄만** 사용하도록 필터링(`budget-area-labor.js:301-305`).
- 저장 후 인건비 예산내역의 OT비 행에 반영(`budget-area-labor.js:328`).

## 5. 비즈니스 로직 & 규칙 (계획 수립·계산·검증·SCM 반영 규칙)

### 5-1. 상세계정 금액 파생 (`getMonthlyBudgetRows` override, `budget-status-4.js:2003-2019`)
인건비(`CATS[0]`)에 한해 월별 예산값을 상세 3계정으로 분해한다:
- 이관 월액 `transferMonths[idx]` = `getLaborTransferAmountForMonthFinal(mo.m)` (해당 월 이관 rows 금액 합, `budget-status-4.js:1756-1758`).
- OT 월액 `otMonths[idx]` = `getLaborOtAmountForMonthFinal(mo.m)` (`budget-status-4.js:1768-1772`).
- **실투입 월액 = max(월 예산값 − 이관 − OT, 0)** (`budget-status-4.js:2009`). 즉 실투입은 잔여 공제분이다.
- 실적 배분: `totalActual`(=calcActual+calcQuasi)에서 이관 실적·OT 실적을 빼고 남은 것을 실투입 실적으로(`budget-status-4.js:2016`).
- 이관 실적 `transferActual` = actualized 건 합(`getLaborTransferActualTotalFinal`, `budget-status-4.js:1764-1766`).
- OT 실적 `otActual` = 각 row.actual 합(`getLaborOtActualTotalFinal`, `budget-status-4.js:1778-1780`).

### 5-2. 실투입 인력 → 예산 반영 규칙 (`syncLaborAssignmentsToBudget`, 활성판 `budget-status-4.js:1062-1090`)
- 대상: `getLaborRows(proj)` 중 **`laborStatusClass(status) === 'done'`인 인력만**(SCM 확정완료/승인완료). 다른 상태는 예산에 반영 안 됨(`budget-status-4.js:1066`).
- 각 plan 월에 대해: 인력별 `mm = row.monthly[month.m]`, `rowAmount = round(mm × unitPrice)`을 합산.
- 결과를 **`month[laborCat].q`(투입확정 금액)**에 기록하고, `details`에 `type:'투입확정'`, `source:'laborAssignment'` 항목으로 추가(`budget-status-4.js:1077`, `1087-1088`). 기존 laborAssignment 소스 details는 매번 재계산 전 제거(`budget-status-4.js:1068`).
- 상태 분류(`laborStatusClass` override, `budget-status-4.js:1046-1052`): '확정완료'/'승인완료' 포함 → done, '대기' → wait, '저장' → saved, 그 외 → draft.

### 5-3. 월별 MM 자동 배분 (`buildScmLaborMonthlyMmFinal`, `budget-status-4.js:970-982`)
- 투입기간(월 리스트)을 `monthRangeByDate`로 산출, 총 MM을 균등 분할(`base = floor(total/months × 100)/100`), 마지막 달에 잔차(`total − used`) 몰아넣기(`budget-status-4.js:974-979`).

### 5-4. 계획 저장 검증 (`saveSimpleAccountPlan`, `budget-status-3.js:1683-1708`)
- plan 월별 입력값(`next`)이 해당 월 **투입확정(q)보다 작으면 저장 거부**: `"<월> 인건비 계획은 투입확정 <금액>원보다 작을 수 없습니다."` (`budget-status-3.js:1695-1697`). 동일 규칙이 다른 저장 경로에도 존재(`budget-status-3.js:2784`).
- 변경분 없으면 "변경된 계획 금액이 없습니다" 토스트(`budget-status-3.js:1708-1709`).

### 5-5. 이관 저장 규칙 (`saveLaborTransferFinal`, `budget-status-4.js:1842-1869`)
- Sender/actualized/집행완료 건은 수정 불가(`budget-status-4.js:1845-1848`).
- 금액 미입력 시 거부(`budget-status-4.js:1850-1853`). 저장 시 항상 `transferType:'Receiver Project'`, `amount: Math.abs(amount)`(양수화), `actualized:false`로 정규화(`budget-status-4.js:1856-1862`).

### 5-6. OT 저장 (`saveLaborOtPlanFinal`, `budget-status-4.js:1940-1949`)
- `EXPENSE_PLAN_MONTHS` 각 월 입력값을 `parseBudgetAmount`로 파싱해 `row.monthly`에 반영 후 토스트.

## 6. 데이터 모델 (rows/필드·파생)

### 6-1. 인력 후보 풀 `laborCandidatePool` (`budget-status.js:1250-1256`)
필드: `id, name, org, role, pLevel, unitPrice`. (레거시 검색 화면용 인력 마스터.)

### 6-2. SCM 확정 풀 `laborScmConfirmedPoolFinal` (`budget-status-4.js:962-968`)
SCM I/F로 수신된 확정완료 인력. 필드: `id, scmNo, name, pLevel, role, org, startDate, endDate, totalMm, unitPrice`.

### 6-3. 등록 인력 배정 `budgetLaborAssignments[proj]` (`budget-status.js:1257-1278`, 접근자 `getLaborRows` `budget-status.js:1497-1500`)
행 필드: `id, personId, scmNo, name, org, role, pLevel, unitPrice, startDate, endDate, workType, totalMm, amount, status, requestedAt, approvedAt, scmDocNo, monthly{월:MM}`.
- SCM 등록 경로로 생성된 행: `workType:'SCM 확정'`, `status:'SCM 확정완료'`, `requestedAt:'SCM 확정 데이터 수신'`, `scmDocNo=scmNo` (`budget-status-4.js:1015-1034`).
- 상태값 예: 'SCM 승인완료', 'MM 저장완료', 'MM 입력중'(레거시 데이터, `budget-status.js:1262`, `1268`, `1274`), 'SCM 확정완료'(신규 등록).
- 파생: `amount = round(totalMm × unitPrice)`, 월별 반영액 = `round(monthly[월] × unitPrice)`.

### 6-4. 이관 rows `laborTransferRowsByProjectFinal[proj]` (`budget-status-4.js:1735-1744`)
필드: `id, transferType('Receiver Project'|'Sender Project'), expectedMonth, amount(Receiver +, Sender −), description, status('계획'|'집행완료'), actualized(bool)`.

### 6-5. OT rows `laborOtRowsByProjectFinal[proj]` (`budget-status-4.js:1746-1754`)
필드: `id, accountCode('701301'|'701302'), accountName, carried, actual, monthly[10]`. 인건비 화면은 701302 필터 제외(`budget-area-labor.js:302-305`).

### 6-6. 상수

## 8. 외부 연동 (SCM I/F 등)

SCM(Supply Chain Management, 인력 공급/투입 관리) 연동이 인건비의 핵심 외부 인터페이스다.

- **수신(Inbound)**: SCM에서 투입계획이 확정(승인)된 인력이 I/F로 수신되어 `laborScmConfirmedPoolFinal`(확정완료 풀, `budget-status-4.js:962`) 및 알림용 `laborSignalsFinal.scmInbox`(`budget-area-labor.js:140-143`)에 적재된다. 팝업 안내문 "SCM에서 확정완료된 인력만 조회됩니다"(`budget-status-4.js:1109`).
- **등록(예산화)**: 수신만으로는 예산 미반영. 사용자가 "확정 인력 등록"으로 선택·등록해야 인건비 계획 rows에 편입(`budget-area-labor.js:186` "등록해야 인건비로 예산화됩니다", `budget-status-4.js:1000-1044`).
- **예산 반영(투입확정 q)**: 등록된 SCM 확정완료 인력만 `syncLaborAssignmentsToBudget`에서 `month[laborCat].q`(투입확정)로 집계(`budget-status-4.js:1062-1090`). 이 값은 계획 하한선으로 작동(§5-4).
- **중복 방지**: `scmNo` 기준 이미 등록된 건은 재등록 차단(`budget-status-4.js:1007-1012`, `1101`).

SCM 관련 3대 계정 시그널(`renderLaborAlertsFinal`, `budget-area-labor.js:166-233`):
1. **Case3 (info) SCM 인력 확정 수신**: `scmInbox`에 미등록 확정 인력 존재 → [확정 인력 등록] 유도(`budget-area-labor.js:172-190`).
2. **Case1 (warn) OT비 실적 선발생**: 계획 없이 OT 정산 실적이 먼저 발생(`otUnplanned`, `budget-area-labor.js:135`, `193-209`) → [OT비 계획 열기]로 보정 유도. **미승인/계획없는 OT 실적 선발생 케이스** 처리 지점.
3. **Case2 (danger) P레벨 단가 확정**: P레벨 단가는 매년 5월경 확정 → 인력·MM 변동이 없어도 계획(전년 단가 기준) 대비 예산 초과 가능(`pGradeRate`, `budget-area-labor.js:137-138`, `211-230`).

> 목업 주석 명시: 위 시그널 데이터는 "실제로는 OT 정산 실적, P레벨 단가 마스터, SCM I/F 수신함에서 옵니다"(`budget-area-labor.js:133`).

## 9. 사용자 플로우 (계획 수립/조정 시나리오)

### 9-1. 실투입인건비 계획 수립 (SCM 확정 인력 등록)
1. `#/budget-adjust/labor?pj=budgetMock` 진입 → 인건비 편집기.
2. 알림 "SCM 인력 확정 수신" 확인 → [확정 인력 등록] 클릭 → `openLaborScmCandidatePopupFinal`.
3. "투입가능 인력 리스트" 팝업에서 인력 radio 선택 → [등록].
4. `registerSelectedScmLaborFinal`: 월별 MM 자동 배분·금액 산출 → rows에 unshift → `persistBudgetLaborState` → `syncLaborAssignmentsToBudget` → 토스트 "SCM 확정완료 인력이 인건비 계획에 등록되었습니다."(`budget-status-4.js:1035-1043`).
5. 예산내역의 "인건비" 부모행/실투입 자식행, 월별 투입확정(q) 갱신.

### 9-2. 이관인건비 계획 등록 (Receiver)
1. 상세 탭 [이관인건비] 선택 → `switchLaborKindFinal('transfer')`.
2. [신규등록] → Receiver Project 폼(이관예정월·금액·사유) 입력 → [등록].
3. `saveLaborTransferFinal`: 금액 양수화·Receiver로 정규화 후 rows에 추가 → 요약(받은/보낸/순) 갱신.
4. Sender Project 건은 집행완료 후 조회 전용으로 수신(수정 불가).

### 9-3. OT비 계획 보정 (미계획 실적 대응)
1. 알림 "OT비 실적 발생"(계획 없이 실적 선발생) 확인 → [OT비 계획 열기] → `laborGoKindFinal('ot')`.
2. OT 월별 그리드에 계획금액 키인 → [계획 저장] → `saveLaborOtPlanFinal`.
3. OT비 행/월별 반영.

### 9-4. 계획 조정 & 검증
- 계획 금액을 투입확정(q)보다 낮추려 하면 저장 거부(§5-4).

## 11. 요구사항 후보 (기능 요구사항 bullet — SRS 힌트)

- FR-LAB-01 인건비 계정 편집기는 `#/budget-adjust/labor?pj=<프로젝트키>` 딥링크로 진입할 수 있어야 한다(pj 미지정 시 기본 프로젝트).
- FR-LAB-02 예산내역 표는 "인건비" 부모합계행 1줄을 기본 노출하고, 토글로 실투입/이관/OT 3개 상세계정 행을 펼치고 접을 수 있어야 한다.
- FR-LAB-03 부모행 계획/실적/잔여/월별 값은 상세 3계정의 합계여야 한다.
- FR-LAB-04 상세계정은 실투입인건비·이관인건비·OT비 3탭으로 구분되고, 탭 선택에 따라 전용 패널을 표시해야 한다.
- FR-LAB-05 실투입인건비 계획은 SCM에서 확정완료된 인력만 선택·등록할 수 있어야 한다(자유 입력 불가).
- FR-LAB-06 SCM 확정 인력 등록 시 시작/종료일·총MM 수신값으로 월별 MM과 금액을 자동 배분해야 한다.
- FR-LAB-07 동일 SCM 문서번호(scmNo) 인력은 중복 등록을 차단해야 한다.
- FR-LAB-08 SCM 확정완료(done) 상태 인력만 월별 예산의 투입확정(q) 금액으로 반영해야 한다.
- FR-LAB-09 인건비 계획 금액은 해당 월 투입확정 금액보다 작게 저장할 수 없어야 한다(저장 거부 + 안내).
- FR-LAB-10 이관인건비 신규 계획은 Receiver Project만 등록 가능하고, 금액은 양수로 정규화되어야 한다.
- FR-LAB-11 Sender Project/집행완료/actualized 이관 건은 조회 전용이며 수정할 수 없어야 한다.
- FR-LAB-12 이관인건비 요약은 건수·이관받은(+)·이관보낸(−)·순 이관금액을 구분 표시하고, 순 이관금액을 예산내역 이관인건비 행에 반영해야 한다.
- FR-LAB-13 OT비는 월별 계획금액을 직접 키인해 저장하고, 인건비 예산내역 OT비 행에 반영해야 한다(계정 701301 단일 사용).
- FR-LAB-14 SCM I/F로 확정 수신된 미등록 인력이 있을 때 알림과 [확정 인력 등록] 진입을 제공해야 한다.
- FR-LAB-15 계획 없이 OT 정산 실적이 선발생한 경우 경고 알림과 OT비 계획 보정 진입을 제공해야 한다.
- FR-LAB-16 P레벨 단가 확정으로 인한 예산 초과 가능성을 위험 알림으로 안내해야 한다(인력·MM 변동 없어도 초과 가능).
- FR-LAB-17 등록된 인력 배정 상태는 localStorage에 영속화하고 재진입 시 복원해야 한다.
- FR-LAB-18 각 알림에 대해 AI 해설(요약·근거 facts)을 요청·표시할 수 있어야 한다.
