# 수행원가 > 원가조정 > 경비
> SRS Agent 입력용. 심화 명세. (통 단위 예산·ERP 한도·연단위 입력)

---

## 1. 개요 (경비 계정 특수성)

경비는 수행원가 5개 계정(`CATS = ['인건비','외주비','재료비','경비','A/S Cost']`, `budget-status.js:742`) 중 **`CATS[3]` 경비** 계정 전용 화면이다. 원가조정(예산통) 편집기의 계정 중에서 **규칙이 가장 복잡한 계정**으로, 다른 계정과 구분되는 3가지 특수성을 가진다.

1. **예산통(pool) 단위 관리** — 예산은 소계정 단위가 아니라 **중계정(예산통) 단위로 한 통**이다. 같은 중계정에 묶인 소계정들은 ERP 가용예산을 "나눠 쓰는" 것이 아니라 "함께 쓴다". 따라서 한도 검증도 소계정별이 아니라 **통 단위 합계**로 한다. (`budget-area-expense.js:90~94` 주석, `expensePoolRowsFinal`)
2. **통제/비통제 구분** — 중계정마다 `control` 속성이 `'통제'`/`'비통제'`로 지정된다. **통제 중계정**만 매출귀속부서의 **ERP 가용예산 한도**에 걸린다. 비통제 중계정은 한도 검증 대상이 아니다. (`EXPENSE_MIDDLE_ACCOUNTS_FINAL`, `validateExpenseErpAvailability`)
3. **연단위 계획 입력** — 경비 계획은 월별 입력이 의미가 없어 **연도(2026/2027) 단위로 통 입력**한다. 연 합계는 월별로 분배하지 않고 **해당 연도 첫 월 슬롯에 통합 저장**(합계 유지)한다. 연도 구간은 `EXPENSE_PLAN_MONTHS`에서 자동 도출한다. (`expensePlanYearsFinal`, `saveExpensePlan`)

> 이 파일(`budget-area-expense.js`)은 `budget-status-4.js`에 있던 경비 데이터/그리드/검증/패널/편집기 데코레이터를 이관한 것이며, `budget-status-*.js` 전부 뒤에 로드되어야 한다(데코레이터 체인 + 활성 override). `EXPENSE_PLAN_MONTHS`는 인건비 OT와 공유하는 데이터라 `budget-status.js`에 그대로 두고 참조만 한다. (`budget-area-expense.js:1~5`)

### 3.3 중계정 집계 뷰 — `getExpenseMiddleRowsFinal()` (`budget-area-expense.js:50~59`)

각 중계정에 대해 소속 소계정(`row.middleCode === mid.code && row.middleName === mid.name`)을 모아 다음을 집계한다:
- `months` — `EXPENSE_PLAN_MONTHS` 인덱스별 소계정 월값 합
- `plan` — months 총합
- `actual` — 소계정 actual 합
- `erpAvailable` — 소계정 erpAvailable 합 (= 통 가용예산)
- `controlled` — `mid.control === '통제'`

소계정도 없고 plan·actual도 0인 통은 `filter`로 제외한다(`:58`).

## 4. 화면 구성 (연단위 계획 그리드·실적 [+] 펼침·가용예산조회)

메인 패널은 `renderExpensePlanPanel(data)` (`budget-area-expense.js:298~370`). 편집기 셸 `.setup-editor.expense-single-editor` 안에 렌더된다.

### 4.1 헤더 (`:341~351`)
- 제목: `경비 자원계획 <총 N건>` (N = 소계정 수)
- 안내문: 계획은 소계정별로 **연단위**로 작성, 실적 열의 **＋** 로 지난 26년 1월~7월 월별 실적 펼침, **공동예산** 묶음은 가용잔액을 함께 씀
- 액션 버튼 3개:
  - `경비 실적조회` → `showExpenseActualLookup()`
  - `가용예산조회` (teal) → `showExpenseErpAvailabilityModal()`
  - `계획 저장` (primary) → `saveExpensePlan()`

### 4.2 그리드 열 구성 (`:354~363`)
좌→우 순서:
1. `계정` — 소계정명 + 통제/비통제 배지 + (공동예산 N건 태그)
2. `이전계획` — `row.carried`
3. **(펼침 시)** `실적 월별 열` — `EXPENSE_ACTUAL_MONTHS` 각 월 (`'26.1월` 형식)
4. `실적[+]` / `실적 합계[－]` — `row.actual`, 토글 버튼 포함
5. `연도 열` — 연도별 계획 입력칸 (예: `26년 (7월~12월)`, `27년 (1월~4월)`)
6. `계획 합계` — 소계정 계획 총합
7. `가용잔액` — 통 단위 잔액(첫 행에 rowspan 병합)

### 4.3 연단위 계획 입력 그리드 (`:326~328`)
- 연도별 `<input class="exp-year-input" id="expense-plan-{row.id}-{year}">`
- 초기값: `expenseYearPlan(row, idxs)` — 해당 연도 월 인덱스 합
- `oninput="expenseRecalcRow('{row.id}')"` — 입력 즉시 실시간 재계산

### 4.4 가용잔액 병합 셀 (`:307~316`)
- 통(pool)의 **첫 행에만** 셀을 생성하고 `rowspan="poolRows.length"`로 병합
- 통제 통: `fmt(Math.max(balance,0))`, 음수면 `.danger` 클래스, 공동(2건 이상)이면 `.shared`(옅은 배경 + 세로 가운데)
- 비통제 통: `-` 표시
- `id="expense-bal-pool-{poolIndex}"` — 재계산 시 갱신 대상

### 4.5 실적 월별 [+] 펼침
- 상태 플래그 `expenseActualExpanded` (`:229`, 기본 false)
- 토글 `toggleExpenseActualCols()` (`:254~257`) → 플래그 반전 후 `renderBudgetPage()` 재렌더
- 펼침 시 `EXPENSE_ACTUAL_MONTHS`(2026-01~07) 각 월 열 추가, 각 소계정은 `expenseMonthlyActual(row)`로 목업 배분값 표시
- 접힘/펼침에 따라 헤더 라벨 `실적` ↔ `실적 합계`, 버튼 `＋` ↔ `－`
- 패널 루트에 `.actual-expanded` 클래스 부여 (`:340`)

### 4.6 ERP 가용예산조회 모달 (`showExpenseErpAvailabilityModal`, `:181~226`)
- 통제 중계정만 대상 (`getExpenseMiddleRowsFinal().filter(row => row.controlled)`)
- 표 열: 소계정 / 이전예산(A) / 현재계획(B) / 통제여부 / ERP 가용예산 / 계획 합계 / 잔액
- ERP 가용예산·계획 합계·잔액은 **통(중계정) 단위**로 `rowspan` 병합 표시
- `잔액 = group.erpAvailable − group.plan`, 음수면 `.danger`
- 공동 통은 소계정명 옆에 `공동 N건` 태그
- 안내: "통제 계정은 매출귀속부서에 ERP 가용예산이 있어야 계획 수립 가능. 같은 예산을 쓰는 소계정들의 **계획 합계**가 가용예산 초과 시 저장 불가."

## 5. 비즈니스 로직 & 규칙

### 5.1 ERP 가용예산 한도 (통 단위 검증) — `validateExpenseErpAvailability` (`:133~150`)

**규칙: 통제 중계정은 매출귀속부서 ERP 가용예산 내에서만 계획 가능하며, 통(중계정)에 묶인 소계정 계획 합계가 통 한도를 초과하면 저장 불가.**

검증 로직(정확히):
```
checked = []
for row in rows:
    if !row.controlled or row.middleCode in checked: continue   # 비통제·중복 통 skip
    checked.push(row.middleCode)                                 # 통 1회만 검증
    available = expensePoolAvailableFinal(row)   # 통 소계정 erpAvailable 합
    plan      = expensePoolPlanFinal(row)         # 통 소계정 계획 합
    if plan > available:
        return { ok:false, message:`같은 예산을 쓰는 [이름들] 계획 합계 {plan}원이 ERP 가용예산 {available}원을 초과했습니다.` }
return { ok:true }
```

핵심:
- **통 단위 합계로만 검증** — 소계정 개별 초과는 통 안에서 서로 메울 수 있으므로 오류가 아니다(`:134` 주석). 즉 한 소계정이 자기 몫을 넘겨도 같은 통 다른 소계정이 덜 쓰면 통 합계가 한도 이내이면 저장된다.
- **비통제 통은 검증 제외** (`!row.controlled continue`).
- **통당 1회만 검증** (`checked` 배열로 중복 방지) — 같은 통의 소계정을 순회하며 재검증하지 않는다.
- 초과 메시지에는 통에 속한 소계정명들을 `·`로 연결해 표기(`expensePoolRowsFinal(row).map(r => r.name).join(' · ')`).

> **⚠️ 구버전과의 차이(중요):** `budget-status-4.js:2148~2155`의 구 `validateExpenseErpAvailability`는 **소계정별 개별 검증**(`row.controlled && expensePlanTotal(row) > row.erpAvailable`)이었다. `budget-area-expense.js` 버전이 이를 override 하여 **통 단위 검증**으로 바꾼 것이 경비 계정의 최신·정본 규칙이다.

### 5.2 통(pool) 단위 계산 함수군 (`:96~124`)

| 함수 | 정의 | 의미 |
|---|---|---|
| `expensePoolRowsFinal(row, rows)` | `rows.filter(r => r.middleCode === row.middleCode)` | 같은 통 소계정 목록 |
| `expensePoolAvailableFinal(row)` | Σ 통 소계정 `erpAvailable` | 통 가용예산 |
| `expensePoolPlanFinal(row, rows, liveTotals)` | Σ 통 소계정 계획합계 (liveTotals 있으면 우선) | 통 계획 합계 |
| `expensePoolBalanceFinal(row, rows, liveTotals)` | `available − plan` | 통 잔액 |
| `expensePoolIndexFinal(row)` | 통 등장 순서 index | 잔액 셀 id 부여용 |

`liveTotals`는 `{ rowId: 화면입력합계 }` 맵으로, 저장 전 화면 입력값 기준 실시간 재계산에 쓰인다(`:107~111`).

### 5.3 연단위 계획 저장 — `saveExpensePlan` (`:159~179`)

**규칙: 연도별로 입력한 계획을 월별로 분배하지 않고, 해당 연도의 첫 월 슬롯에 통합 저장(합계 유지).**

```
years = expensePlanYearsFinal()          # [{year, idxs}] — EXPENSE_PLAN_MONTHS에서 도출
for each row:
    next = row.monthly.slice()
    for {year, idxs} in years:
        el = getElementById(`expense-plan-{row.id}-{year}`)
        amount = parseBudgetAmount(el.value)
        # 연 합계를 첫 월 슬롯(k===0)에만 넣고 나머지 월은 0
        idxs.forEach((i, k) => next[i] = (k === 0 ? amount : 0))
    row.monthly = next
validation = validateExpenseErpAvailability()   # 저장 시 통 단위 한도 재검증
if !validation.ok: showToast(message); renderBudgetPage(); return   # 저장 중단
showToast('경비 연도별 계획이 저장되었습니다...'); renderBudgetPage()
```

- 저장 시 반드시 `validateExpenseErpAvailability()`를 통과해야 하며, 실패 시 토스트 메시지 + 재렌더로 저장이 **중단**된다(`:171~176`).
- **연도 첫 월 슬롯 통합 저장**의 결과로 `row.monthly`는 연도 경계 첫 월에만 값이 남고, 그 연도 나머지 월은 0이 된다. 계획 총합은 보존된다.

### 5.4 연도 구간 자동 도출 — `expensePlanYearsFinal` / `expenseYearLabel`

- `EXPENSE_PLAN_MONTHS = ['2026-07' ... '2027-04']` (`budget-status.js:2119`, 10개월: 2026-07~12, 2027-01~04)
- `expensePlanYearsFinal()` (`:67~74`): 각 월의 앞 4자리(연도)로 그룹핑 → `[{year:'2026', idxs:[0..5]}, {year:'2027', idxs:[6..9]}]`
- `expenseYearPlan(row, idxs)` (`:77~79`): 해당 연도 월 인덱스의 `row.monthly` 합
- `expenseYearLabel(year, idxs)` (`:82~88`): 데이터에서 월 범위 자동 계산 → `"26년 (7월~12월)"`, `"27년 (1월~4월)"`

> 연도 구간·라벨이 **하드코딩이 아니라 `EXPENSE_PLAN_MONTHS`에서 자동 도출**되므로, 계획 기간이 바뀌면 그리드 연도 열이 자동 대응한다.

### 5.5 실적 월별 배분(목업) — `expenseMonthlyActual` (`:228~251`)

- `EXPENSE_ACTUAL_MONTHS = ['2026-01' ... '2026-07']` (7개월, `:232`)
- `EXPENSE_ACTUAL_WEIGHTS = [0.05,0.08,0.12,0.15,0.18,0.20,0.22]` — 후반월 가중, 합계 1.0 (`:234`)
- 각 월값 = `round(actual * weight)`, **마지막 월은 잔여 보정**(`a - acc`)으로 `row.actual`과 정확히 일치시킴 (`:241~246`)
- `actual <= 0`이면 전월 0 반환
- 실제 실적 데이터가 아닌 **목업 배분**임(표시용).

### 5.6 실시간 재계산 — `expenseRecalcRow(id)` (`:271~296`)

입력(`oninput`) 즉시:
1. `expenseLiveTotalFinal(id)` — 해당 소계정 연도별 입력칸 합 → 계획합계 셀(`expense-total-{id}`) 갱신
2. 비통제 소계정이면 여기서 종료(`if (!row.controlled) return`)
3. 통제면: 같은 통 소계정 전체의 화면 입력값을 `liveTotals`로 수집 → `expensePoolBalanceFinal`로 통 잔액 계산
4. 통 잔액 셀(`expense-bal-pool-{poolIndex}`) 텍스트·`.danger` 갱신
5. 통 소속 모든 행(`expense-tr-{id}`)에 `.expense-over` 토글 → **한 칸을 고치면 같은 통의 모든 행이 함께 갱신**(가용잔액이 공동이므로)

`expenseLiveTotalFinal(id)` (`:260~267`): 연도별 입력칸(`expense-plan-{id}-{year}`) 값을 `parseBudgetAmount`로 합산.

### 5.7 예산 이관 한도 — `getExpenseTransferLimit` (`:152~157`)

계정별 예산 이관 시 경비 이관 한도:
```
Σ (통제 소계정: erpAvailable) + Σ (비통제 소계정: 계획총합)
```
즉 통제 계정은 ERP 가용예산이, 비통제 계정은 현재 계획액이 이관 한도의 기준이 된다. 예산 이관에서 경비 조정배분 변경 시에도 동일한 ERP 가용예산 한도를 체크한다(`:368` 코멘트).

## 9. 사용자 플로우

### 9.1 정상 연단위 계획 수립
1. `#/budget-adjust/expense?pj=<프로젝트>` 진입 → 경비 자원계획 그리드 표시
2. 소계정별 연도 칸(예: `26년(7월~12월)`, `27년(1월~4월)`)에 계획액 입력
3. 입력 즉시 `expenseRecalcRow` → 계획합계·통 가용잔액 실시간 갱신 (공동예산이면 같은 통 행 모두 갱신)
4. `가용예산조회`로 통제 통별 ERP 가용예산 대비 계획/잔액 확인(선택)
5. `계획 저장` → 연 합계를 각 연도 첫 월 슬롯에 통합 저장 → 통 단위 ERP 한도 검증 통과 → "경비 연도별 계획이 저장되었습니다" 토스트

### 9.2 한도 초과 시나리오 (통 단위)
1. 소계정 계획 입력 중 같은 통 소계정 계획 합계가 통 ERP 가용예산 초과
2. 실시간: 통 잔액 셀 음수·`.danger`, 통 소속 모든 행 `.expense-over` 강조
3. `계획 저장` 클릭 → `validateExpenseErpAvailability`가 통 단위로 초과 감지
4. 토스트: `같은 예산을 쓰는 [사무용품비 · 전산소모품비] 계획 합계 X원이 ERP 가용예산 Y원을 초과했습니다.` → **저장 중단**, 재렌더
5. 사용자는 같은 통 안에서 소계정 배분을 조정(한 계정 줄이고 다른 계정 늘림). **통 합계가 한도 이내이면** 개별 소계정이 자기 몫을 넘겨도 저장 가능

### 9.3 실적 확인 플로우
1. 그리드 실적 헤더의 `＋` 클릭 → `toggleExpenseActualCols` → 26년 1~7월 월별 실적 열 펼침(목업 배분)
2. 월별 확인 후 `－`로 접기
3. 상세는 `경비 실적조회`(`showExpenseActualLookup`) 별도 조회

## 11. 요구사항 후보 (SRS Agent 입력)

- 경비 예산은 **중계정(예산통) 단위**로 관리하며, 사용자는 소계정 단위로 계획을 입력한다. 화면에는 중계정 코드·이름을 노출하지 않고 "공동예산 N건" 표시와 공유 가용잔액만 보여준다.
- 중계정은 **통제/비통제**로 구분하며, 통제 중계정만 ERP 가용예산 한도 검증 대상이다. 비통제 중계정(일반비통제성, 인건비)은 한도 미적용(`erpAvailable = null`).
- **통제 중계정의 계획 상한은 매출귀속부서 ERP 가용예산**이다. 같은 통 소계정 **계획 합계**가 통 가용예산(소계정 erpAvailable 합)을 초과하면 저장할 수 없다.
- 한도 검증은 **통 단위 합계**로 하며, 통 안에서 소계정끼리 서로 메울 수 있다(개별 소계정 초과는 통 합계가 한도 이내면 허용). 통당 1회만 검증한다.
- 경비 계획은 **연단위(연도별)**로 입력한다. 계획 기간(`EXPENSE_PLAN_MONTHS`)에서 연도 구간과 헤더 라벨을 자동 도출한다.
- 저장 시 연 합계를 월별로 분배하지 않고 **해당 연도 첫 월 슬롯에 통합 저장**하되 계획 총합은 보존한다.
- 저장은 반드시 ERP 가용예산 한도 검증을 통과해야 하며, 실패 시 초과 소계정명·금액을 안내하고 저장을 중단한다.
- 계획 입력 시 **계획 합계·통 가용잔액을 실시간 재계산**한다. 공동예산 통은 한 소계정을 고치면 같은 통의 모든 행 잔액·강조 상태를 함께 갱신한다.
- 실적 헤더의 `＋`로 **지난 26년(1~7월) 월별 실적 열**을 펼쳐볼 수 있다(현재 목업 배분, 실 ERP 월별 실적으로 대체 예정).
- `가용예산조회` 모달은 통제 중계정별 이전예산·현재계획·ERP 가용예산·계획합계·잔액을 통 단위로 병합 표시하고, 초과 통은 잔액을 위험색으로 강조한다.
- 계정별 예산 이관에서 경비 조정배분을 변경할 때도 동일한 ERP 가용예산 한도를 체크한다.
- 진입은 딥링크 `#/budget-adjust/expense?pj=<프로젝트키>`를 지원하며, `pj` 미지정 시 기본 프로젝트로 진입한다.
