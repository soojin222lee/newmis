# 수행원가 > 원가조정 (adjust)
> SRS Agent 입력용. 코드 근거(파일:라인) 기반. 경로 접두는 `C:\Workspace\budget\public\js\`, 이하 파일명만 표기.
> ⚠️ 렌더러는 `budget-status.js`+`budget-status-2~5.js` 5분할이며 동일 함수를 여러 번 override 한다. 계정별 상세 편집기는 `budget-area-*.js`(데코레이터 체인)가 최종 소유자. 본 문서는 최종 유효 버전 기준(공통 흐름 위주).

## 1. 개요
- **정의**: 수행원가 3개 소메뉴 중 하나. 진입 모드 `costMode='adjust'`로 프로젝트 실행예산을 **편집·수립·이관** 하는 화면.
- **원가조정 고유 진입 지점**: `openBudgetProjectScreen`에서 `costMode==='adjust'`이면 `budgetSetupStage='edit'`(계정별 작성 단계)로 진입한다(`budget-status-5.js:76`, 주석 `budget-cost-adjust.js:4`). status/history와 달리 요약 그리드로 넘어가지 않고 편집 스테퍼에 머문다.
- **두 축의 조정 작업**:
  1. **계정별 상세 작성** — 5대 계정 타일에서 계정 선택(`budgetSetupEditAccount`) → 계정별 편집기(`renderBudgetAccountEditor`) 진입.
  2. **예산 이관(transfer)** — 계정 간 금액 이관. **총액 불변**, 조정배분은 실집행+투입확정 이상이어야 함. 저장 시 이관 변경 이력 버전 생성.
- **결재 흐름**: 이력 → 계정별 작성 → 결재 3단계 스테퍼(`budgetSetupStage: 'history'|'edit'|'approval'`, `budget-status-4.js:1535/1559`).

## 3. 화면 구성
1. **총액 KPI 바**(`renderTotalBudgetBar`, `budget-status-3.js:2018`) — 계획예산/실집행/투입확정/투입미정 4카드(원가현황과 공통).
2. **3단계 스테퍼**(`renderBudgetFlowStepperFinal`, `budget-status-4.js:1559`): `1 이력 · 2 계정별 작성 · 3 결재`. 클릭 시 `goBudgetSetupStage(stage)`(`:1537`).
3. **② 계정별 작성**(진입 기본, `renderBudgetSetupOverview` `budget-status-4.js:1634~`):
   - 계정 타일 5개(`renderAcctTile`, `budget-status-3.js:1563`) — 인건비·외주비·재료비·경비·A/S비, 각 금액+총액대비 비중 바. 선택 시 `openBudgetAccountEditor(key)`(`:1549`)로 `budgetSetupEditAccount` 세팅.
   - 선택 계정 아래 확장 편집기(`renderBudgetAccountEditor(viewData, budgetSetupEditAccount)`) 노출.
   - 상단 액션: `임시저장`, `결재 상신 →`(`goBudgetSetupStage('approval')`).
4. **① 이력**(`budgetSetupStage==='history'`, `budget-status-4.js:1650~`): 실행예산 버전 목록(V1/V2/V3) + 선택 버전 상세 + `＋ 신규 버전 생성`(`createBudgetVersionFinal`, `:1544`). → 상세는 변경이력 문서 참조.
5. **③ 결재**(`budgetSetupStage==='approval'`, `:1679`): 결재라인(기안자 이봄 → 팀장 김도윤) + 버전 diff 써머리(`renderExecBudgetApprovalSummaryFinal`, `:1489`) + `결재요청`.
6. **예산 집행 현황(이관) 테이블**(`renderAccountTransferTable`, 최종 유효본 `budget-status-3.js:2160`) — `budgetDetailStep==='overview'`에서 렌더. 계정별 초기배분/이관/조정배분/실집행/투입확정/투입미정 + `예산 이관 수정` 버튼.

## 4. 비즈니스 로직 & 규칙
### 4.1 예산 이관 (transfer) — 핵심
- **편집 토글**: `startBudgetTransferEdit()`/`cancelBudgetTransferEdit()`(`budget-status.js:1328/1333`)가 `budgetTransferEditMode` 전환. 편집 모드에서 조정배분 셀이 입력 필드(`actr-adjust-<idx>`)로 바뀜(`budget-status-3.js:2177~2179`).
- **저장 검증**(`saveBudgetTransfer`, `budget-status.js:1338~1400`):
  1. **총액 불변**: `Σ nextAdjusted === Σ plan(총액)` 아니면 거부 — `"조정배분 합계는 총액 …원과 같아야 합니다."`(`:1354~1357`).
  2. **하한(한도) 검증**: 각 계정 `nextAdjusted ≥ actual + quasi`(실집행+투입확정) 아니면 거부 — `"… 조정배분은 실집행+투입확정 금액보다 작게 설정할 수 없습니다."`(`:1359~1363`).
  3. 변경 없으면 `"변경된 예산 이관 내역이 없습니다."`(`:1377~1380`).
- **이관 반영**: `data.transfer[acct] = newAdjusted − plan[acct]`(`:1373,1383`). 조정배분 = 초기배분(plan) + transfer(`getBudgetAdjusted`, `budget-status.js:1319`).
- **버전 이력 적재**: 저장 시 `budgetTransferHistory[proj]`에 새 버전 unshift(version = 기존+1, changedAt=현재시각, changedBy=`getBudgetProjectPm`, changes[]=계정별 old/new/diff/transfer)(`:1385~1394`). `budgetHistorySelectedVersion` 최신으로 갱신.
- **영속화**: `persistBudgetTransferState()`가 `localStorage['budgetTransferState']`에 transfers+history 저장(`:1407`), 복원 `restoreBudgetTransferState`(`:1415`).
- **총액 변경 불가 안내**: 이 화면은 총액 내 이관만 가능. 총 Cost 변경은 AI PMO Cost 재산정으로 안내(`showBudgetCostGuide`, 버튼 `budget-status-3.js:2275`).

### 4.2 계정별 작성 / 버전
- 계정 선택은 `budgetSetupEditAccount`로 단일 관리, 편집기는 계정별 `renderBudgetAccountEditor`(`budget-area-labor/outsource/material/expense/as.js`가 override로 최종 소유). 상세 로직은 계정별 별도 문서 소관.
- 버전 스냅샷은 조정 없이 `plan` 대비 비율로 월별 재분배(`applyExecBudgetVersionSnapshotFinal`, `budget-status-4.js:1407`). 신규 버전 생성 시 작성중 버전 이어쓰기 또는 최신 승인본 복제(`createBudgetVersionFinal`, `:1544`).
- **결재 요청 규칙**: `작성중` 상태 버전만 결재요청 가능(`requestExecBudgetApprovalFinal`, `:1443~1451`), 상신 시 상태 `승인요청`/`결재중` 전환.

## 6. 데이터 모델
- **`BUDGET_SOURCE[projKey].plan{계정:금액}`** = 초기배분(Cost), **`.transfer{계정:±금액}`** = 이관액. 조정배분 = plan+transfer.
- **`BUDGET_ACCT_LABELS`**(`budget-status.js:1243`) = `['인건비','외주비','재료비','경비']` — 이관 대상 4계정(A/S는 계정 타일엔 5번째로 표시).
- **`budgetTransferHistory[projKey][]`**(`budget-status.js:1279~1311`): `{ version, changedAt, changedBy, changes:[{acct, oldAdjusted, newAdjusted, diff, transfer}] }`.
- **실행예산 버전 스냅샷**: `getExecBudgetVersionSnapshotsFinal`(`budget-status-4.js:1351`) V1/V2/V3 `{key,label,date,status,owner,memo,budgets{계정:금액}}`, 결재 상태 `execBudgetApprovalStateFinal`(`:1345`).
- **계정별 편집 데이터**: 인건비 `budgetLaborAssignments`(`budget-status.js:1257`), 감가상각 `materialDepreciationPlans`(`budget-status-3.js:3335`) 등 계정별 별도 관리.
- **상태 변수**: `budgetSetupStage`, `budgetSetupEditAccount`, `budgetTransferEditMode`, `budgetHistorySelectedVersion`, `selectedExecBudgetVersionFinal`.

## 7. 사용자 플로우
1. "원가조정" 메뉴 → `#/budget-adjust` → 목록. (딥링크 `?pj=` 또는 `/labor` 등 계정 슬러그로 바로 진입 가능.)
2. 프로젝트 선택 → `openBudgetProjectScreen(k)` → **계정별 작성(edit)** 스테퍼 진입.
3. **계정 편집**: 계정 타일 클릭 → 계정별 편집기에서 상세 계획 수정 → `임시저장`.
4. **예산 이관**: 예산 집행 현황 테이블에서 `예산 이관 수정` → 조정배분 값 입력 → `저장` → (총액 일치·하한 검증 통과 시) `budgetTransferHistory` 새 버전 적재 + `"예산 이관 내역이 저장되었습니다."` 토스트.
5. **결재**: 스테퍼 `결재` → 버전 diff 확인 → `결재요청`(작성중 버전만) → 상태 `승인요청/결재중`.
6. 총액 자체 변경 필요 시 `AI PMO Cost 재산정` 안내로 이탈.

## 9. 요구사항 후보
- 원가조정은 `#/budget-adjust`(및 계정별 `/labor·/outsource·/material·/expense·/as`, `?pj=`) 딥링크로 진입할 수 있어야 한다.
- 진입 시 계정별 작성 스테퍼(이력 → 계정별 작성 → 결재)로 열려야 한다.
- 사용자는 5대 계정 타일에서 계정을 선택해 계정별 상세 계획을 편집할 수 있어야 한다.
- PM은 계정 간 예산을 이관할 수 있으며, 저장 시 **총액은 불변**이어야 한다(조정배분 합계 = 총액).
- 각 계정의 조정배분은 실집행+투입확정 금액 미만으로 설정할 수 없어야 한다.
- 예산 이관 저장 시 변경 내역(계정별 변경 전/후/증감)을 버전으로 기록해야 한다.
- 이관 상태는 로컬 영속화되어 재진입 시 복원되어야 한다.
- 총 Cost 변경은 이 화면에서 불가하며 AI PMO Cost 재산정으로 안내해야 한다.
- 작성중 버전만 결재요청이 가능하며, 결재라인(기안자→팀장)과 버전 diff 써머리를 제공해야 한다.
