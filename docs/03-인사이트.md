# 인사이트 (Insights)
> 요구사항명세서 Agent 입력용. SI 예산관리 목업 웹앱의 인사이트 화면 명세.
> 근거 소스: `public/js/insights.js`, `public/css/insights.css`, `public/js/app.js`(라우팅), `server.js`(`/api/insight`·`/api/progress-summary`·`/api/budget-summary`·`/api/report-summary`).

## 1. 개요

- **목적**: 프로젝트 단위로 손익·원가·실적을 분석하고, AI가 원인과 다음 행동을 제안하는 분석 워크스페이스. (`insights.js` 파일 헤더 주석)
- **분석 단위**: 항상 "프로젝트 1개"를 선택한 뒤 그 프로젝트를 3개 탭으로 분석한다. 전역 상태 `insProject`(선택 프로젝트 인덱스), `insTab`(현재 탭). (`insights.js:7-8`)
- **3개 탭** (`insightsHtml()` `insights.js:307`):
  - `overview` — 종합 현황
  - `progress` — 원가 소진율
  - `version` — 버전별 예산
- **핵심 데이터 축(4가지 금액 개념)** — `INS_PROJECTS` 주석(`insights.js:22`) 기준:
  - `base` = **원가**(계약 시 수립한 원가 기준)
  - `budget` = **계획**(승인된 실행예산). 진척 탭에서는 "합의 Cost"로도 불림.
  - `actual` = **실적**(전표 발생 누적분)
  - `forecast` = **예상원가**(현재 전망 최종 원가)
- **AI 연동 4종**: 종합현황 자동 인사이트, 원가 소진율 분석, 버전 예산 요약, 3탭 종합 AI 보고서. 모두 서버(`server.js`)를 경유하며 OpenAI 키 미설정 시 로컬 폴백 문장을 반환.
- **현재 시점 상수**: `INS_CUR = 8`(현재 8월), 전체 기간 `MW.length = 12`개월. (`insights.js:15-16`)

## 2. 진입 경로 & URL (딥링크 포함)

### 진입 함수
- `showInsights(tab)` (`insights.js:278`): 탭 값을 `overview|progress|version`로 검증(그 외는 `overview`), 화면 전환(`setScreen('s-insights')`), 네비 활성화(`setNav('ngbtn-sub-insight')`), `renderInsights()` 호출.
- `gotoInsights(id, tab)` (`insights.js:285`): AI 바로가기/딥링크 진입점. `id`가 있으면 `insProjectIndexById(id)`로 프로젝트 선택 후 `showInsights(tab)`.
- `selectInsProject(i)` (`insights.js:289`): 캐러셀에서 프로젝트 변경 시 재렌더 + `updateHashForScreen('s-insights')`로 URL에도 반영.

### 딥링크 URL 규칙 (`app.js`)
- **URL 형식**: `#/insights/<탭>?pj=<불투명 프로젝트ID>` — 프로젝트 번호(인덱스) 대신 **불투명 ID**를 노출. (`app.js:63-67`, `insights.js:274` 주석)
  - `SCREEN_ROUTES['s-insights']` (`app.js:64-67`): `insRouteId()`로 현재 프로젝트 ID를 얻어 `insights/<탭>?pj=<id>`(ID 없으면 `insights/<탭>`) 생성.
- **역방향 라우팅**:
  - 정적: `ROUTE_ACTIONS['insights']` (`app.js:91`) → `gotoInsights(routeQueryParam('pj'), 'overview')`.
  - 동적: `DYNAMIC_ROUTES`의 `/^insights(?:\/([^/?]+))?$/` (`app.js:130`) → `gotoInsights(routeQueryParam('pj'), m[1])`로 탭 캡처.
  - `routeQueryParam('pj')` (`app.js:121`)로 해시의 쿼리 파라미터를 읽는다.
- **불투명 ID 헬퍼** (`insights.js:275-276`):
  - `insRouteId()` → `INS_PROJECTS[insProject].id`
  - `insProjectIndexById(id)` → 매칭 인덱스(없으면 0)
- **홈/네비 연동**: 홈 화면 AI 길안내(`NAV_ROUTES` `app.js:1217-1219`)에서 `insights-overview|progress|version` 키가 각각 `#/insights/<탭>?pj=<id>`로 이동. (`app.js:1242-1248`)

## 4. 비즈니스 로직 & 규칙 (지표 수식·Cost 분해·버전 돌려쓰기)

### 4.1 계정 배분 파생 — `projAccounts(p)` (`insights.js:37`)
- 5대 원가 카테고리(`COST_CATS`: 인건비/외주비/구매/경비/기타 `insights.js:17`)의 `p.cost` 값 합(`fcSum`) 대비 각 계정 비중 `sh`를 구한 뒤:
  - `base = p.base × sh`, `plan = p.budget × sh`, `actual = p.actual × sh`, `forecast = p.cost[key]`
  - `share = round(sh×100)`, `delta = forecast − plan`, `deltaBase = forecast − base`
- 즉 계약원가/실행예산/실적을 **예상원가 구성비로 안분**한다.

### 4.2 종합현황 KPI — `projKpis(p)` (`insights.js:253`)
- 진행률 `prog = round(actual / forecast × 100)`
- 예상원가 초과 `overCost = forecast − budget`(양수=악화 `bad`)
- 예상 원가율 = `p.rate`, 계획 대비 편차 = `p.diff`(양수=악화).

### 4.3 월별 Trend — `projTrend(p)` (`insights.js:244`)
- 월 가중치 `MW`(12개, 합=1로 정규화)로 `plan[i] = budget × w[i]`.
- `r = forecast / budget`.
- `actual[i] = plan[i] × (1 + (r−1)×1.15)` (단, `i < INS_CUR`인 과거 월만; 이후 null).
- `forecast[i] = plan[i] × r` (단, `i ≥ INS_CUR−1`; 이전 월 null).

### 4.4 원가 소진율 지표 — `projProgress(p)` (`insights.js:579`)
- 누적 계획 비율 `planPct[i] = cum[i] / total × 100` (`cum`=MW 누적).
- 현재 인덱스 `idxNow = INS_CUR − 1` (=7).
- **소진율(현재)** `actualNow = actual / budget × 100`.
- **계획율(현재)** `planNow = planPct[idxNow]`.
- 실적 곡선 `actualPct[i] = cum[i]/cum[idxNow] × actualNow` (현재월까지).
- **예상 최종** `fcEnd = forecast / budget × 100`.
- 예상 잔여 곡선 `fcPct`: 현재월 이후를 `actualNow → fcEnd`로 잔여 진척비율에 따라 선형 보간.
- **KPI 수식(UI 툴팁 기준, `insights.js:635-638`)**:
  - 계획율 = 누적 계획금액 ÷ 총 계획 × 100
  - 소진율 = 누적 실적(전표) ÷ 합의 Cost × 100
  - 진척 편차 = 소진율 − 계획율 (`+`=조기 소진 주의, `−`=계획 내)
  - 예상 최종 = 예상원가 ÷ 합의 Cost × 100 (100% 초과 시 오버런)

### 4.5 합의 Cost 4분할 — `projMoney(p, i)` (`insights.js:567`)
- `cost = budget` (써도 되는 합의 금액 = 실행예산).
- `actual` = 전표 발생 실적.
- `rest = cost − actual` (미집행 잔여 풀).
- `cRatio` = 프로젝트별 집행예정 비중 `[0.42, 0.34, 0.46, 0.30, 0.33][i]`(없으면 0.35).
- `committed = rest × cRatio` (구매/PO 완료·전표 미집행).
- `remaining = rest − committed` (잔여).
- `reserve = remaining × 0.4` (손실예비비 = 잔여 중 언더런 잠재).
- `remainFree = remaining − reserve` (순수 가용 잔여).
- **분해 화면**(`insMoneyBreakdown` `insights.js:683`)의 4분할 막대: **실적(1f2937) + 집행예정(f5a623) + 잔여가용(cdd5df) + 손실예비비(22b07d)**. 브래킷은 `집행 = actual+committed`, `잔여 = remaining`.

### 4.6 버전별 예산 "돌려쓰기" — `projVersions/projBaseline` (`insights.js:68-81`)
- **총 실행예산 `B = p.budget`는 V1~V4에서 동일**(총액 불변, 계정 간 배분만 이동).
- 현재(V4) 배분 비율 `cur = {인건비:0.40, 외주비:0.35, 재료비:0.17, 경비:0.08}`.
- 이동량 `shift = [0.055, 0.036, 0.018, 0]` (V1→V4). 각 버전 `i`:
  - `인건비 = B × (0.40 + shift[i])`, `외주비 = B × (0.35 − shift[i])`, 재료비·경비는 고정.
  - → V1은 인건비 최대, V4로 갈수록 인건비→외주비로 예산이 이동.
- **기준(계약 원가) 배분** `projBaseline(p)`: `r = {인건비:0.42, 외주비:0.33, 재료비:0.17, 경비:0.08}`, 각 계정 = `p.base × r`.
- `insVerCols(p)` (`insights.js:82`): `[기준(계약원가), V1, V2, V3, V4]` 컬럼 배열.
- 단위 변환: `insVerVal`(비율=값/컬럼합×100, 금액=값), `insVerFmt`(`%`/`억`), 증감 단위 `%p`/`억` (`insights.js:87-89`).
- 하위 상세계정 금액/증감 = 부모 값 × 상세계정 비율 `r`(`INS_SUB_ACCTS`). (`insights.js:227-234`)

## 8. 사용자 플로우

1. 진입: 좌측 네비 "인사이트" 또는 홈 AI 길안내/딥링크(`#/insights/<탭>?pj=<id>`)로 진입 → 기본 탭 `overview`.
2. 프로젝트 선택: 상단 캐러셀에서 프로젝트 클릭(`selectInsProject`) → URL의 `pj` 파라미터 갱신.
3. **종합 현황**: KPI·월별 Trend 확인 → AI Insight 자동 로드(`/api/insight`) → 트렌드 월 hover→"원인 분석" 또는 "ASK AI"로 챗 연계 → 계정표 정렬/열토글/[+] 소계정 확인.
4. **원가 소진율** 탭 이동: 기간 경과·4 KPI(계획율/소진율/편차/예상최종)·소진율 곡선·Cost 4분할 확인 → `✦ AI 분석`(`/api/progress-summary`) 팝업.
5. **버전별 예산** 탭: 계정/단위 토글 → 기준 대비 V1~V4 돌려쓰기 차트·표·[+] 상세계정 확인 → `✦ AI 요약`(`/api/budget-summary`) 팝업.
6. **AI 보고서 생성**(상단 버튼): 로딩 → `/api/report-summary`(3탭 종합) → SK AX Report 팝업(요약·제언 + 실적표 + Trend/계획vs실적/Cost 분석/계정별 원가). PDF 저장·데이터 내보내기는 "준비"(토스트).
