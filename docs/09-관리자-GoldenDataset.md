# 09. 관리자 > Golden Data set 관리

> 원천 데이터: [`rawdata/screens/admin-golden.yaml`](rawdata/screens/admin-golden.yaml) · 화면 코드: `public/js/admin-golden.js`

## 왜 필요한가

예산관리 Agent는 대화("지금 CP 여유 얼마야?", "외주비 3천만원 늘려줘")와 데이터 감지로 예산 조정안을 만듭니다.
답변이 맞는지, 근거로 쓴 숫자가 맞는지를 사람이 매번 확인할 수는 없으므로 **기준이 되는 질문과 정답, 기준값을 한곳에 모아 두고**
Agent를 바꿀 때마다 다시 평가합니다.

## 화면 구성

관리자 사이트 좌측 메뉴의 **🏅 Golden Data set 관리**(환율 관리 다음)로 들어갑니다. 탭이 두 개입니다.

### ① 질문·정답 셋

| 칸 | 내용 |
|---|---|
| ID | GQ-001 형식, 등록 시 자동 발번 |
| 질문 · 기대 답변 | 사용자가 할 법한 질문과, 답에 반드시 들어가야 할 내용·수치 |
| 기대 의도 | Agent가 질문을 어떤 동작으로 읽어야 하는지 (CP 여유 조회 · 계정 증감 · 이관 · 상세계정 편성 · 전부 반영 · 제안 다시 불러오기 · 기안 · 계정 상세) |
| 근거 데이터 | 답을 계산할 때 써야 하는 데이터 |
| 최근 결과 | 통과 / 실패 / 미실행 |
| 사용 | 평가 대상 포함 여부 |

- 위쪽 요약 카드에 평가 대상 · 통과 · 실패 건수와 최근 실행 시각을 보여 줍니다.
- **[평가 실행]** 은 사용 중인 질문을 Agent에 보내 의도와 핵심 수치를 판정합니다(목업은 판정 결과만 표시).
- 기대 답변을 고치면 최근 결과가 **미실행**으로 돌아가 다시 평가하도록 합니다.

### ② 기준 데이터 셋

CP총액, 계정별 CP한도, 경비 실적 마감월, 택1 묶음처럼 **Agent 답변과 제안이 근거로 쓰는 기준값**을 출처 시스템(AI PMO · ERP · 구매 · SCM · CRM · BMS Agent)과 기준일과 함께 둡니다.
출처 시스템의 값이 바뀌면 기준값과 기준일을 갱신하고, 관련 질문을 다시 평가합니다.

## 동작 규칙

- 삭제는 행 안에서 **[삭제] → 삭제할까요? [삭제][취소]** 로 한 번 더 확인합니다.
- 지우지 않고 평가·근거에서만 빼고 싶으면 **사용 / 제외** 토글을 씁니다.
- 저장·평가 실행은 목업 스텁입니다(화면 상태만 바뀜).

## 구현 메모

`admin.js`(수진)를 고치지 않으려고 `admin-golden.js` 가 그 뒤에 로드되어 `ADMIN_SECTIONS` 에 메뉴를 끼워 넣고
`admSectionBody` 를 데코레이터로 감쌉니다. `admin.html` 에는 script 한 줄만 추가했습니다.
