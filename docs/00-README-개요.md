# 프로젝트 예산관리 시스템 — 기능 명세 문서 세트

> **목적**: 이 문서 세트는 **요구사항명세서(SRS) 자동 생성 Agent의 입력**으로 쓰기 위한 것이다.
> 각 화면·업무별로 **비즈니스 로직 · 프론트엔드 로직 · 백엔드/API/LLM 연동 · 데이터 모델 · 사용자 플로우**를
> 실제 소스 코드 근거(파일·함수 인용)와 함께 정리했다.

---

## 1. 시스템 개요

SK 계열 SI/컨설팅 프로젝트의 **수행원가(실행예산) 관리 + AI 분석** 목업 웹 애플리케이션.
PM/팀장이 담당 프로젝트의 원가 계획·실적·변동을 관리하고, AI가 현황을 해석·조회·안내한다.

- **형태**: 바닐라 JS 정적 SPA (빌드 없음) + 순수 Node.js HTTP 서버
- **기술 스택**: HTML/CSS/JS(무프레임워크), Node.js `http`(zero-dependency), `node:sqlite`(내장), OpenAI Chat Completions
- **설계 원칙**: 외부 npm 의존성 없음(zero-dep), LLM 키는 서버 환경변수만 사용(코드/깃 미저장), LLM 미설정 시 규칙 기반 폴백
- **실행**: `OPENAI_API_KEY=... node server.js` → `http://localhost:57291`

## 3. 공통 규약 (요구사항 추출 시 참고)

- **URL 딥링크**: 해시 경로 = 메뉴 경로, 프로젝트/계정은 **끝에 파라미터**로.
  - 인사이트: `#/insights/<overview|progress|version>?pj=<불투명ID>` (보안상 프로젝트번호 대신 ID)
  - 수행원가: `#/budget-status?pj=<키>`, `#/budget-adjust/<labor|outsource|material|expense|as>?pj=<키>`, `#/budget-history?pj=<키>`
  - 화면↔URL **양방향 동기화** (내부 이동 시 해시 자동 갱신, 딥링크 접속 시 해당 화면 진입)
- **AI/LLM 기능** (모두 서버 `/api/*` 경유, 키 노출 없음):
  - 종합현황 AI Insight, 원가 소진율 AI 분석, 버전 예산 AI 요약, AI 보고서(3탭 종합), 메인 채팅 응답, 화면 네비게이터, 예산 알림 해설, 맞춤 레포트 도우미, **AI 레포트 LLM→SQL**
  - 공통 패턴: 키 있으면 실제 OpenAI(`source:"ai"`), 없으면 규칙 기반 폴백(`source:"fallback"`)
- **채팅 통합 동작**: 질문 시 **답변 + 관련 화면 자동 이동 + 우측 도킹**이 함께 이뤄진다.
- **주의(코드 열람 시)**: 팀 협업으로 `app.js`/`dashboard.js`의 일부 함수(`routeIntent(s)`, `renderPmDashboard` 등)가 **여러 번 재정의**되어 있고 **마지막 정의가 유효**하다. 캐시버스팅은 `index.html`의 `?v=`로 관리한다.

## 4. 데이터(목업) 위치

- 홈 프로젝트: `HOME_PROJECTS` (dashboard.js), 업무 피드: `HOME_FEED`
- 인사이트 프로젝트: `INS_PROJECTS` (insights.js)
- 수행원가: `EXEC_BUDGET_PROJECTS`(목록) + `BUDGET_SOURCE`(키별 원가 데이터) (budget-status.js)
- 레포트/ SQLite 시드: `PROJECT_ROWS`/`BUDGET_ROWS` (server.js), 필드 카탈로그 `customReportFields`(custom-report.js)
- 리스크: `data.json` (서버 영속)

## 5. 문서 작성 규칙 (일관성)

각 문서는 다음 섹션을 따른다: 개요 → 진입/URL → 화면 구성 → 비즈니스 로직·규칙 → 프론트엔드 로직 → 백엔드/API/LLM → 데이터 모델 → 사용자 플로우 → 관련 소스 파일.
로직 서술은 **파일·함수명을 인용**하여 추적 가능하게 한다.
