# 채팅 AI 어시스턴트 & 화면 네비게이터
> 요구사항명세서 Agent 입력용.

> 정리 원칙: 아래 내용은 모두 소스 코드(`public/js/app.js`, `server.js`, `ai-proxy.js`, `public/js/dashboard.js`, `public/index.html`) 근거로 작성했다. `app.js`는 여러 차수에 걸쳐 개발되어 같은 함수/상수(`openAiChat`, `sendAiChat`, `routeIntent`, `AGENTS` 등)가 여러 번 재정의되어 있다. **자바스크립트 함수 선언 호이스팅 특성상 "파일에서 가장 마지막에 선언된 정의"가 실제 동작하는 버전**이므로, 본 문서는 최종 정의를 기준으로 기술하고 이전 정의는 "폐기됨"으로 표기한다.

## 1. 개요

메인 채팅 AI 어시스턴트는 SI 예산관리 웹앱의 단일 대화 창(`#ai-chat-overlay`)에서 동작하며, 사용자의 자연어 질문을 **오케스트레이터(AI 어시스턴트)** 가 유형 판정 후 담당 Agent에게 배정하는 구조다.

최종 구성(`app.js` 11·12차 재정의, 라인 1774~2162 기준):

- **오케스트레이터** `ORCH` — "AI 어시스턴트", 질의 유형 판정 후 담당 Agent 표시 (`aiOrchestratorMsg`, app.js:1799)
- **4개 담당 Agent** (`AGENTS`, 최종값은 app.js:1774~1794의 `Object.assign`으로 확정)
  - `navi` **화면 길잡이** — 화면·절차 안내 (어디서/무엇을 준비해서/몇 분)
  - `q` **데이터 분석** — 숫자의 의미와 원인을 근거와 함께 설명 (What-if 포함)
  - `risk` **이상징후 감시** — MIS 데이터의 위험 신호 경고 (`cat:'budget'`)
  - `todo` **할 일 도우미** — 선행 시스템 이벤트로 생긴 조치 업무 제시 (`cat:'work'`, 자동처리·위임등급 포함). 구 `pilot` 키는 `todo`로 흡수됨 (app.js:1791).

핵심 특징:
- **다중 에이전트 동시 응답**: 하나의 질문에 여러 인텐트가 걸리면 담당 Agent가 순차적으로 각각 답한다(최대 3개, `INTENT_MAX`).
- **통합 동작**: 답변형 질문(`q`)은 답변 + 관련 화면 자동 이동(`navToRelevant`) + 우측 도킹(`dockAiChat`)이 함께 일어난다.
- **네비게이터**: 자연어를 서버 `/api/navigate`로 보내 LLM이 `NAV_ROUTES`에서 화면 키를 고르고, `navGo`가 딥링크로 이동한다.

## 4. 비즈니스 로직 & 규칙 (인텐트 라우팅·통합 동작·매핑)

### 4.1 인텐트 라우팅 — 다중 에이전트 동시 응답 (`routeIntents`, app.js:2021)
입력 텍스트에서 공백을 모두 제거(`text.replace(/\s/g,'')`)한 뒤 판정한다.

**우선순위(위에서부터, 단락 판정):**
1. **메인 복귀 (단독)** — `(메인|홈|처음|첫화면|대시보드)` AND `(가|이동|보여|복귀|돌아|줘)` → `navi` 하나만 반환, `showMain()` 호출. 다른 인텐트와 섞지 않음.
2. **화면 이동 (단독)** — 이동 동사군 `(가고싶|가줘|데려가|이동하|이동해|이동시|열어줘|화면으로|화면 보여|보여줘|바로가|네비게|navigate)` AND 화면 주제어군 `(화면|인사이트|레포트|보고서|원가|실적|계획|비교|소진|버전|예산|현황|조정|프로젝트|cost|SQL 등)` 모두 매칭 → `navi` 하나만 반환, `chatNavigate(text)` 실행(서버 `/api/navigate` 경유 실제 이동).
3. **"확인해야 할 것"류** — `(확인할것|확인사항|확인해야|확인필요|점검할|다보여|전부보여|모두보여)` → `risk`(이상징후) + `todo`(할 일) **둘 다** 추가.
4. **개별 판정기 `INTENT_RULES`(app.js:1982) 순회** — 걸리는 규칙을 모두 수집(중복 키 제거). 최대 `INTENT_MAX = 3`개까지.
5. 위에서 아무것도 안 걸렸고 일반 이동 의도어 `(찾아|어디|어떻게|화면|이동|바로가기|절차|방법|메뉴|열어|가줘|보여줘|이동해|가고싶|데려가)`가 있으면 → `navi` `chatNavigate`.
6. 그 외 전부 → `q` `askLLMAnswer(text)` (서버 LLM 경유).

**`INTENT_RULES` 개별 판정기 (app.js:1982~2018), key로 중복 제거:**
| key | agent | 트리거(정규식 요지) | 렌더 |
|-----|-------|--------------------|------|
| nav | navi | 찾아줘/어디서/바로가기/화면으로/열어줘/가줘/데려가/이동하/네비게 등 | `chatNavigate(text)` |
| risk | risk | 이상징후/이상/징후/리스크/위험/경고/급증/정합성/알림 | `chatOpenRisks()` |
| auto | todo | 자동반영/자동처리/AI가처리/알아서 | `pilotAutoHtml()` |
| trust | todo | 위임/자동조종/얼마나믿/신뢰도 | `pilotTrustHtml()` |
| todo | todo | 할일/해야할/처리할/투두/todo/오늘/브리핑 | `chatOpenTodos()` |
| whatif | q | 하면/한다면/투입하면/늘리면/줄이면/시뮬/가정/만약 | `pilotWhatIfHtml(text)` |
| outsource | q | `외주비` AND (왜/늘/증가/많/올랐) | `qOutsourceHtml()` |
| rate | q | 원가율 | `qCostRateHtml()` |
| compare | q | 계획대비 | `qComparePlanHtml()` |

- `routeIntent(text)`(단수, app.js:2074)는 하위호환용: `routeIntents`의 첫 결과만 `{agent, agents, render}`로 감싸 반환.

### 4.2 통합 동작 (`sendAiChat` 최종, app.js:2081)
1. 입력값 트림 → 빈 값이면 중단.
2. `aiUserMsg(text)` 사용자 말풍선 추가, 입력창 비움.
3. `setChatAskBar(text)` 첫 질의를 상단에 고정(최초 1회만).
4. `routeIntents(text)`로 담당 목록 산출 → `aiOrchestratorMsg`로 "이 질문은 …가 담당/함께 답합니다" 노출.
5. 각 담당 Agent가 **순차 렌더**: `560 + i*640` ms 간격으로 타이핑 표시 후 `render()`.
6. **자동 화면 이동 규칙**: 담당 목록에 `q`가 있고 `navi`가 없으면 → `navToRelevant(text)` 호출. 즉 **답변형 질문이면 답변과 동시에 관련 화면으로 이동 + 우측 도킹**한다. (navi 인텐트는 이미 자체적으로 이동하므로 중복 이동 방지)

정리:
- **질문(q)** → 답변 렌더 + `navToRelevant`(관련 화면 이동) + `dockAiChat`(우측 도킹)
- **이동의도(navi)** → `chatNavigate`(화면 이동) + `dockAiChat`(도킹)

## 6. 백엔드/API/LLM 연동 (엔드포인트·스키마·프롬프트·폴백)

공통: LLM은 OpenAI Chat Completions(`api.openai.com/v1/chat/completions`)를 서버 경유로 호출한다. 키는 **`process.env.OPENAI_API_KEY`에서만** 읽고(코드/깃 미저장), 모델은 `OPENAI_MODEL || "gpt-4o-mini"`. 키가 없으면 LLM을 부르지 않고 **로컬 규칙 기반 폴백**을 반환(`source:"fallback"`). 브라우저는 서버를 경유하므로 키가 클라이언트로 노출되지 않는다. (`callLLM`, server.js:178; 타임아웃 20초)

### 6.1 `POST /api/chat` — 메인 챗봇 답변 (server.js:595 `handleChat`)
**요청 스키마:**
```json
{
  "question": "문자열(필수, 비어있으면 400)",
  "context": {
    "project": "프로젝트명 또는 null",
    "finance": {
      "cp": 계약금액, "plan": 계획, "act": 실적, "left": 잔여,
      "rate": 예상원가율, "mgap": 당월 계획대비 실적차,
      "accounts": [{ "name","plan","act","left","pct" }]
    },
    "todos": ["확인 필요 항목 title", ...]
  }
}
```
**응답:** `{ "answer": "...", "source": "ai"|"fallback", "note"?: "에러/empty 사유" }`

**LLM 프롬프트 요지 (`buildChatPrompt`, server.js:551):** "아래는 실행예산 시스템의 현재 데이터다. 이 숫자만 근거로 답하고, 없는 수치는 추측하지 마라." + 문맥(대상 프로젝트/계약·계획·실적·잔여/예상원가율 85% 관리기준선/당월 gap/계정별/확인 필요 항목) + `질문:` (500자 절단). system은 기본 "비개발자 PM에게 간결한 한국어, 마크다운·불릿 금지".

**폴백 (`localChatAnswer`, server.js:576):** 문맥 숫자로 규칙 기반 문장 생성 — 계약/계획/실적/잔여/예상원가율, 85% 기준선 초과 시 "조기경보 대상", 여력 가장 낮은 계정, 확인 필요 항목 건수/목록. 문맥(`finance`)이 없으면 "프로젝트를 선택하면 더 구체적으로 답할 수 있어요".

### 6.2 `POST /api/navigate` — 자연어 → 화면 route 선택 (server.js:522 `handleNavigate`)
**요청 스키마:**
```json
{
  "message": "사용자 자연어(필수)",
  "routes": [{ "key": "insights-progress", "label": "...", "desc": "..." }]
}
```
(프론트는 `NAV_ROUTES`를 `{key,label,desc}`로 축약해 전달 — app.js:1286/1299)

**응답:** `{ "key": "선택된 route key", "reply": "선택 이유 1문장", "source": "ai"|"fallback" }`

**LLM 프롬프트 요지 (`buildNavPrompt`, server.js:511):** "사용자가 이동하고 싶어하는 화면을 아래 목록에서 딱 하나 고른다." + 화면 목록(`key : label — desc`) + 사용자 메시지 → **JSON 한 개만 출력** `{"key": "...", "reply": "..."}`. system은 "화면 네비게이터, 지정된 JSON으로만".
- 서버는 응답에서 코드펜스/`{...}` 추출 후 JSON 파싱. `key`가 없거나 유효 routes에 없으면 로컬 폴백.

**폴백 (`localNavigate`, server.js:494):** 정규식 기반 키 선택 — 기본 `insights-overview`, 이후 우선순위:
`버전|돌려|배분`→`insights-version`; `소진|cost|원가.*(실적|계획|비교)|비교`→`insights-progress`; `종합|현황|kpi|트렌드`+`인사이트`→`insights-overview`; `자연어|물어|질의|sql`→`ai-report`; `레포트|보고서|조회`→`custom-report`; `원가조정|조정|계정.*예산`→`budget-adjust`; `원가현황|수행원가`→`budget-status`; `수주`→`si-project`; `메인|홈`→`dashboard`. 선택 키가 유효 routes에 없으면 첫 route로 대체.

### 6.3 (참고) 기타 채팅 인접 엔드포인트 (server.js)
동일한 키·폴백 패턴 사용:
- `POST /api/budget-summary` — 예산 변동 요약 (`handleBudgetSummary`)
- `POST /api/report-summary` — 보고서 요약/제언

## 8. 사용자 플로우 (질문형/이동형 시나리오)

### 8.1 질문형 (예: "SKON 외주비 왜 늘었어?")
1. 홈 `#ai-main-query`에 입력 → `askFromHome()` → `openAiChat('main', q)`.
2. `sendAiChat()`: 사용자 말풍선 + 첫 질의 고정.
3. `routeIntents`: `outsource`(q) 규칙 매칭 → 담당 `[q]`.
4. 오케스트레이터 "이 질문은 **데이터 분석**가 담당합니다" 표시 → 타이핑 후 `qOutsourceHtml()` 렌더.
5. 담당에 `q` 있고 `navi` 없음 → **`navToRelevant('SKON 외주비 왜 늘었어?')`** 자동 호출.
6. `/api/navigate` → LLM(또는 폴백)이 `insights-progress` 등 선택 → `navGo`로 딥링크 이동 + `dockAiChat`으로 대화 우측 도킹.
   → 결과: 답변 카드 + 관련 분석 화면이 함께 뜨고 대화는 옆에 남는다.

### 8.2 이동형 (예: "버전별 예산 화면으로 가줘")
1. 입력 → `sendAiChat()`.
2. `routeIntents` 2번 조건(이동 동사 + 화면 주제어) 매칭 → `[navi]` 단독, `chatNavigate(text)`.
3. `/api/navigate` → LLM이 `insights-version` 선택(폴백 시 `버전|돌려|배분`→동일 키).
4. "**인사이트 · 버전별 예산** 화면으로 이동할게요" 길안내 카드(이유 `reply` 포함) 렌더.
5. 850ms 뒤 `navGo('insights-version')` → `#/insights/version?pj=<insId>` 이동 + `dockAiChat`.
   → `q` 인텐트가 없으므로 §8.1의 추가 `navToRelevant`는 실행되지 않음(중복 이동 방지).

### 8.3 복합 질의 (예: "이상징후랑 할 일 같이 알려줘")
1. `routeIntents`: "확인해야 할 것"류 또는 risk+todo 규칙 → `[risk, todo]`.
2. 오케스트레이터 "이 질문은 **이상징후 감시 · 할 일 도우미**가 함께 답합니다".
3. `risk`가 `chatOpenRisks()`, 이어서 `todo`가 `chatOpenTodos()`를 순차(640ms 간격) 렌더.

### 8.4 이동 의도 but 화면 특정 불가
- 일반 이동어만 있고 대상 화면 불명 → `chatNavigate`(서버 판정) 또는 로컬 `naviAskHtml`로 **되묻기**(추천 화면 버튼 제시). 엉뚱한 화면으로 강제 이동하지 않음.

### 8.5 LLM 키 미설정 시
- `/api/chat`·`/api/navigate` 모두 서버 폴백(`source:"fallback"`)으로 응답 → 프론트는 "규칙 기반 답변/길안내" 태그로 표기하되 동작은 동일하게 유지(화면이 비지 않음).
