## 1. 화면 1개 = 반드시 3가지 세트

| 산출물 | 위치 | 목적 |
|---|---|---|
| 화면 코드 | `public/js/<screen>.js` (또는 .vue) | 실제 목업 화면 |
| **rawdata YAML** | `docs/rawdata/screens/<screen>.yaml` | 지니(Jinny)가 읽는 **구조화 근거** (요소·CRUD·API·FR) |
| **화면 컨셉 md** | `docs/<번호>-<화면>.md` | 화면 목적·업무 흐름·FR 후보(산문) |

표준 예시: `docs/rawdata/screens/ai-report.yaml` (이 구조를 그대로 따르세요)

## 2. rawdata YAML 스키마 (★ CRUD 필드 추가)

```yaml
screen:
  id:            # DOM screen id (예: s-budget-status)
  name:          # 화면명
  menu_path:     # 메뉴 경로 (예: 수행원가 > 원가현황)  ← 트리 그룹화에 사용
  route:         # 해시 URL (예: "#/budget-status")     ← 화면 자동 캡처에 사용
  purpose:       # 한 줄 목적
  source_files: [] # 관련 파일 + 역할 주석

states: []       # {id, when(조건), shows[]}

elements:        # ★★ 가장 중요 — 버튼/입력/칩을 하나도 빠짐없이
  - id:          # 요소 식별자 (예: btn-save-budget)   ← 명세의 '근거요소 id'가 됨
    label:       # 화면에 보이는 이름 (예: 저장)         ← CRUD 동사 명확히!
    type:        # button / input / chip / toggle / grid
    crud:        # ★ NEW: C(등록) / R(조회) / U(수정) / D(삭제) / N(이동·기타)
    event:       # onclick / onkeydown(Enter)
    front:
      handler:   # 호출 함수(인자 포함) 예: saveBudget()  ← '핸들러 근거'가 됨
      validation:# 검증 규칙 (없으면 생략)
      state_writes: []
    backend:     # 없으면 null
      api:       # 예: /api/budget/save
      method:    # GET/POST/PUT/DELETE
      security:  # 예: SELECT 전용·권한 체크
    result:      # 결과/화면 전이

apis: []         # {path, method, handler, request, response, security[]}
data:
  state_vars: []
flows: []        # {name, steps[]}
requirements:    # ★ FR 후보 — SRS 통합의 재료
  - { id: FR-BST-01, text: "사용자는 조건으로 실행예산 목록을 조회할 수 있어야 한다" }
  - { id: FR-BST-02, text: "..." }
```

### 작성 규칙 (꼭 지켜주세요)
1. **영문 key + 한국어 value.** 로직은 `file:function`(가능하면 라인)으로 **근거 인용**.
2. **elements를 빠짐없이** — 버튼·입력·칩·토글·그리드 컬럼까지. (지니(Jinny) 명세의 최소 단위)
3. **`crud` 를 명시** — 없으면 지니(Jinny)가 텍스트로 추정합니다(부정확). 직접 적으면 정확.
4. **`label` 에 CRUD 동사** — 저장/등록/수정/삭제/조회/검색. (시각화·감지 정확도↑)
5. **`handler` 는 실제 함수명** — 코드에 없는 함수 지어내지 말 것(환각 방지).
6. **`requirements` 에 FR 후보** — `FR-<화면약자>-NN` 형식. 화면마다 5~10개.
7. **근거 없는 항목 금지** — 목업 스텁/미구현이면 그렇게 표기(예: `logic: "목업 스텁, 동작 없음"`).

### CRUD 판정 기준
| 코드 | 의미 | 예 |
|---|---|---|
| **C** | 생성/등록 | 신규 등록, 추가, 저장(신규), 발행 |
| **R** | 조회/읽기 | 조회, 검색, 상세보기, 목록, 필터, 엑셀 다운로드 |
| **U** | 수정/변경 | 수정, 편집, 저장(변경), 반영, 확정 |
| **D** | 삭제 | 삭제, 제거, 취소(레코드) |
| **N** | 이동·기타 | 화면 이동, 팝업 열기, 토글, 새로고침 (CRUD 아님) |

## 3. 화면 컨셉 md (`docs/<화면>.md`)
- 이 화면이 **무엇을 위한 화면인지**(업무 목적), 누가 쓰는지
- **대표 업무 흐름**(예: 조건 선택 → 조회 → 저장)
- 화면 수준 **FR 후보**(YAML requirements와 중복 OK — 지니(Jinny)가 통합·중복제거함)
- 화면 캡처/스크린샷(있으면)

## 4. 좋은 예시 (요소 1개)

```yaml
  - id: btn-run-query
    label: 질의 실행
    type: button
    crud: R                       # 조회(SELECT 실행)
    event: onclick
    front:
      handler: runNl2Sql()
      file: custom-report.js
      validation: "질문 또는 조건 중 최소 1개(없으면 토스트)"
      state_writes: [crNlQuery, crNlResult]
    backend:
      api: /api/nl2sql
      method: POST
      security: "SELECT 전용·다중문/DDL 차단·API키 서버보관"
    result: 결과 테이블 렌더(상태 done/empty/error)
```

## 5. 🤖 바이브코딩 프롬프트 (복붙용)

목업 화면을 AI(Claude/Cursor 등)로 만들 때, 아래를 **함께** 지시하세요.

```
너는 예산관리 목업의 한 화면을 만든다. 화면 코드와 함께,
지니(Jinny)가 읽을 rawdata YAML을 반드시 같이 생성해라.

[화면 코드 규칙]
- 버튼은 인라인 onclick="handler()" 로 연결한다(addEventListener 대신). 그래야 CRUD 감지가 된다.
- 버튼 label에 CRUD 동사를 명확히 쓴다(저장/등록/수정/삭제/조회/검색).

[rawdata YAML 규칙]  → docs/rawdata/screens/<화면>.yaml
- 스키마: screen(id,name,menu_path,route,purpose,source_files) / states / elements / apis / data / flows / requirements
- elements: 화면의 모든 버튼·입력·칩·토글을 하나도 빠짐없이. 각 요소에 반드시:
    id, label, type, crud(C/R/U/D/N), event, front.handler(실제 함수명), front.validation,
    backend(api·method·security 또는 null), result
- crud 판정: 등록=C, 조회/검색/다운로드=R, 수정/편집/저장(변경)=U, 삭제=D, 이동/팝업/토글=N
- requirements: FR-<화면약자>-NN 형식으로 5~10개, '~할 수 있어야 한다' 톤
- 근거 없는 내용 금지: 코드에 없는 함수/ API를 지어내지 말 것. 목업 스텁이면 "목업 스텁"이라고 표기.
- 영문 key + 한국어 value. 로직은 file:function 으로 근거 인용.

[화면 컨셉 md]  → docs/<번호>-<화면>.md
- 화면 목적·사용자·대표 업무 흐름·FR 후보를 산문으로 정리.

출력: (1) 화면 코드  (2) rawdata YAML  (3) 화면 컨셉 md — 3개를 모두 생성.
```

## 6. 제출 전 셀프 체크리스트
- [ ] `docs/rawdata/screens/<화면>.yaml` 생성했다
- [ ] 모든 버튼·입력이 elements에 있다 (누락 0)
- [ ] 각 요소에 `crud`(C/R/U/D/N)를 넣었다
- [ ] `handler`·`api`가 실제 코드와 일치한다(지어내지 않음)
- [ ] `requirements`에 FR 후보를 5~10개 넣었다
- [ ] `route`(해시 URL)가 정확하다 (화면 자동 캡처용)
- [ ] `docs/<화면>.md`에 화면 컨셉·업무 흐름을 적었다
